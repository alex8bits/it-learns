# Command: Sync Route Documentation with Application Routes (it-learns)

This is the **documentation sync step** for the **it-learns** project
(Laravel 13 / PHP 8.3 — онлайн-платформа обучения IT-навыкам).

Ensure the **route/API documentation** is complete by comparing the current
routes (across all surfaces and versions) with existing documentation in
`docs/` and adding any missing endpoints.

---

## Goal

Сделать так, чтобы документация маршрутов (админка, публичная часть, API) была
**полной и актуальной** относительно реально зарегистрированных маршрутов в
коде. Любой добавленный в коде эндпоинт должен автоматически попадать в
документацию; любой документированный, но не существующий — флагаться на
ручную проверку (не удалять автоматически).

---

## Inputs

- Доступ к исходному коду **it-learns** для детекции маршрутов.
- Существующие файлы документации в репо (если есть) — например `docs/routes.md`, `docs/api.md`, `docs/admin.md`, Postman/OpenAPI коллекции.

---

## Steps

### 1. Load the Existing Documentation

- Прочитать все существующие файлы документации маршрутов, если они есть.
- Извлечь все эндпоинты:
  - HTTP method
  - route/path (с surface + version, например `api/v1/...`, `admin/users`, `courses/{slug}`)
  - query-параметры
  - схема request body (если доступна)
  - headers
  - тип авторизации (`auth` web, `auth:api`, `role:admin`, `EnsurePremium`, throttle)

### 2. Scan Application Routes

- Задетектить все маршруты из исходного кода.
- Источники для сканирования:
  - `routes/web.php` — публичная часть (каталог, личный кабинет).
  - `routes/auth.php` — аутентификация (если выделена).
  - `routes/admin.php` — админка.
  - `routes/api.php` — API (с версионированием `v1/`, `v2/`).
- Для каждого маршрута зафиксировать:
  - HTTP method
  - полный path (после surface/version префикса)
  - middleware (`auth`, `auth:api`, `role:admin`, `EnsurePremium`, `throttle:...`, `signed`, etc.)
  - controller@method или Closure
  - имена FormRequest / Resource классов, если привязаны в route
  - схемы request/response, если доступны
  - **премиум-флаг**: да/нет
  - **ИИ-вызовы**: да/нет (если в контроллере или action упоминается LlmClient)
  - **изоляция среды**: да/нет (если упоминается PracticeEnvironmentManager)

### 3. Compare Endpoints

- Матчить эндпоинты по **HTTP method + full path (surface + version + path)**.
- Разные версии одного и того же пути — **отдельные** записи: `api/v1/users` и `api/v2/users` — разные эндпоинты.
- Идентифицировать:
  - Маршруты есть в коде, но **отсутствуют в документации**.
  - Маршруты есть в документации, но **отсутствуют в коде** — флагать на ручную проверку, **не удалять автоматически**.
  - Маршруты, у которых изменились middleware/auth — флагать на ручную проверку.

### 4. Update Documentation

Для каждого недостающего эндпоинта:

- Добавить секцию в существующем стиле документации.
- Включить:
  - Method
  - Full path (с surface и version)
  - Middleware / auth requirement
  - Описание (вывести из названия route/controller/method, если явно не описано)
  - Параметры (path, query, body)
  - Пример request
  - Пример response (если возможно)
  - **Премиум-флаг / ИИ / изоляция среды** — явно, если применимо

### 5. Preserve Structure

- **Не переписывать** существующую документацию.
- Только **дописывать** недостающие эндпоинты в соответствующие секции.
- Сохранять группировки по surface (`public`, `admin`, `api`) и version (`v1`, `v2`).

### 6. Output

- Обновить файлы документации напрямую.
- Сводка:
  - Добавленные эндпоинты (сгруппированные по surface × version)
  - Пропущенные эндпоинты (уже задокументированные)
  - Зафлагованные эндпоинты (есть в доках, но нет в коде — нужна ручная проверка)
  - Маршруты, которые не удалось распарсить

---

## Rules

- **Не удалять и не модифицировать** существующие задокументированные эндпоинты.
- Следовать существующему формату и структуре документации.
- Если у маршрута несколько версий (`/v1/`, `/v2/`) — обрабатывать отдельно и держать в разных секциях.
- Нормализовать пути перед сравнением (убрать trailing slashes, нормализовать параметры `{id}` ↔ `:id`).
- Surface (`public|admin|api`) и version (`v1|v2`) — часть идентичности пути, никогда не схлопывать.
- Премиум/ИИ/изоляция среды — явно отмечать, если затрагивается, чтобы в документации было видно, какие маршруты требуют `EnsurePremium`, какие дёргают `LlmClient`, какие работают с `PracticeEnvironmentManager`.

---

## Expected Result

Документация содержит **все текущие маршруты** it-learns по всем surface и
версиям, с автоматически добавленными недостающими эндпоинтами на основе
реальных route-определений. Всё, что было в доках, но не в коде — репортится,
но **не удаляется**.

---

## Final message

После работы вывести:

- Список файлов документации, в которые внесены изменения.
- Сводку: добавлено / пропущено / зафлаговано / не распарсилось.
- Полные пути до затронутых файлов.
