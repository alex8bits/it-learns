# MySQL сервер и клиент: клиент-серверная архитектура, базы данных и USE, системные схемы; обзор клиентов

## Материал

### Ранее в курсе

- Урок 1 уровня «Основы» «Что такое БД и СУБД» — узнали, что база данных — это организованные в таблицы данные, а СУБД (например, MySQL) — программа, которая ими управляет; познакомились с самой простой командой `SELECT столбцы FROM таблица`.

Мы уже знаем, что MySQL — это СУБД: программа, которая хранит данные и выполняет над ними запросы. Но как именно приложение «разговаривает» с этой программой? На чьём компьютере она вообще выполняется? И что происходит, когда вы набираете команду `SELECT ...` — куда она отправляется? В этом уроке разберём устройство MySQL как работающей системы: архитектуру «клиент-сервер», понятие базы данных внутри СУБД, системные схемы и инструменты, которыми пользуются разработчики.

### Клиент-серверная архитектура

MySQL устроена по модели **клиент-сервер** — той же, что используется в вебе (браузер — клиент, веб-сайт — сервер) и в большинстве сетевых сервисов.

- **Сервер** — это отдельная работающая программа, процесс с именем `mysqld` (суффикс `d` означает *daemon* — «демон», то есть фоновый процесс, работающий постоянно, а не запускающийся заново на каждый запрос). Сервер MySQL запускается один раз (обычно при старте компьютера или контейнера) и продолжает работать, слушая определённый сетевой порт — по умолчанию **3306**. Именно сервер физически хранит данные на диске, обслуживает запросы и следит за их корректным выполнением.
- **Клиент** — это любая программа, которая подключается к серверу по сети (даже если сервер и клиент находятся на одном компьютере, соединение всё равно происходит через сетевой протокол или локальный сокет) и отправляет ему команды SQL. Клиентом может быть текстовая консольная утилита, графическая программа или код вашего веб-приложения — все они «разговаривают» с сервером на одном и том же языке протокола MySQL.

Ключевое следствие такой архитектуры: **сервер и клиент — это разные программы**, и их может быть много одновременно. К одному серверу MySQL могут подключаться десятки клиентов параллельно: разные пользователи, разные приложения, разные скрипты администрирования. Сервер сам разруливает параллельные запросы, следит, чтобы один клиент не испортил данные, которые в этот момент читает другой (эта тема подробно раскрывается позже, в уровне «Средний», когда речь пойдёт о транзакциях и изоляции). Пока достаточно запомнить: **клиент не хранит данные сам** — он только отправляет запросы и получает результат; вся ответственность за хранение и целостность лежит на сервере.

Подключение клиента к серверу всегда требует нескольких параметров: адрес сервера (host, например `127.0.0.1` или `localhost`, если сервер на этом же компьютере, либо доменное имя удалённого сервера), порт (по умолчанию 3306), имя пользователя и пароль. Сервер проверяет эти данные и, если они верны, устанавливает **сессию** — активное соединение, в рамках которого клиент может отправлять запросы, пока не отключится.

### Базы данных внутри одного сервера и команда USE

Важный нюанс: один запущенный сервер MySQL может обслуживать **не одну, а сразу множество баз данных одновременно**. Например, на одном сервере может физически находиться база данных интернет-магазина, база данных внутреннего блога компании и тестовая база данных для разработки — и всё это без конфликтов, потому что каждая база данных — это изолированный набор таблиц со своим именем.

Список всех баз данных, доступных на сервере, можно посмотреть командой:

```sql
SHOW DATABASES;
```

Она выведет что-то вроде:

| Database |
|---|
| information_schema |
| mysql |
| performance_schema |
| shop |
| sys |

Прежде чем выполнять запросы к таблицам конкретной базы данных, клиенту нужно сообщить серверу, с какой из них он собирается работать. Для этого используется команда `USE`:

```sql
USE shop;
```

После выполнения этой команды все последующие запросы в текущей сессии («пока клиент не отключился или не выполнил `USE` с другим именем») по умолчанию будут искать таблицы именно в базе данных `shop`. Например, запрос `SELECT * FROM products;` после `USE shop;` будет искать таблицу `products` именно там.

Можно обойтись и без `USE`, если каждый раз явно указывать имя базы данных перед именем таблицы через точку:

```sql
SELECT * FROM shop.products;
```

Такая запись «база_данных.таблица» называется **полностью определённым именем** (fully qualified name) и полезна, когда в одном запросе нужно обратиться к таблицам из разных баз данных одновременно. Но в подавляющем большинстве повседневных сценариев проще один раз выполнить `USE` и дальше писать только имена таблиц.

Важно не путать понятия: «база данных» здесь — это именованный контейнер таблиц внутри одного сервера, а не сам сервер MySQL целиком. Когда говорят «у нас есть база данных для магазина и база данных для блога», обычно имеют в виду именно две такие именованные схемы на одном сервере, а не два разных сервера.

### Системные базы данных

Обратите внимание на список выше: помимо `shop` (нашей рабочей базы) там есть ещё несколько баз данных, которые MySQL создаёт сам при установке. Это **системные схемы**, и трогать их руками (изменять или удалять) не стоит — они нужны серверу для собственной работы:

- **`information_schema`** — «база данных о базах данных». Она не хранит ваши данные, а предоставляет информацию о структуре всех остальных баз: какие таблицы существуют, какие у них столбцы, какие ограничения. Например, запрос к `information_schema.tables` вернёт список всех таблиц на сервере. Эта схема полезна, когда нужно программно узнать структуру базы, а не открывать документацию проекта.
- **`mysql`** — служебная база самого сервера: здесь хранится информация о пользователях, их правах доступа, паролях и различных настройках. Именно сюда обращается сервер, когда проверяет, можно ли пользователю подключиться и что ему разрешено делать (подробнее о пользователях и правах — на уровне «Продвинутый»).
- **`performance_schema`** — база для мониторинга производительности сервера: сколько времени занимают запросы, сколько памяти используется, какие блокировки происходят. Полезна при диагностике медленной работы сервера, но для начинающего пользователя не нужна в повседневной работе.
- **`sys`** — набор готовых, удобных для человека представлений (views) над данными `performance_schema` — упрощает чтение диагностической информации без глубокого знания внутреннего устройства сервера.

Вы ещё не раз встретите эти имена — например, при написании запросов, которые исследуют структуру базы, или при работе с правами пользователей. Пока достаточно знать, что они существуют и что это «служебная» часть сервера, а не часть вашего проекта.

### Обзор клиентов MySQL

Поскольку клиент и сервер — разные программы, для одного и того же сервера MySQL существует множество разных клиентов — от простых текстовых до полноценных графических приложений. Разберём самые распространённые.

**`mysql` (консольный клиент, CLI)** — официальная утилита командной строки, которая устанавливается вместе с сервером MySQL. Запускается из терминала:

```
mysql -h 127.0.0.1 -P 3306 -u root -p
```

где `-h` — адрес сервера, `-P` — порт, `-u` — имя пользователя, `-p` заставляет клиент запросить пароль перед подключением. После подключения открывается интерактивная консоль, в которую можно вводить SQL-команды прямо построчно; каждая команда завершается точкой с запятой `;`. Консольный клиент — минималистичный, но универсальный инструмент: он есть почти везде, где установлен MySQL, работает быстро и не требует графического интерфейса — это особенно удобно при подключении к серверу по SSH или в автоматических скриптах.

**MySQL Workbench** — официальное графическое приложение от Oracle (разработчика MySQL). Позволяет визуально просматривать структуру базы данных, строить ER-диаграммы (диаграммы связей между таблицами — про них будет отдельный разговор на уровне «Начинающий»), редактировать данные через таблицы, а не только через текстовые команды, и писать SQL-запросы в удобном редакторе с подсветкой синтаксиса и автодополнением.

**DBeaver** — универсальный графический клиент с открытым исходным кодом, который умеет подключаться не только к MySQL, но и к множеству других СУБД (PostgreSQL, SQLite, Oracle и другим) через единый интерфейс. Популярен среди разработчиков, которым приходится работать с разными базами данных в разных проектах — не нужно переключаться между разными программами для каждой СУБД.

Кроме перечисленных существуют и другие клиенты: встроенные средства в средах разработки (например, плагины для VS Code или PhpStorm), веб-интерфейсы типа phpMyAdmin, а также клиентские библиотеки, встроенные в языки программирования (например, `mysqli` или PDO в PHP, `mysql-connector` в Python) — они позволяют приложению подключаться к серверу MySQL программно, без участия человека, и именно так работает подключение «сайт — база данных» в реальных проектах.

Важно понимать: независимо от того, каким клиентом вы пользуетесь — консольным `mysql`, графическим Workbench или кодом на PHP — все они в конце концов отправляют один и тот же SQL-текст одному и тому же серверу и получают структурно одинаковый результат. Разница между клиентами — это разница в удобстве работы для человека или программы, а не в том, что «умеет» сервер. Поэтому знания, полученные в этом курсе, применимы независимо от того, какой конкретный клиент вы выберете для практики.

### Резюме

- MySQL работает по модели **клиент-сервер**: сервер (`mysqld`) — отдельный процесс, который хранит данные и слушает сетевой порт (по умолчанию 3306); клиент — любая программа, которая подключается к серверу и отправляет ему SQL-команды.
- Один сервер может обслуживать сразу несколько **баз данных** — изолированных наборов таблиц с собственными именами; посмотреть список всех баз можно командой `SHOW DATABASES`.
- Команда `USE имя_базы` выбирает базу данных для текущей сессии, после чего запросы по умолчанию обращаются к таблицам именно этой базы; альтернатива — явное указание `база.таблица` в каждом запросе.
- Сервер сам создаёт несколько **системных баз данных**: `information_schema` (метаданные о структуре других баз), `mysql` (пользователи и права), `performance_schema` и `sys` (диагностика производительности) — трогать их руками в обычной работе не требуется.
- Клиенты MySQL разнообразны: консольная утилита `mysql`, графические приложения (MySQL Workbench, DBeaver), веб-интерфейсы и клиентские библиотеки в коде приложений — все они говорят с сервером на одном и том же языке SQL.
