# Изменение и удаление объектов: ALTER TABLE (ADD/MODIFY/DROP COLUMN); различия DELETE / TRUNCATE / DROP

## Материал

- Урок 2 уровня «Основы» «MySQL сервер и клиент» — клиент-серверная архитектура, базы данных, `USE`.
- Урок 3 уровня «Основы» «Синтаксис SQL и SELECT» — синтаксис запросов, `LIMIT`.
- Урок 4 уровня «Основы» «Добавление данных» — `INSERT INTO ... VALUES ...`.
- Урок 5 уровня «Основы» «Типы данных» — `INT`, `DECIMAL`, `VARCHAR`/`TEXT`, `DATE`/`DATETIME`, `BOOL`, `utf8mb4`.
- Урок 6 уровня «Основы» «Создание таблиц с ограничениями» — `CREATE TABLE`, `PRIMARY KEY`, `AUTO_INCREMENT`, `NOT NULL`, `UNIQUE`, `DEFAULT`, `CHECK`.

Таблица, созданная командой `CREATE TABLE`, не обязана оставаться неизменной навсегда. Проекты развиваются: понадобился новый столбец, старый оказался не нужен, а иногда нужно вовсе очистить или удалить всю таблицу. В этом уроке разберём команду изменения структуры таблицы `ALTER TABLE`, а также важное различие между тремя похожими на первый взгляд, но принципиально разными операциями: `DELETE`, `TRUNCATE` и `DROP`.

### ALTER TABLE: изменение структуры существующей таблицы

`ALTER TABLE`, как и `CREATE TABLE`, относится к DDL-командам — она не трогает содержимое строк напрямую, а меняет саму структуру таблицы: добавляет, изменяет или удаляет столбцы. Общий вид команды:

```sql
ALTER TABLE имя_таблицы действие;
```

где вместо `действие` подставляется одна из трёх операций, которые мы разберём по очереди.

### ADD COLUMN: добавление нового столбца

Если в уже существующей таблице `products` понадобилось хранить, например, артикул товара, который изначально не был предусмотрен, новый столбец можно добавить без пересоздания таблицы:

```sql
ALTER TABLE products
ADD COLUMN sku VARCHAR(64);
```

После выполнения этой команды у таблицы `products` появляется новый столбец `sku`, доступный для использования в `SELECT` и `INSERT` точно так же, как если бы он существовал с самого начала. У уже существующих строк таблицы значением нового столбца станет `NULL` (если не указано иное, например через `DEFAULT`, с которым мы познакомились в прошлом уроке) — новый столбец не может «магическим образом» узнать, каким должно быть значение для строк, вставленных до его появления.

Новый столбец можно сразу снабдить теми же ограничениями, что и при `CREATE TABLE`:

```sql
ALTER TABLE products
ADD COLUMN sku VARCHAR(64) UNIQUE;
```

### MODIFY COLUMN: изменение существующего столбца

Если структура столбца перестала соответствовать реальным потребностям — например, изначально отведённой длины `VARCHAR` не хватает, или столбец нужно сделать обязательным, — используется `MODIFY COLUMN`:

```sql
ALTER TABLE products
MODIFY COLUMN name VARCHAR(500) NOT NULL;
```

Важный нюанс: при `MODIFY COLUMN` необходимо заново указать *полное* определение столбца — тип данных и все нужные ограничения, — а не только то, что меняется. Если написать только `MODIFY COLUMN name VARCHAR(500)`, не повторив `NOT NULL`, ранее заданное ограничение `NOT NULL` для этого столбца будет снято, потому что новое определение полностью заменяет старое, а не дополняет его.

Изменение типа существующего столбца — операция, к которой стоит относиться внимательно: если в столбце уже есть данные, а новый тип несовместим со старыми значениями (например, сужение `VARCHAR(500)` до `VARCHAR(10)`, когда в таблице уже есть более длинные значения), сервер либо откажет с ошибкой, либо (в зависимости от режима) обрежет данные — и то и другое стоит предвидеть заранее, а не выяснять по факту.

### DROP COLUMN: удаление столбца

Если столбец больше не нужен, его можно удалить целиком:

```sql
ALTER TABLE products
DROP COLUMN sku;
```

Эта операция удаляет и сам столбец, и **все значения**, которые в нём хранились для всех строк таблицы — без возможности отмены средствами самого SQL. Если данные в удаляемом столбце представляют ценность, их стоит предварительно сохранить (например, через `SELECT`, скопировав результат куда-то, или, что чаще на практике, через полноценную резервную копию базы данных — про такие процедуры пойдёт речь на уровне «Продвинутый»).

### Несколько действий в одной команде ALTER TABLE

MySQL позволяет выполнить сразу несколько изменений структуры за одну команду `ALTER TABLE`, перечислив действия через запятую:

```sql
ALTER TABLE products
ADD COLUMN sku VARCHAR(64) UNIQUE,
MODIFY COLUMN price DECIMAL(12, 2) NOT NULL;
```

Это не только компактнее, но и, как и с `INSERT` нескольких строк одной командой, обычно эффективнее, чем несколько отдельных `ALTER TABLE` — особенно на таблицах, где перестройка структуры требует чтения и перезаписи существующих данных.

### Три способа «убрать данные»: DELETE, TRUNCATE, DROP

Теперь разберём операции, которые не *создают* и не *изменяют* структуру, а, наоборот, что-то удаляют — но делают это на принципиально разных уровнях. Именно из-за внешнего сходства («все они что-то удаляют») эти три команды часто путают, а перепутать их на реальной базе данных — рискованно.

**`DELETE`** — команда удаления **строк** из таблицы; сама таблица со всей её структурой (столбцами, ограничениями) при этом остаётся на месте. `DELETE` относится к DML (языку манипулирования данными, как `INSERT`), а не к DDL — она работает со строками, а не со структурой. Полный синтаксис `DELETE` с условием, определяющим, какие именно строки удалить, мы подробно разберём в отдельном уроке позже (вместе с `UPDATE`); здесь достаточно знать общий смысл:

```sql
DELETE FROM products WHERE id = 5; -- удалит одну конкретную строку
```

`DELETE` без условия `WHERE` удалит **все** строки таблицы, но, в отличие от следующей команды, будет делать это построчно и медленнее на больших таблицах, а также позволяет удаление отследить и, в определённых сценариях, отменить в рамках транзакции (с транзакциями вы познакомитесь на уровне «Средний»).

**`TRUNCATE`** — команда, которая удаляет **все строки** таблицы одним махом, но при этом сама структура таблицы, включая все столбцы и ограничения, полностью сохраняется:

```sql
TRUNCATE TABLE products;
```

После `TRUNCATE` таблица `products` продолжает существовать со всеми своими столбцами и ограничениями — она просто становится пустой, будто в неё только что выполнили `CREATE TABLE`, но ни одной строки ещё не добавили. `TRUNCATE` относится к DDL (а не к DML, как `DELETE`), выполняется значительно быстрее `DELETE` без условия на больших таблицах, потому что физически работает иначе (пересоздаёт хранилище данных таблицы, а не удаляет строки по одной), но за счёт этого практически необратим и не даёт такой же гибкости отслеживания, как `DELETE` в рамках транзакции.

**`DROP`** — самая радикальная из трёх команд: она удаляет **саму таблицу целиком**, вместе со всей структурой (столбцами, ограничениями) и всеми данными в ней:

```sql
DROP TABLE products;
```

После выполнения этой команды таблицы `products` не существует вовсе — чтобы снова работать с товарами, нужно будет заново выполнить `CREATE TABLE` со всеми ограничениями, которые вы хотите сохранить, и заново наполнить её данными. `DROP` — тоже DDL-команда и, как и `TRUNCATE`, необратима стандартными средствами SQL.

### Сравнительная таблица трёх команд

| Команда | Что удаляет | Структура таблицы | Тип команды | Скорость на больших таблицах |
|---|---|---|---|---|
| `DELETE` | конкретные строки (по условию) или все строки | сохраняется | DML | медленнее (построчно) |
| `TRUNCATE` | все строки | сохраняется | DDL | быстрее |
| `DROP` | всю таблицу целиком | удаляется вместе с данными | DDL | быстрее, необратимо |

Практическое правило, которое стоит запомнить с самого начала работы с базами данных: чем «радикальнее» команда, тем осторожнее нужно быть перед её выполнением, особенно на настоящей рабочей базе данных, а не в учебной песочнице. `DROP TABLE` и `TRUNCATE TABLE` без предварительной резервной копии на продуктивной базе — одна из самых частых причин серьёзных инцидентов в реальных проектах; прежде чем выполнять такие команды, всегда стоит на секунду остановиться и перепроверить, к той ли базе данных и к той ли таблице вы сейчас подключены.

### Резюме

- `ALTER TABLE` — DDL-команда изменения структуры уже существующей таблицы: `ADD COLUMN` добавляет новый столбец, `MODIFY COLUMN` изменяет тип или ограничения существующего (при этом определение столбца указывается полностью, а не частично), `DROP COLUMN` удаляет столбец вместе со всеми хранившимися в нём значениями.
- Несколько действий `ALTER TABLE` можно объединить в одну команду через запятую.
- `DELETE` (DML) удаляет строки таблицы (по условию или все), сохраняя саму структуру таблицы — работает построчно и относительно медленнее на больших объёмах.
- `TRUNCATE` (DDL) быстро очищает все строки таблицы, тоже сохраняя структуру, но необратим и не даёт гибкости условного удаления.
- `DROP` (DDL) удаляет таблицу целиком — и структуру, и все данные; самая радикальная и необратимая из трёх операций.
- Перед выполнением `TRUNCATE` и `DROP` на реальной базе данных стоит всегда убеждаться, что вы работаете именно с той базой и таблицей, которую действительно собираетесь изменить.
