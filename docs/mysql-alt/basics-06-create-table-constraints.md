# Создание таблиц с ограничениями: CREATE TABLE, PRIMARY KEY, AUTO_INCREMENT, NOT NULL, UNIQUE, DEFAULT, CHECK

До этого момента мы работали с таблицами, которые как будто бы уже существовали. В этом уроке мы наконец научимся создавать их сами — и не просто создавать, а сразу закладывать в структуру таблицы правила, которые защищают данные от ошибок. Это команда `CREATE TABLE` и набор **ограничений** (constraints): `PRIMARY KEY`, `AUTO_INCREMENT`, `NOT NULL`, `UNIQUE`, `DEFAULT`, `CHECK`.

### CREATE TABLE: команда, меняющая структуру, а не данные

Все команды, с которыми мы работали до сих пор (`SELECT`, `INSERT`), относятся к DML — языку манипулирования *данными*: они читают или изменяют содержимое таблиц, но сама структура таблицы (набор столбцов, их типы, правила) остаётся неизменной. `CREATE TABLE` принадлежит к другой группе команд — **DDL** (Data Definition Language, «язык определения данных»): она не читает и не изменяет строки, а создаёт саму структуру, в которой строки будут храниться.

Базовый синтаксис:

```sql
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    price DECIMAL(10, 2) NOT NULL,
    stock INT NOT NULL DEFAULT 0
);
```

Здесь `CREATE TABLE products` объявляет имя новой таблицы, а внутри скобок — список столбцов, каждый со своим типом данных (мы разбирали их в прошлом уроке) и, опционально, дополнительными правилами — ограничениями. Именно эти правила мы сейчас разберём по одному.

### PRIMARY KEY: уникальный идентификатор строки

Практически у каждой таблицы есть столбец, который однозначно определяет конкретную строку — «паспорт» записи, по которому её можно найти без ошибки, даже если все остальные значения в двух строках совпадают. Такой столбец называют **первичным ключом** (primary key) и объявляют модификатором `PRIMARY KEY`:

```sql
id INT AUTO_INCREMENT PRIMARY KEY
```

`PRIMARY KEY` накладывает сразу два требования на значения столбца: они должны быть **уникальными** (в таблице не может быть двух строк с одинаковым значением первичного ключа) и **не NULL** (пустое значение первичного ключа не имеет смысла — иначе он не сможет однозначно идентифицировать строку). Если попытаться вставить строку с таким же значением `id`, какое уже есть в таблице, сервер откажет с ошибкой дублирования.

Первичный ключ — это не просто формальность: именно по нему в дальнейшем строится большинство связей между таблицами (например, заказ будет хранить `customer_id`, ссылающийся на первичный ключ таблицы клиентов, — про такие связи подробно поговорим на уровне «Начинающий»), и именно по первичному ключу сервер быстрее всего умеет находить конкретную строку.

### AUTO_INCREMENT: сервер сам придумывает следующий номер

Придумывать уникальные числа для `id` вручную при каждой вставке — неудобно и рискованно: легко ошибиться и вставить дубликат. Модификатор `AUTO_INCREMENT` решает эту задачу за вас: сервер сам присваивает столбцу следующее по порядку целое число (обычно начиная с 1) при каждой новой вставленной строке, если явно не указать значение для этого столбца:

```sql
INSERT INTO products (name, price, stock) VALUES ('Клавиатура', 4500.00, 12);
-- id этой строки сервер выберет сам, например 1
```

`AUTO_INCREMENT` применим только к числовому столбцу и почти всегда сочетается с `PRIMARY KEY` — это самый частый способ организовать простой, надёжный и предсказуемый идентификатор строки, не требующий никакой ручной работы от того, кто вставляет данные.

### NOT NULL: значение обязательно

Мы не раз упоминали особое значение `NULL` — «значение отсутствует» — и подробно разберём его в отдельном уроке позже. Пока важно знать: если столбец не имеет модификатора `NOT NULL`, в него по умолчанию можно записать `NULL`, то есть оставить значение фактически незаполненным. Модификатор `NOT NULL` запрещает такую возможность — сервер откажет вставить строку, где для этого столбца не указано конкретное значение:

```sql
name VARCHAR(255) NOT NULL
```

Здесь `NOT NULL` означает: у товара обязательно должно быть название — строка без явно указанного `name` не будет создана. `NOT NULL` стоит ставить на каждый столбец, значение которого действительно обязано присутствовать для корректной работы с записью — это дисциплинирует структуру данных и защищает от «пустых мест», о существовании которых легко забыть при написании кода приложения.

### UNIQUE: значение не должно повторяться, но это не первичный ключ

Иногда столбцу нужно требование «значения не повторяются», но по смыслу он не подходит на роль главного идентификатора строки. Классический пример — email клиента: у двух разных клиентов не может быть одинакового email, но именно `email` как строка неудобен в роли основного идентификатора, которым обычно служит компактное число. Для такого требования используется модификатор `UNIQUE`:

```sql
email VARCHAR(255) UNIQUE
```

В отличие от `PRIMARY KEY`, столбец с `UNIQUE` всё же может (если явно не добавить `NOT NULL`) содержать `NULL` — причём в MySQL допускается сразу несколько строк с `NULL` в уникальном столбце, потому что `NULL` трактуется как «значение неизвестно», а не как конкретное повторяющееся значение (подробно про эту особенность NULL — в отдельном уроке). В одной таблице можно объявить `UNIQUE` для нескольких разных столбцов одновременно — в отличие от `PRIMARY KEY`, которых на таблицу может быть только один (хотя технически первичный ключ может состоять из нескольких столбцов сразу — с этим случаем вы встретитесь позже, на уровне «Средний», при разборе связующих таблиц).

### DEFAULT: значение по умолчанию

Часто у столбца есть «естественное» значение, которое стоит использовать, если при вставке строки его явно не указали. Например, для нового товара логично считать, что на складе его 0 штук, пока не указано иное:

```sql
stock INT NOT NULL DEFAULT 0
```

Если при `INSERT` не указать значение для `stock`, сервер автоматически подставит `0` — вставка при этом не завершится ошибкой, даже если столбец объявлен `NOT NULL`, поскольку значение всё равно будет заполнено — просто не явно вами, а модификатором `DEFAULT`. `DEFAULT` можно комбинировать с любым типом данных: например, `is_active BOOL DEFAULT TRUE` для нового товара «по умолчанию активен», или `created_at DATETIME DEFAULT CURRENT_TIMESTAMP` — специальное выражение, которое автоматически подставляет текущую дату и время сервера в момент вставки строки, без необходимости указывать её явно из приложения.

### CHECK: произвольное условие на значение

Иногда правило корректности значения сложнее, чем «не должно быть NULL» или «должно быть уникальным» — например, цена товара не может быть отрицательной, а количество на складе не может быть меньше нуля. Для таких произвольных условий существует ограничение `CHECK`:

```sql
price DECIMAL(10, 2) NOT NULL CHECK (price >= 0)
```

Здесь `CHECK (price >= 0)` требует, чтобы значение столбца `price` в любой строке таблицы было не меньше нуля; попытка вставить строку с отрицательной ценой будет отклонена сервером с ошибкой нарушения ограничения. `CHECK` может ссылаться и на несколько столбцов сразу в одном условии, но на уровне «Основы» вам будет достаточно простых однострочных условий вроде показанного выше.

Важная деталь: поддержка `CHECK` как реально проверяемого ограничения (а не просто «принимаемого, но игнорируемого» синтаксиса) появилась в MySQL относительно недавно — начиная с версии 8.0.16, на которую и рассчитан этот курс. В более старых версиях MySQL `CHECK` можно было написать, но сервер его не применял на практике — если вы когда-нибудь встретите такое поведение в старом проекте, теперь вы понимаете, откуда оно.

### Полный пример таблицы со всеми ограничениями

Соберём все изученные ограничения в одну реалистичную таблицу товаров:

```sql
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    price DECIMAL(10, 2) NOT NULL CHECK (price >= 0),
    stock INT NOT NULL DEFAULT 0 CHECK (stock >= 0),
    sku VARCHAR(64) UNIQUE
);
```

Читая это объявление, можно почти сразу понять бизнес-правила таблицы без единой строчки комментария: у каждого товара есть автоматически присваиваемый уникальный числовой идентификатор; название обязательно; цена обязательна и не может быть отрицательной; количество на складе обязательно, по умолчанию равно нулю и не может быть отрицательным; артикул (`sku`) необязателен, но если указан — должен быть уникальным среди всех товаров. Такая «самодокументируемость» структуры таблицы — одна из причин, почему ограничения стоит закладывать в схему с самого начала, а не пытаться проверять то же самое только в коде приложения.

### Что произойдёт при попытке нарушить ограничение

Если попытаться вставить строку, которая нарушает любое из перечисленных правил (повторяющийся `id` или `sku`, отсутствующее `name`, отрицательная `price`), сервер откажется выполнять `INSERT` целиком и вернёт ошибку, описывающую, какое именно ограничение было нарушено — например, `Duplicate entry` для нарушения `UNIQUE`/`PRIMARY KEY`, `cannot be null` для `NOT NULL`, `Check constraint ... is violated` для `CHECK`. Строка при этом не будет добавлена ни частично, ни целиком — либо вставка полностью успешна и удовлетворяет всем правилам таблицы, либо не происходит вовсе. Это ровно то поведение, о котором мы говорили в самом первом уроке курса: СУБД не позволяет незаметно испортить данные, отклоняя некорректные попытки их изменить прямо на уровне сервера, до того как ошибка успеет повлиять на что-либо ещё.

### Резюме

- `CREATE TABLE` — DDL-команда, создающая структуру новой таблицы: список столбцов с типами данных и, опционально, ограничениями (constraints).
- `PRIMARY KEY` объявляет столбец уникальным идентификатором строки: значения обязаны быть уникальными и не NULL; на таблицу — один первичный ключ.
- `AUTO_INCREMENT` заставляет сервер автоматически присваивать следующее по порядку число числовому столбцу (обычно первичному ключу) при каждой новой вставке.
- `NOT NULL` требует, чтобы значение столбца было обязательно указано (или подставлено через `DEFAULT`) — недопустимо оставлять его пустым.
- `UNIQUE` запрещает повторяющиеся значения в столбце, но, в отличие от `PRIMARY KEY`, таких столбцов в таблице может быть несколько, и NULL не считается «повторяющимся значением».
- `DEFAULT значение` подставляет указанное значение автоматически, если оно не было явно указано при `INSERT`.
- `CHECK (условие)` проверяет произвольное логическое условие на значение (или значения) строки; поддерживается сервером, начиная с MySQL 8.0.16.
- Попытка вставить строку, нарушающую любое ограничение таблицы, полностью отклоняется сервером с ошибкой — данные защищены от повреждения на уровне структуры таблицы, а не только силами кода приложения.
