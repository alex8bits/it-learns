# Добавление данных: INSERT ... VALUES (одна и несколько строк)

## Материал

### Ранее в курсе

- Урок 1 уровня «Основы» «Что такое БД и СУБД» — узнали, что данные хранятся в таблицах со строками и столбцами, и научились читать их через `SELECT`.
- Урок 2 уровня «Основы» «MySQL сервер и клиент» — разобрались с архитектурой клиент-сервер, базами данных на одном сервере и командой `USE`.
- Урок 3 уровня «Основы» «Синтаксис SQL и SELECT» — освоили правила синтаксиса, регистр ключевых слов, форматирование запросов и ограничение результата через `LIMIT`.

До сих пор мы только читали данные из уже существующих таблиц — как если бы кто-то другой их туда положил. Но откуда эти данные там появляются? В этом уроке разберём первую команду, которая не читает, а *изменяет* содержимое базы данных: `INSERT` — добавление новых строк в таблицу.

### От чтения к изменению данных

Все команды SQL делятся на две большие группы по своей задаче. Команды **чтения** (в первую очередь `SELECT`) не меняют данные — они просто возвращают их в виде результирующей таблицы, а сама база данных остаётся в точности такой же, как до запроса. Команды **изменения** — `INSERT`, `UPDATE`, `DELETE` (с двумя последними мы познакомимся позже) — наоборот, влияют на содержимое таблиц: добавляют, изменяют или удаляют строки. Такие команды иногда называют DML-операциями (Data Manipulation Language — «язык манипулирования данными»), в отличие от DDL-команд (Data Definition Language), которые меняют не данные, а структуру таблиц — с ними мы встретимся в уроке про `CREATE TABLE`.

`INSERT` — самая простая из команд изменения: она умеет только добавлять новые строки, не трогая уже существующие.

### Синтаксис INSERT: одна строка

Базовая форма команды добавления одной строки выглядит так:

```sql
INSERT INTO products (name, price, stock)
VALUES ('Клавиатура механическая', 4500.00, 12);
```

Разберём составные части:

- **`INSERT INTO`** — ключевые слова, означающие «добавить в». После них указывается имя таблицы, в которую добавляется строка — в данном случае `products`.
- **Список столбцов в скобках** — `(name, price, stock)`. Здесь мы явно перечисляем, в какие столбцы таблицы будем записывать значения, и в каком порядке.
- **`VALUES`** — ключевое слово, после которого в скобках через запятую перечисляются значения — ровно в том же количестве и в том же порядке, что и столбцы выше. Первое значение (`'Клавиатура механическая'`) попадёт в столбец `name`, второе (`4500.00`) — в `price`, третье (`12`) — в `stock`.

Обратите внимание на кавычки: текстовые значения (строки) заключаются в одинарные кавычки `'...'`, а числа — нет. Мы подробно разберём типы данных и их правильную запись в следующем уроке; сейчас достаточно запомнить это базовое правило: строки — в кавычках, числа — без них.

Если в таблице есть столбец, значение для которого сервер способен подставить сам (например, числовой идентификатор `id`, который автоматически увеличивается на единицу при каждой новой строке — с таким механизмом, `AUTO_INCREMENT`, мы познакомимся в уроке про создание таблиц), его можно не указывать ни в списке столбцов, ни в списке значений — сервер сам заполнит это поле подходящим значением.

### Столбцы можно не указывать явно — но лучше указывать

MySQL допускает и более короткую запись `INSERT`, без явного списка столбцов:

```sql
INSERT INTO products
VALUES (NULL, 'Мышь беспроводная', 1200.00, 30);
```

В этом случае значения должны быть перечислены **строго в том порядке, в котором столбцы определены в самой таблице**, причём для *каждого* столбца таблицы должно быть указано какое-то значение (или явно `NULL`, если позволяет схема таблицы, — о `NULL` подробно поговорим в отдельном уроке позже).

Такая запись короче, но опасна: если структура таблицы изменится (например, кто-то добавит новый столбец через `ALTER TABLE`, о чём мы поговорим позже, или просто переставит их порядок), запрос без явного списка столбцов начнёт вставлять значения не туда, куда вы рассчитывали, — и не обязательно сразу заметно. Явное перечисление столбцов, как в первом примере, делает запрос независимым от внутреннего порядка столбцов таблицы и явно показывает читающему код, что именно куда записывается. Поэтому в этом курсе, и в реальной практике, мы будем всегда явно указывать список столбцов при `INSERT`.

### Добавление нескольких строк одной командой

Если нужно добавить сразу несколько товаров, необязательно писать отдельную команду `INSERT` для каждого — можно перечислить несколько наборов значений через запятую в одной команде:

```sql
INSERT INTO products (name, price, stock)
VALUES
    ('Клавиатура механическая', 4500.00, 12),
    ('Мышь беспроводная', 1200.00, 30),
    ('Монитор 27"', 21000.00, 5);
```

Здесь список столбцов указан один раз, а после `VALUES` идут три группы значений в скобках, разделённые запятыми — каждая группа становится отдельной новой строкой таблицы. Такая запись не просто компактнее — она обычно и заметно **быстрее**, чем несколько отдельных команд `INSERT`, потому что сервер обрабатывает вставку как одну операцию, а не как несколько независимых обращений с накладными расходами на каждое. При загрузке большого объёма данных (сотни и тысячи строк) вставка одной командой с множеством групп значений — стандартная практика.

### Порядок столбцов в разных группах значений одинаков

Важное правило: список столбцов после `INSERT INTO таблица (...)` указывается **один раз** и относится сразу ко всем группам значений после `VALUES`. Нельзя для одной строки указать значения в порядке `(name, price)`, а для другой — `(price, name)`: порядок значений в каждой группе строго соответствует единому списку столбцов, заданному в начале команды.

### Что произойдёт, если данные не подходят под структуру таблицы

`INSERT`, как и любая другая команда изменения данных, подчиняется правилам, заданным структурой таблицы. Если таблица требует, чтобы в каком-то столбце обязательно было значение (ограничение `NOT NULL` — про него подробно в уроке про `CREATE TABLE`), а вы попытаетесь вставить строку без значения для этого столбца, сервер откажет с ошибкой, и строка не будет добавлена. Аналогично, если столбец объявлен как хранящий, например, только числа, а вы попытаетесь записать туда текст, который невозможно интерпретировать как число, сервер вернёт ошибку.

Такое поведение — не недостаток, а одно из главных преимуществ базы данных перед хранением данных в обычном файле, о котором мы говорили в первом уроке: сервер сам не позволяет записать заведомо некорректные данные, избавляя разработчика от необходимости проверять каждую мелочь в коде приложения. Мы вернёмся к этой теме подробнее, когда будем разбирать ограничения (`constraints`) при создании таблиц.

### Проверка результата

После выполнения `INSERT` полезно убедиться, что данные действительно добавились — для этого достаточно уже знакомого нам `SELECT`:

```sql
SELECT name, price, stock
FROM products;
```

Если команда `INSERT` выполнилась без ошибок, клиент обычно сообщает, сколько строк было добавлено (например, «3 rows affected» — «затронуто 3 строки»), а последующий `SELECT` покажет эти строки в результате наравне с уже существовавшими.

### Резюме

- `INSERT` — команда добавления новых строк в таблицу; в отличие от `SELECT`, она изменяет содержимое базы данных, а не просто читает его.
- Базовый синтаксис: `INSERT INTO таблица (столбец1, столбец2, ...) VALUES (значение1, значение2, ...);` — количество и порядок значений должны точно соответствовать количеству и порядку указанных столбцов.
- Текстовые значения записываются в одинарных кавычках, числовые — без кавычек.
- Список столбцов можно не указывать явно, но тогда значения должны идти в точности в порядке столбцов самой таблицы для каждого столбца без исключения — такая запись менее надёжна при изменении структуры таблицы, поэтому явное перечисление столбцов предпочтительнее.
- Одной командой `INSERT` можно добавить сразу несколько строк, перечислив несколько групп значений через запятую после `VALUES` — это компактнее и быстрее, чем несколько отдельных команд.
- Сервер проверяет вставляемые данные на соответствие структуре таблицы и откажет добавить строку, которая нарушает её ограничения — это защищает данные от повреждения на уровне СУБД.
