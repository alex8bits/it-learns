В прошлом уроке мы научились комбинировать несколько условий с помощью `AND`/`OR`. Но некоторые распространённые задачи фильтрации, хотя формально и выразимы через `AND`/`OR`, на практике оказываются громоздкими или вовсе неудобными: «товар относится к одной из пяти конкретных категорий», «цена лежит в диапазоне от и до», «имя клиента начинается на определённую букву». Для таких задач в SQL есть специальные, более компактные операторы — `IN`, `BETWEEN` и `LIKE`. Все три — не новая логика, а удобные «сокращения» для конструкций, которые мы уже умеем строить вручную; понимание этой эквивалентности помогает не воспринимать их как магию.

### IN: принадлежность списку значений

Оператор `IN` проверяет, входит ли значение столбца в заданный список значений. Вспомним из прошлого урока задачу «товар из категории "Периферия" или "Мониторы"», решённую через `OR`:

```sql
SELECT name, category, price
FROM products
WHERE category = 'Периферия' OR category = 'Мониторы';
```

Тот же результат `IN` даёт в разы компактнее:

```sql
SELECT name, category, price
FROM products
WHERE category IN ('Периферия', 'Мониторы');
```

Формально `col IN (v1, v2, v3)` полностью равносильно `col = v1 OR col = v2 OR col = v3` — это не новый вид фильтрации, а именно сокращённая запись серии сравнений на равенство через `OR`. Разница становится особенно заметной, когда список растёт: сравните пять значений через `OR` с той же проверкой через `IN`:

```sql
-- то же самое, но неудобно читать при росте списка
WHERE category = 'Периферия' OR category = 'Мониторы' OR category = 'Ноутбуки'
   OR category = 'Аксессуары' OR category = 'Сеть'
```

```sql
WHERE category IN ('Периферия', 'Мониторы', 'Ноутбуки', 'Аксессуары', 'Сеть')
```

У `IN` есть отрицающая форма `NOT IN`, проверяющая, что значение **не** входит в список — она равносильна цепочке `<>`, соединённых через `AND`:

```sql
SELECT name, category
FROM products
WHERE category NOT IN ('Периферия', 'Мониторы');
```

С `NOT IN` стоит быть внимательным к `NULL` в списке или в самом проверяемом столбце: если хотя бы одно значение в списке — `NULL`, результат `NOT IN` становится «неизвестно» для всех строк, где значение не совпало явно ни с одним элементом списка, и такие строки исчезают из результата, даже если интуитивно ожидалось, что они должны попасть. Причина та же трёхзначная логика, что и в предыдущем уроке: `NOT IN` — это по сути серия `<>`, соединённых через `AND`, а `AND` с «неизвестно» в одной из частей сам даёт «неизвестно».

### BETWEEN: значение внутри диапазона

Оператор `BETWEEN` проверяет, лежит ли значение в диапазоне между двумя границами, **включая обе границы**. Найдём товары с ценой от 1000 до 5000 рублей включительно:

```sql
SELECT name, price
FROM products
WHERE price BETWEEN 1000 AND 5000;
```

Эта запись — сокращение для условия с двумя сравнениями, соединёнными `AND`:

```sql
SELECT name, price
FROM products
WHERE price >= 1000 AND price <= 5000;
```

Важно, что `BETWEEN` включает обе границы (то есть работает как `>= ... AND <= ...`, а не как строгое `> ... AND < ...`) — товар ценой ровно 1000 или ровно 5000 попадёт в результат. Если нужен диапазон без границ, придётся вернуться к явным `>`/`<`, потому что у `BETWEEN` нет варианта «исключить границы».

`BETWEEN` работает не только с числами, но и с датами — например, найдём заказы, оформленные в течение конкретного месяца (даты сравниваются лексикографически, как и числа, поэтому это работает без дополнительных функций):

```sql
SELECT id, created_at
FROM orders
WHERE created_at BETWEEN '2024-03-01' AND '2024-03-31 23:59:59';
```

Обратите внимание на явное указание времени `23:59:59` у верхней границы: если столбец `created_at` имеет тип `DATETIME` и хранит не только дату, но и время, а верхнюю границу записать как `'2024-03-31'` (что означает `'2024-03-31 00:00:00'`), заказы, сделанные днём 31 марта, окажутся **за пределами** диапазона — это классическая ошибка «в диапазон дат забыли включить конец дня». К работе с датами и специальным функциям для них мы вернёмся подробно в одном из следующих уроков — здесь достаточно знать этот практический нюанс `BETWEEN` с датами.

Есть и `NOT BETWEEN` — отрицающая форма, эквивалентная `< нижняя_граница OR > верхняя_граница`:

```sql
SELECT name, price
FROM products
WHERE price NOT BETWEEN 1000 AND 5000;
```

### LIKE: поиск по текстовому шаблону

`IN` и `BETWEEN` работают с точными значениями и диапазонами, но что делать, если нужно найти строки, которые «содержат» подстроку, «начинаются» или «заканчиваются» определённым фрагментом текста, не зная точного значения целиком? Для этого служит оператор `LIKE`, сравнивающий текст со специальным **шаблоном**, в котором два символа имеют особый смысл:

- `%` — заменяет **любое количество любых символов**, включая ноль символов;
- `_` — заменяет **ровно один** любой символ.

Найдём все товары, название которых содержит слово «мышь» в любом месте строки:

```sql
SELECT name
FROM products
WHERE name LIKE '%мышь%';
```

Знак `%` до и после слова означает «перед этим словом может быть что угодно (или ничего), и после — тоже что угодно (или ничего)». Найдём товары, название которых **начинается** на «Клавиатура» (без `%` перед шаблоном — только после):

```sql
SELECT name
FROM products
WHERE name LIKE 'Клавиатура%';
```

А товары, название которых **заканчивается** на конкретное слово — `%` только перед шаблоном:

```sql
SELECT name
FROM products
WHERE name LIKE '%27"';
```

Символ `_` полезен, когда нужно найти строки строго определённой длины с известной частью и одним произвольным символом — например, артикулы вида `KB-0` + одна произвольная цифра:

```sql
SELECT name, sku
FROM products
WHERE sku LIKE 'KB-0_';
```

Этот шаблон найдёт `KB-01`, `KB-02`, … `KB-09`, но не найдёт `KB-010` (там на месте `_` было бы уже два символа, а не один) и не найдёт `KB-1` (не совпадает начальная часть шаблона).

Отдельная деталь, о которой полезно знать сразу: чувствительность `LIKE` к регистру символов зависит от **сравнения (collation)**, установленного для столбца или соединения, а не является жёстким правилом самого оператора. Многие типичные для MySQL сравнения по умолчанию (например, `utf8mb4_general_ci` — суффикс `_ci` означает *case-insensitive*, «регистронезависимое») делают `LIKE 'клавиатура%'` и `LIKE 'КЛАВИАТУРА%'` равносильными. Подробный разговор про сравнения и регистр — тема отдельного урока на уровне «Продвинутый»; здесь достаточно запомнить, что видимое поведение регистра в `LIKE` определяется настройкой базы, а не является универсальной константой языка SQL.

### ESCAPE: когда % или _ — часть искомого текста, а не шаблона

Что если в самих данных встречается символ `%` или `_` как обычный текстовый символ, а не как служебный символ шаблона — например, нужно найти товар, в названии которого буквально есть знак процента, вроде «Скидка 10%»? Прямой поиск `LIKE '%10%%'` не сработает так, как хочется: MySQL воспримет второй `%` как символ шаблона «любое количество символов», а не как буквальный знак процента. Для таких случаев в `LIKE` предусмотрена конструкция `ESCAPE`, которая назначает один символ **экранирующим** — стоящий сразу после него `%` или `_` начинает читаться буквально, а не как шаблон:

```sql
SELECT name
FROM products
WHERE name LIKE '%10\%%' ESCAPE '\';
```

Здесь символ `\` назначен экранирующим через `ESCAPE '\'`, а сочетание `\%` внутри шаблона означает «буквальный символ `%`», а не «любое количество символов». Оставшиеся `%` в начале и в конце шаблона по-прежнему работают как обычные символы шаблона — «что угодно до» и «что угодно после». В качестве экранирующего можно выбрать любой символ, но по историческим причинам чаще всего используется именно обратный слэш `\`. На практике конструкция `ESCAPE` нужна нечасто — только когда в реальных данных действительно встречаются символы `%` или `_` как часть смысла текста, а не как разделители.

### IN, BETWEEN и LIKE можно комбинировать с AND/OR

Все три оператора этого урока — обычные условия, которые точно так же участвуют в составных выражениях с `AND`/`OR`/`NOT` и скобками из прошлого урока. Например, найдём недорогие товары из определённых категорий, название которых содержит слово «беспроводная»:

```sql
SELECT name, category, price
FROM products
WHERE category IN ('Периферия', 'Аксессуары')
  AND price BETWEEN 500 AND 3000
  AND name LIKE '%беспроводная%';
```

### Резюме

- `col IN (v1, v2, ...)` — сокращение для серии сравнений на равенство через `OR`; удобно при проверке принадлежности списку из нескольких значений. Есть отрицающая форма `NOT IN` — осторожно с `NULL` в списке.
- `col BETWEEN a AND b` — сокращение для `col >= a AND col <= b`; **включает обе границы**; работает и с числами, и с датами (для дат — не забывать про время суток на верхней границе). Есть `NOT BETWEEN`.
- `LIKE` сравнивает текст с шаблоном: `%` — любое количество любых символов (включая ноль), `_` — ровно один произвольный символ.
- Чувствительность `LIKE` к регистру определяется настройками сравнения (collation) базы/столбца, а не жёстко зафиксирована в самом операторе.
- `ESCAPE 'символ'` назначает экранирующий символ, позволяя искать буквальные `%`/`_` как часть текста, а не как служебные символы шаблона.
- Все три оператора — обычные условия `WHERE`, свободно комбинируемые между собой и с `AND`/`OR`/`NOT` из предыдущего урока.
