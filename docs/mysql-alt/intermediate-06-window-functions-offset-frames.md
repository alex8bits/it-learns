Это тема второго урока про оконные функции.

### LAG и LEAD: значение соседней строки

`LAG()` возвращает значение указанного столбца из строки, которая находится **на N позиций раньше** текущей (по порядку, заданному `ORDER BY` внутри `OVER`); `LEAD()` — симметрично, значение из строки **на N позиций позже**. Классическая задача, для которой они созданы — сравнение текущего периода с предыдущим, например, помесячная выручка магазина и её изменение относительно прошлого месяца:

```sql
WITH monthly_revenue AS (
    SELECT
        DATE_FORMAT(o.created_at, '%Y-%m') AS month,
        SUM(oi.quantity * oi.price) AS revenue
    FROM orders o
    INNER JOIN order_items oi ON oi.order_id = o.id
    GROUP BY DATE_FORMAT(o.created_at, '%Y-%m')
)
SELECT
    month,
    revenue,
    LAG(revenue) OVER (ORDER BY month) AS prev_month_revenue,
    revenue - LAG(revenue) OVER (ORDER BY month) AS revenue_change
FROM monthly_revenue
ORDER BY month;
```

Для каждой строки (месяца) `LAG(revenue) OVER (ORDER BY month)` подставляет `revenue` **предыдущей** по порядку строки — то есть выручку прошлого месяца, оказавшуюся рядом с текущей без единого самостоятельного `JOIN` таблицы на саму себя. Задача «сравнить строку с предыдущей» ранее в курсе требовала бы self-join (пятнадцатый урок уровня «Начинающий») с искусственным условием соответствия по номеру месяца — заметно более громоздкой конструкции, чем `LAG`.

Для самой первой строки окна (у которой просто не существует предыдущей) `LAG()` возвращает `NULL` — предсказуемое, ожидаемое поведение (аналогично `SUM`/`MAX` по пустому множеству из восьмого урока уровня «Начинающий»): значения для сравнения физически не существует, и `NULL` корректно отражает это «отсутствие». `LAG()` и `LEAD()` принимают необязательный второй аргумент — смещение (по умолчанию 1) и необязательный третий — значение по умолчанию вместо `NULL`, например, `LAG(revenue, 1, 0) OVER (ORDER BY month)` вернёт `0` для первой строки вместо `NULL`, если по смыслу задачи это уместнее.

### FIRST_VALUE и LAST_VALUE: значение из края окна

`FIRST_VALUE()` возвращает значение из **первой** строки окна, `LAST_VALUE()` — из **последней**, независимо от того, на какой по счёту строке эта функция вычисляется. Например, для каждого заказа клиента показать сумму его самого первого заказа (чтобы видеть, выросли клиент в тратах или нет с момента первого обращения):

```sql
SELECT
    o.id AS order_id,
    o.customer_id,
    o.created_at,
    SUM(oi.quantity * oi.price) AS order_total,
    FIRST_VALUE(SUM(oi.quantity * oi.price)) OVER (
        PARTITION BY o.customer_id ORDER BY o.created_at
    ) AS first_order_total
FROM orders o
INNER JOIN order_items oi ON oi.order_id = o.id
GROUP BY o.id, o.customer_id, o.created_at;
```

Здесь `PARTITION BY o.customer_id` делит окно по клиентам (как в прошлом уроке), а `FIRST_VALUE(...)` внутри каждого такого окна берёт сумму самой первой по дате строки — то есть сумму первого заказа этого клиента — и повторяет её рядом с каждым последующим заказом того же клиента. `LAST_VALUE()` в применении требует особой осторожности: по умолчанию граница окна («до какой строки считается „последняя“») устроена не так, как интуитивно ожидается — это подробно объясняется в следующем разделе про `ROWS BETWEEN`.

### Рамка окна: ROWS BETWEEN

До сих пор `PARTITION BY`/`ORDER BY` определяли *раздел* и *порядок* строк в окне, но не то, какая именно **часть** этого раздела участвует в вычислении для конкретной строки. Эта часть называется **рамкой** (frame) и задаётся дополнительно конструкцией `ROWS BETWEEN ... AND ...`. Когда `ORDER BY` присутствует, а рамка не указана явно, MySQL по умолчанию использует рамку `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` — «от начала раздела до текущей строки включительно». Именно из-за этого умолчания оконный `SUM` с `ORDER BY` без явной рамки превращается в **накопительную сумму** (running total), а не в сумму всего раздела:

```sql
SELECT
    o.id AS order_id,
    o.customer_id,
    o.created_at,
    SUM(oi.quantity * oi.price) AS order_total,
    SUM(SUM(oi.quantity * oi.price)) OVER (
        PARTITION BY o.customer_id ORDER BY o.created_at
    ) AS running_total
FROM orders o
INNER JOIN order_items oi ON oi.order_id = o.id
GROUP BY o.id, o.customer_id, o.created_at
ORDER BY o.customer_id, o.created_at;
```

Для каждого заказа клиента `running_total` показывает сумму **всех его заказов до текущего и включая текущий**, а не сумму всех заказов клиента вообще — именно этот эффект и создаёт умолчание «от начала раздела до текущей строки». Как только следующий по дате заказ того же клиента обрабатывается, окно «сдвигается» — включает ещё одну строку, и накопительная сумма увеличивается. Это ровно то поведение, которое нужно для отчёта «рост выручки клиента со временем» — каждая строка показывает, сколько клиент потратил *к этому моменту*.

Рамку можно указать и явно, что делает намерение видимым в самом тексте запроса, а не зависящим от неочевидного умолчания:

```sql
SUM(SUM(oi.quantity * oi.price)) OVER (
    PARTITION BY o.customer_id
    ORDER BY o.created_at
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
) AS running_total
```

`UNBOUNDED PRECEDING` означает «без ограничения назад — от самого начала раздела», `CURRENT ROW` — «до текущей строки включительно». Явная запись рамки рекомендуется именно потому, что умолчание совпадает с ней лишь при наличии `ORDER BY` — для новичка это легко забыть и получить не накопительную, а, например, полную сумму раздела там, где она была не нужна, либо наоборот.

Другой частый вид рамки — **скользящее окно фиксированного размера**, например, среднее за последние три месяца:

```sql
SELECT
    month,
    revenue,
    AVG(revenue) OVER (
        ORDER BY month
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS moving_avg_3m
FROM monthly_revenue
ORDER BY month;
```

`2 PRECEDING AND CURRENT ROW` — рамка из трёх строк: две предыдущие плюс текущая. Для первых двух месяцев, у которых физически нет двух предыдущих строк, MySQL просто использует столько строк, сколько реально доступно (одну или две) — рамка не «дополняется» несуществующими строками и не выдаёт ошибку, а корректно сокращается у самого края раздела.

Наконец, чтобы получить **сумму по всему разделу целиком** для каждой строки (в отличие от накопительной суммы), рамку нужно расширить в обе стороны:

```sql
SUM(SUM(oi.quantity * oi.price)) OVER (
    PARTITION BY o.customer_id
    ORDER BY o.created_at
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
) AS customer_total_all_orders
```

`UNBOUNDED FOLLOWING` — «без ограничения вперёд, до самого конца раздела» — в сочетании с `UNBOUNDED PRECEDING` даёт весь раздел целиком, независимо от позиции текущей строки; именно такая рамка нужна и для корректной работы `LAST_VALUE()`, если вы хотите получить действительно последнюю строку раздела, а не «последнюю среди строк до текущей включительно», которая при умолчании совпадает с самой текущей строкой.

### Резюме

- **`LAG(col, N)`** / **`LEAD(col, N)`** возвращают значение столбца из строки, смещённой на `N` позиций назад/вперёд относительно текущей в пределах окна; для строк у края окна, где соседа не существует, результат — `NULL` (или значение по умолчанию, заданное третьим аргументом).
- **`FIRST_VALUE()`** / **`LAST_VALUE()`** возвращают значение из первой/последней строки текущей **рамки** окна — не всего раздела, если рамка не расширена явно.
- **Рамка окна** (`ROWS BETWEEN ... AND ...`) определяет, какая часть раздела участвует в вычислении для текущей строки; при наличии `ORDER BY` без явной рамки MySQL по умолчанию берёт `UNBOUNDED PRECEDING AND CURRENT ROW` — отсюда эффект «накопительной суммы» у обычного оконного `SUM`/`AVG` с `ORDER BY`.
- Явное указание рамки (`ROWS BETWEEN N PRECEDING AND CURRENT ROW` для скользящего окна, `UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING` для всего раздела) делает намерение запроса видимым и не зависящим от неочевидного умолчания.
- У краёв раздела рамка корректно сокращается до реально доступных строк, не вызывая ошибок и не «доливая» несуществующие данные.
- Оконные функции этого и прошлого урока вместе закрывают класс задач «вычислить что-то по группе строк, не теряя ни одной исходной строки» — от простой нумерации до накопительных итогов и сравнения с соседними периодами.
