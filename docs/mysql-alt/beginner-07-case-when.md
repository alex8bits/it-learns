Функция `COALESCE`, которую мы изучили в одиннадцатом уроке «Основ», решает частный случай условной логики: «подставь запасное значение, если исходное — `NULL`». Но реальные задачи часто требуют более гибкой условной логики: «если цена меньше 1000 — категория "бюджетный", если от 1000 до 5000 — "средний", иначе — "премиум"». Для произвольных условий в SQL есть выражение `CASE WHEN` — аналог конструкции `if/elif/else`, знакомой из большинства языков программирования, но записываемой как **выражение**, возвращающее значение, а не как управляющая конструкция, меняющая поток исполнения программы.

### Поисковый CASE: проверка произвольных условий

Самая гибкая и часто используемая форма — **поисковый** (searched) `CASE`, в котором после каждого `WHEN` стоит произвольное логическое условие (в точности такое же, какие мы уже писали в `WHERE`):

```sql
SELECT name, price,
    CASE
        WHEN price < 1000 THEN 'бюджетный'
        WHEN price < 5000 THEN 'средний'
        ELSE 'премиум'
    END AS price_segment
FROM products;
```

Выражение вычисляется построчно: для каждой строки таблицы `products` условия `WHEN` проверяются **по порядку сверху вниз**, и как только находится первое истинное условие, `CASE` возвращает значение из соответствующего `THEN` и **немедленно прекращает** проверку последующих условий — даже если они тоже оказались бы истинными. Именно поэтому во втором условии достаточно написать `WHEN price < 5000`, а не `WHEN price >= 1000 AND price < 5000` — раз мы дошли до второго условия, значит первое (`price < 1000`) уже дало `FALSE`, то есть цена гарантированно не меньше 1000, а проверка `< 5000` довершает диапазон. Порядок условий в `CASE` — не формальность, а часть логики: если случайно поменять условия местами, начиная с более широкого, более узкие условия попросту никогда не будут достигнуты.

Ветка `ELSE` — необязательная, но крайне рекомендуемая: она задаёт значение для всех строк, не подошедших ни под одно из условий `WHEN`. Если `ELSE` не указан, а ни одно условие не оказалось истинным, `CASE` возвращает `NULL` — это не ошибка, но часто неожиданный результат, если про такую возможность забыли:

```sql
SELECT name, price,
    CASE
        WHEN price < 1000 THEN 'бюджетный'
        WHEN price < 5000 THEN 'средний'
    END AS price_segment
FROM products;
-- товары дороже 5000 получат NULL в price_segment, а не 'премиум'
```

### Простой CASE: сравнение одного выражения со списком значений

Есть и более компактная форма — **простой** (simple) `CASE`, когда одно и то же выражение сравнивается на равенство с несколькими конкретными значениями:

```sql
SELECT name, category,
    CASE category
        WHEN 'Периферия' THEN 'Аксессуары для ПК'
        WHEN 'Мониторы' THEN 'Экраны'
        ELSE 'Другое'
    END AS category_display
FROM products;
```

Это в точности эквивалент поискового `CASE` с условиями равенства, записанный короче — `CASE category WHEN 'Периферия' THEN ...` полностью равносилен `CASE WHEN category = 'Периферия' THEN ...`. Простую форму стоит использовать именно тогда, когда речь идёт про сравнение одного и того же значения с несколькими вариантами через равенство — как только нужны неравенства, диапазоны или условия с разными столбцами, требуется уже поисковая форма.

### CASE как обычное выражение — можно использовать почти везде

`CASE` — это **выражение**, а не отдельная команда, и оно ведёт себя так же, как любое другое выражение из третьего урока (арифметика, `CONCAT`, строковые функции): его можно использовать в `SELECT`, в `WHERE`, комбинировать с другими функциями, вкладывать одно в другое. Например, используем `CASE` прямо в `WHERE`, чтобы отфильтровать «премиальные» товары без явного повторения условия дважды:

```sql
SELECT name, price
FROM products
WHERE (CASE WHEN price >= 5000 THEN 1 ELSE 0 END) = 1;
```

Этот пример скорее иллюстративный — в реальности такое условие проще и естественнее написать напрямую как `WHERE price >= 5000`, но он показывает, что `CASE` — полноценное выражение, а не специальная конструкция, доступная только внутри `SELECT`. Более практичный пример — комбинирование `CASE` с уже знакомым нам `CONCAT` и функцией `COALESCE`:

```sql
SELECT name,
    CONCAT(name, ' — ', CASE WHEN stock > 0 THEN 'в наличии' ELSE 'нет в наличии' END) AS availability_label
FROM products;
```

### CASE внутри ORDER BY: условная сортировка

Одно из самых полезных нестандартных применений `CASE` — сортировка по условной логике, которую невозможно выразить через простой `ORDER BY column`. Классический пример — «сначала показать товары в наличии, а среди них — отсортировать по возрастанию цены, а товары не в наличии — отправить в конец списка, независимо от их цены»:

```sql
SELECT name, price, stock
FROM products
ORDER BY
    CASE WHEN stock > 0 THEN 0 ELSE 1 END,
    price ASC;
```

Здесь `CASE` вычисляет для каждой строки временное «служебное» число — `0` для товаров в наличии и `1` для отсутствующих — и `ORDER BY` сортирует прежде всего по этому числу (все нули окажутся раньше всех единиц), а при равенстве этого числа — по цене. Обратите внимание, что у `ORDER BY` здесь два «уровня» сортировки, разделённые запятой — этот приём (сортировка сначала по одному критерию, а при совпадении — по следующему) мы уже видели в девятом уроке «Основ», просто здесь первый критерий — не обычный столбец, а вычисленное `CASE`-выражение.

Другой распространённый пример — сортировка по нестандартному порядку значений, который не совпадает ни с алфавитным, ни с числовым порядком самого столбца — например, вывести заказы в порядке важности статуса, а не в алфавитном порядке названий статусов:

```sql
SELECT id, status
FROM orders
ORDER BY
    CASE status
        WHEN 'new' THEN 1
        WHEN 'processing' THEN 2
        WHEN 'shipped' THEN 3
        WHEN 'delivered' THEN 4
        ELSE 5
    END;
```

Без такого `CASE` обычная сортировка `ORDER BY status` расставила бы статусы в алфавитном порядке текста (`'delivered'`, `'new'`, `'processing'`, `'shipped'`), что почти никогда совпадает с желаемым порядком по смыслу бизнес-процесса.

### Резюме

- `CASE WHEN условие THEN значение ... ELSE значение END` — поисковый `CASE`: условия проверяются по порядку сверху вниз, возвращается значение из первого истинного `WHEN`; последующие условия не проверяются.
- `CASE выражение WHEN значение THEN результат ... END` — простой `CASE`: компактная запись для сравнения одного выражения на равенство с несколькими вариантами; эквивалент поискового `CASE` с условиями равенства.
- Ветка `ELSE` необязательна, но без неё несовпавшие строки получат `NULL` — это легко забыть и получить неожиданный результат.
- `CASE` — обычное выражение, а не отдельная команда: его можно использовать в `SELECT`, `WHERE`, комбинировать с `CONCAT` и другими функциями.
- `CASE` внутри `ORDER BY` позволяет задать произвольный, нестандартный порядок сортировки (например, «сначала в наличии, затем по цене» или пользовательский порядок статусов), не выражаемый простым `ORDER BY column`.
