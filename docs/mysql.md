# Курс по MySQL — план создания (черновик)

> Статус: черновик плана (v2 — после внешнего ревью: JOIN перенесён в «Начинающий»,
> добавлены порядок выполнения SELECT, COALESCE/NULLIF, чтение ошибок, мини-проекты,
> блоки в «Продвинутом»). Обсуждаем состав, потом наполняем через админку.
> **Правила составления уроков: [mysql-lesson-rule.md](mysql-lesson-rule.md)** — материал,
> теория, практика, границы тем и путь сохранения файла урока
> (`docs/mysql/<level>-<NN>-<theme>.md`).
> Структура соответствует платформе: Курс → Уровень → Урок; урок = материал (чтение) +
> теоретические задания (quiz) + практические SQL-задания (изолированная среда).
> Практика — не в каждом уроке: «—» в колонке «Практика» = урок только с материалом и
> теорией (платформа поддерживает: урок завершается по ответам на теорию).
> **Версия: курс ведётся под MySQL 8.x.** Минимальные версии для возможностей:
> CTE (в т.ч. рекурсивные) и оконные функции — 8.0; `JSON_TABLE` — 8.0.14;
> `CHECK`-ограничения — 8.0.16.

## Цель курса

Дать исчерпывающие знания MySQL: путь от «впервые вижу SQL» до уверенной работы с
производственной базой — проектирование схемы, JOIN'ы, подзапросы, оконные функции,
транзакции, индексы и оптимизация, серверные объекты и основы эксплуатации.

## Аудитория и входные требования

- **Основы**: никакой подготовки не нужно.
- **Начинающий**: пройден «Основы» (однотабличные запросы, INSERT/UPDATE/DELETE, ограничения).
- **Средний**: уверенный SELECT/WHERE/GROUP BY, JOIN'ы, представление о внешних ключах.
- **Продвинутый**: всё из «Среднего», опыт чтения чужих запросов.

## Сквозной учебный датасет

Одна знакомая БД на весь курс упрощает материал и позволяет строить задания с нарастающей
сложностью. Предлагаем основной домен — **интернет-магазин**:

- `categories(id, parent_id, name)` — дерево (self-join, рекурсивные CTE);
- `products(id, category_id, name, price, stock, created_at, attributes JSON)`;
- `customers(id, name, email, city, registered_at)`;
- `orders(id, customer_id, status, created_at, paid_at)`;
- `order_items(id, order_id, product_id, quantity, price)` — M:N + история цен;
- `payments(id, order_id, amount, method, payload JSON)`;
- `reviews(id, product_id, customer_id, rating, body, created_at)` — под FULLTEXT;
- `employees(id, name, manager_id, salary, hired_at)` — self-join, оконные функции;
- `order_log(id, order_id, changed_at, old_status, new_status)` — под триггеры.

Для спец-тем (партиционирование, репликация, бэкап) — отдельные мини-схемы с большим
объёмом сгенерированных данных.

Практика: изолированная среда с сид-скриптом и эталонным результатом; для уроков этого
курса используем `runtime = mysql` (Docker-изоляция), эталон сравнивается канонически.

## Уровень 3 — «Средний»

Цель: сложный SQL — подзапросы, CTE, оконные функции, загрузка данных, транзакции,
проектирование схемы. ~12 уроков (10 с практикой, 2 только теория).

| № | Урок | Практика |
|---|---|---|
| 1 | Подзапросы: вводный мост «как собирать сложный запрос» — простой SELECT → SELECT с агрегатом → SELECT как источник другого SELECT → derived table → CTE (подзапросы и CTE — способы композиции, а не случайные конструкции); скалярные подзапросы, IN (подзапрос), производные таблицы в FROM | «Дороже среднего», «клиенты без заказов» |
| 2 | Коррелированные подзапросы: EXISTS / NOT EXISTS | Сравнение с LEFT JOIN-анти-join |
| 3 | UNION / UNION ALL: правила совместимости, сортировка результата; отдельная техника вертикального комбинирования (на фоне JOIN — горизонтального и подзапросов — вложенного) | Склейка отчётов |
| 4 | CTE: WITH, цепочки CTE, читаемость; рекурсивные CTE; календарная таблица | Обход дерева категорий; выручка по месяцам, включая месяцы без заказов |
| 5 | Оконные функции I: ROW_NUMBER, RANK, DENSE_RANK, PARTITION BY | Топ-3 в каждой категории, дедупликация |
| 6 | Оконные функции II: LAG/LEAD, FIRST_VALUE, накопительные суммы, ROWS BETWEEN | Рост по месяцам, скользящее среднее |
| 7 | Загрузка данных: INSERT ... SELECT (миграции, ETL); upsert-паттерны: INSERT ... ON DUPLICATE KEY UPDATE, REPLACE, INSERT IGNORE — различия, когда что применять | Идемпотентная загрузка: повторный прогон не плодит дубликаты |
| 8 | Чтение ошибок MySQL: типичные коды (1054 unknown column, 1064 syntax, 1062 duplicate key, 1451/1452 foreign key, 1048 cannot be null); алгоритм разбора: код → текст → строка → таблица/колонка → нарушенное ограничение | — (закрепляется во всей последующей практике) |
| 9 | Транзакции: ACID, START TRANSACTION / COMMIT / ROLLBACK, SAVEPOINT; сценарий «заказ → order_items → stock → payment» с намеренной ошибкой на одном из шагов | Всё или ничего: частично сохранённый заказ невозможен |
| 10 | Изоляция и блокировки: уровни изоляции, неповторяемое чтение/фантомы, SELECT ... FOR UPDATE | — (нужно две параллельные сессии; в материале — Docker-инструкция «два соединения дома») |
| 11 | Проектирование схемы: 1НФ-3НФ, M:N через связующую таблицу, денормализация; VIEW | Нормализовать «сырую» таблицу; собрать VIEW-отчёт |
| 12 | Проект «Аналитика магазина»: CTE + подзапросы + оконные функции + VIEW | 2–3 сквозных задания на пройденное |

## Формат теории (для всех уровней)

Полные правила составления урока — [mysql-lesson-rule.md](mysql-lesson-rule.md); здесь — краткая выжимка.

- 3–5 вопросов на урок, один вопрос — одна идея; вариант ровно один верный.
- Неверные варианты — «правдоподобные ловушки», каждый со своим `error_text`:
  почему именно этот выбор неверен (платформа показывает текст при ошибке).
- Любимые темы вопросов: NULL-семантика, WHERE vs HAVING, ON vs WHERE в LEFT JOIN,
  логический порядок выполнения запроса, COUNT(*) vs COUNT(col), UNION vs UNION ALL,
  когда индекс не применяется, DELETE vs TRUNCATE vs DROP.

## Порядок работ (когда план согласован)

1. Зафиксировать схему сквозного датасета + сид-скрипты по урокам (эволюция схемы:
   таблицы появляются по мере уроков).
2. Создать курс и 4 уровня в админке; уроки — черновиками, публиковать по мере готовности.
3. Наполнять уроками волнами: уровень целиком → ревью → публикация. Каждый урок
   составляется **только как markdown-файл** по правилам
   [mysql-lesson-rule.md](mysql-lesson-rule.md) и сохраняется в
   `docs/mysql/<level>-<NN>-<theme>.md`; на этапе составления ничего не пишется в БД
   и в сидеры. Затем урок механически переносится в БД — через админку, сгенерированный
   по файлам сидер или бота (формат файла машиночитаем).
4. Настроить практику: seed_sql + expected_rows/expected_hash; runtime = mysql.
5. Приёмка уровня: самостоятельный прогон «глазами студента» в предпросмотре админки.

## Открытые вопросы

  (например, «однотабличная аналитика» и «связи и JOIN'ы»)?
- Docker-инструкции «попробовать дома» (изоляция-лаба с двумя сессиями, события,
  администрирование, бэкап) — один общий документ или врезки в соответствующих уроках?
