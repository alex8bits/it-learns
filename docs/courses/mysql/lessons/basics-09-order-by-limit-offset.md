## Материал

В третьем уроке мы упомянули: `LIMIT` без сортировки не гарантирует, *какие* именно строки попадут в результат — это упоминание было отложено «на потом». Пришло время закрыть этот вопрос: разберём `ORDER BY` — секцию, которая определяет порядок строк в результате, — а также точную форму `LIMIT`/`OFFSET`, позволяющую реализовать постраничный вывод данных.

### Зачем нужен явный порядок строк

По умолчанию, без каких-либо дополнительных указаний, MySQL не даёт никаких гарантий, в каком порядке вернутся строки результата `SELECT`. На практике сервер часто (хотя не всегда и не гарантированно) возвращает строки в том порядке, в котором физически хранит данные на диске — но полагаться на это нельзя: порядок хранения может зависеть от способа вставки, от внутренних оптимизаций сервера, от использованных индексов (тема уровня «Продвинутый») и может измениться при следующем изменении данных, даже если сам запрос остался тем же.

Если порядок строк важен для задачи — «показать самые дешёвые товары первыми», «вывести клиентов по алфавиту» — на него нельзя полагаться неявно. Для этого существует секция `ORDER BY`.

### ORDER BY: сортировка результата

```sql
SELECT name, price
FROM products
ORDER BY price;
```

Этот запрос вернёт все товары, отсортированные по возрастанию цены — от самого дешёвого к самому дорогому. По умолчанию `ORDER BY` сортирует **по возрастанию** (для чисел — от меньшего к большему, для текста — по алфавиту, для дат — от более раннего к более позднему момента времени, то есть с использованием тех же правил сравнения, которые мы разобрали в прошлом уроке для `WHERE`).

Чтобы явно указать порядок сортировки, используются модификаторы:

- **`ASC`** (ascending — «по возрастанию») — тот же порядок, что и по умолчанию, обычно указывается для явности, хотя без него результат будет тем же;
- **`DESC`** (descending — «по убыванию») — обратный порядок, от большего к меньшему:

```sql
SELECT name, price
FROM products
ORDER BY price DESC;
```

Этот запрос вернёт товары от самого дорогого к самому дешёвому.

### Место ORDER BY в общем порядке частей запроса

`ORDER BY` — ещё одна секция в уже знакомой нам цепочке частей SQL-запроса. Её место — после `WHERE` (если оно есть), но перед `LIMIT`:

```sql
SELECT name, price
FROM products
WHERE price < 5000
ORDER BY price DESC
LIMIT 3;
```

Логика такого порядка выполнения естественна, даже если формально СУБД может оптимизировать выполнение внутри себя иначе: сначала отбираются нужные строки (`WHERE`), затем они выстраиваются в нужном порядке (`ORDER BY`), и только затем из отсортированного результата берётся ограниченное количество первых строк (`LIMIT`). Именно поэтому `LIMIT` в сочетании с `ORDER BY` даёт предсказуемый и осмысленный результат — например, «три самых дорогих товара дешевле 5000» из примера выше, а не случайные три строки, как могло бы быть без сортировки.

### Сортировка по нескольким столбцам

Иногда сортировки по одному столбцу недостаточно — например, если несколько товаров стоят одинаково, и хочется, чтобы внутри одной цены они шли по алфавиту названия. Для этого в `ORDER BY` можно перечислить несколько столбцов через запятую:

```sql
SELECT name, price
FROM products
ORDER BY price DESC, name ASC;
```

Порядок здесь имеет значение: сервер сначала сортирует все строки по первому указанному столбцу (`price`, по убыванию); а затем — только для тех групп строк, где значение первого столбца *совпадает*, применяет сортировку по второму столбцу (`name`, по возрастанию). Если бы все товары имели разные цены, второй критерий сортировки (`name`) вообще не проявился бы в результате — он «включается в игру» только при совпадении по первому. Каждому столбцу в списке `ORDER BY` можно назначить свой собственный модификатор `ASC`/`DESC` независимо от других: например, `ORDER BY price DESC, name ASC` — цена по убыванию, а внутри одной цены — название по алфавиту.

### LIMIT и OFFSET: явное постраничное разбиение

Мы уже знакомы с простейшей формой `LIMIT N` — «верни не более N первых строк результата». Но что, если нужны не первые N строк, а, например, строки с 11-й по 20-ю — то есть «вторая страница» результатов, если считать по 10 строк на страницу? Для этого существует **смещение** (offset) — указание, сколько первых строк результата нужно пропустить, прежде чем начать отбирать.

Есть две равнозначные формы записи:

```sql
-- форма 1: LIMIT количество OFFSET смещение
SELECT name, price
FROM products
ORDER BY id
LIMIT 10 OFFSET 10;
```

```sql
-- форма 2 (сокращённая, специфичная для MySQL): LIMIT смещение, количество
SELECT name, price
FROM products
ORDER BY id
LIMIT 10, 10;
```

Обе записи означают одно и то же: «пропустить первые 10 строк отсортированного результата, а затем вернуть следующие 10» — то есть строки со 11-й по 20-ю. Единственное отличие двух форм — порядок чисел: в варианте с явным `OFFSET` сначала указывается количество, затем смещение (`LIMIT количество OFFSET смещение`), а в сокращённом варианте с запятой — сначала смещение, затем количество (`LIMIT смещение, количество`) — это легко перепутать, поэтому в этом курсе мы рекомендуем использовать более явную и однозначную форму с ключевым словом `OFFSET`, даже если она чуть длиннее — код становится нагляднее и меньше провоцирует ошибку «перепутал порядок чисел».

### Постраничный вывод: практическая формула

Комбинация `ORDER BY` + `LIMIT ... OFFSET ...` — это ровно тот механизм, который стоит за постраничной навигацией («страница 1», «страница 2», …) в любом реальном приложении: списке товаров интернет-магазина, ленте сообщений, таблице заказов в админ-панели. Если на странице должно быть `N` строк, а пользователь запрашивает страницу номер `k` (считая с первой страницы как `k = 1`), формула смещения такая:

```
OFFSET = (k - 1) * N
```

Например, для 10 товаров на странице и запроса третьей страницы: `OFFSET = (3 - 1) * 10 = 20`, значит нужно пропустить первые 20 строк и взять следующие 10:

```sql
SELECT name, price
FROM products
ORDER BY id
LIMIT 10 OFFSET 20;
```

**Критически важно**, чтобы такой запрос всегда сопровождался `ORDER BY` по стабильному критерию (обычно — по первичному ключу или иному однозначно упорядочивающему столбцу). Если сортировки нет, или сортировка ведётся по столбцу, где допускаются повторяющиеся значения без дополнительного уточнения порядка (например, только по `price`, где несколько товаров стоят одинаково), при переходе между «страницами» есть риск, что одна и та же строка попадёт сразу на две разные страницы, а другая — вообще ни на одну, потому что относительный порядок строк с одинаковым значением сортировки формально не гарантирован сервером между двумя отдельными выполнениями запроса.

### Резюме

- `ORDER BY столбец` определяет порядок строк в результате `SELECT`; без него порядок строк не гарантирован и не должен считаться предсказуемым.
- Модификаторы `ASC` (по возрастанию, по умолчанию) и `DESC` (по убыванию) задают направление сортировки; правило «больше/меньше» зависит от типа данных (числа, текст по алфавиту, даты хронологически), как и в `WHERE`.
- Можно сортировать по нескольким столбцам сразу, перечислив их через запятую — второй и последующие столбцы применяются только при совпадении значений по предыдущим.
- `ORDER BY` располагается после `WHERE` и перед `LIMIT` в общей структуре запроса.
- `LIMIT количество OFFSET смещение` (или равнозначная сокращённая форма `LIMIT смещение, количество`) отбирает конкретный диапазон строк из отсортированного результата — это основа постраничного вывода данных.
- Смещение для страницы номер `k` при `N` строках на странице вычисляется как `(k - 1) * N`.
- Постраничный вывод обязательно должен сопровождаться `ORDER BY` по однозначному критерию — иначе набор строк на «страницах» может пересекаться или содержать пропуски между отдельными запросами.

## Теоретические задания

### Вопрос 1: Почему результат запроса `SELECT ... LIMIT 3` без ORDER BY называют непредсказуемым?

- ✅ без ORDER BY сервер не гарантирует порядок строк, поэтому «первые три» не определены
- ❌ LIMIT выполняется до чтения таблицы и берёт случайные строки — error_text: LIMIT ничего не выбирает сам — он лишь обрезает уже полученный результат; непредсказуемость в том, что без ORDER BY не гарантирован сам порядок строк результата.
- ❌ без ORDER BY сервер всегда возвращает последние вставленные строки — error_text: порядок «как вставляли» не гарантирован: он зависит от физического хранения и внутренних оптимизаций сервера и может измениться, даже если запрос не менялся.

### Вопрос 2: Какой порядок строк вернёт `ORDER BY price DESC`?

- ✅ от самого дорогого товара к самому дешёвому
- ❌ от самого дешёвого к самому дорогому — это же порядок по умолчанию — error_text: по умолчанию (и с ASC) сортировка идёт по возрастанию; DESC — явное указание убывания: от большего значения к меньшему.
- ❌ по названиям товаров: цена — число, а сортировать по значению можно только текст — error_text: сортировать можно значения любого типа: числа — по величине, текст — по алфавиту, даты — хронологически; здесь сортировка числовая, но по убыванию.

### Вопрос 3: Когда в `ORDER BY price DESC, name ASC` вступает в силу столбец name?

- ✅ только для строк с одинаковой ценой: второй столбец уточняет порядок внутри групп равных значений первого
- ❌ name пересортировывает весь результат, отменяя сортировку по цене — error_text: порядок столбцов задаёт приоритет: сначала строки выстраиваются по цене, и лишь там, где цена совпала, сравниваются названия.
- ❌ никогда: MySQL использует только первый столбец списка — error_text: используются все перечисленные столбцы — просто каждый следующий подключается лишь при совпадении значений по предыдущим; иначе порядок «внутри одинаковых цен» было бы не задать.

### Вопрос 4: Какие строки отсортированного результата вернёт `LIMIT 10 OFFSET 20`?

- ✅ строки с 21-й по 30-ю
- ❌ строки с 20-й по 29-ю: OFFSET — номер первой возвращаемой строки — error_text: OFFSET — это сколько строк пропустить: пропускаем 20, значит первая возвращаемая — 21-я, и при LIMIT 10 результат — строки с 21-й по 30-ю.
- ❌ строки с 11-й по 20-ю: число после LIMIT — это смещение — error_text: в форме «LIMIT количество OFFSET смещение» число после LIMIT — размер страницы, а смещение стоит после OFFSET; их легко перепутать местами, поэтому и рекомендуется явная форма с ключевым словом OFFSET.

### Вопрос 5: Постраничный вывод по 5 строк на страницу. Какой OFFSET нужен для страницы №3?

- ✅ 10 — по формуле (k − 1) × N: (3 − 1) × 5
- ❌ 15 — смещение равно произведению номера страницы на размер страницы — error_text: при таком расчёте даже первая страница начиналась бы не с начала списка; смещение — это сколько строк пропустить до нужной страницы: (3 − 1) × 5 = 10.
- ❌ 3 — смещение равно номеру страницы — error_text: OFFSET 3 пропустил бы всего три строки и вернул строки 4–8 — середину первой страницы, а не третью.
