## Материал

На уровне «Основы» мы уже пользовались `WHERE` для отбора строк по одному условию: цена больше значения, категория равна конкретному тексту. Но реальные задачи почти никогда не описываются одним условием: «товары дороже 1000, но только из категории "Периферия"», «клиенты из Москвы или Санкт-Петербурга», «заказы, которые не в статусе "отменён"». Чтобы выразить такие требования, `WHERE` умеет комбинировать несколько условий с помощью **логических операторов** `AND`, `OR` и `NOT`. Этот урок открывает уровень «Начинающий» именно ими, потому что почти любая следующая тема курса — от `LIKE` до `JOIN` — будет использовать составные условия как обычный рабочий инструмент.

### AND: оба условия одновременно

Оператор `AND` объединяет два условия так, что итоговое условие истинно только тогда, когда истинны **оба** условия одновременно. Найдём товары категории «Периферия», которые дороже 1000 рублей:

```sql
SELECT name, category, price
FROM products
WHERE category = 'Периферия' AND price > 1000;
```

Каждая строка таблицы `products` проверяется по очереди: сначала вычисляется `category = 'Периферия'` (`TRUE` или `FALSE`), затем `price > 1000` (`TRUE` или `FALSE`), а затем оба результата соединяются оператором `AND`. Строка попадёт в результат только если оба условия дали `TRUE`. Если товар относится к «Периферии», но стоит 800 рублей — строка не пройдёт, потому что второе условие даёт `FALSE`, а `AND` требует истинности обеих частей.

`AND` можно применять и к большему числу условий — они просто соединяются друг за другом:

```sql
SELECT name, category, price, stock
FROM products
WHERE category = 'Периферия' AND price > 1000 AND stock > 0;
```

Здесь строка проходит фильтр только если верны все три условия сразу: правильная категория, достаточная цена и товар есть на складе.

### OR: хотя бы одно из условий

Оператор `OR`, в отличие от `AND`, требует истинности **хотя бы одного** из условий — обоих, или только одного, не важно, какого именно. Найдём товары либо из категории «Периферия», либо из категории «Мониторы»:

```sql
SELECT name, category, price
FROM products
WHERE category = 'Периферия' OR category = 'Мониторы';
```

Строка попадёт в результат, если верно первое условие, либо верно второе, либо (в принципе) оба сразу — хотя здесь одновременная истинность обоих условий невозможна, так как `category` не может одновременно равняться двум разным значениям. Важное практическое наблюдение: если нужно проверить принадлежность столбца к одному из нескольких конкретных значений, повторять `OR` для каждого значения по отдельности неудобно уже при трёх-четырёх вариантах — специальный, более компактный оператор для этого случая, `IN`, будет темой следующего урока; здесь же важно понять именно логику `OR` как таковую.

### NOT: логическое отрицание

Оператор `NOT` инвертирует результат условия, стоящего сразу за ним: `TRUE` становится `FALSE`, а `FALSE` становится `TRUE`. Найдём все товары, которые **не** относятся к категории «Периферия»:

```sql
SELECT name, category
FROM products
WHERE NOT category = 'Периферия';
```

Этот запрос равносилен более привычной записи через `<>` (оператор «не равно», знакомый нам с восьмого урока «Основ»):

```sql
SELECT name, category
FROM products
WHERE category <> 'Периферия';
```

Для простого «не равно» `<>` обычно читается проще и используется чаще, чем `NOT ... = ...`. Настоящая сила `NOT` раскрывается, когда он применяется к более сложному условию в скобках — например, «не (дорогой товар из Периферии)»:

```sql
SELECT name, category, price
FROM products
WHERE NOT (category = 'Периферия' AND price > 1000);
```

Такая строка попадёт в результат, если условие в скобках в целом ложно — то есть либо товар не из «Периферии», либо (даже если из «Периферии») цена не больше 1000. Обратите внимание, что отрицание составного условия — это не то же самое, что отрицание каждой части по отдельности: `NOT (A AND B)` не равносильно `(NOT A) AND (NOT B)`. Верное преобразование (закон де Моргана, хотя запоминать это название не обязательно — достаточно понимать суть) выглядит так: `NOT (A AND B)` равносильно `(NOT A) OR (NOT B)`, а `NOT (A OR B)` равносильно `(NOT A) AND (NOT B)`. То есть отрицание «И» превращается в «ИЛИ» отрицаний, и наоборот. Это не тема для механического заучивания формулы — куда полезнее просто аккуратно проверять логику на конкретных данных, если условие получилось сложным.

### Приоритет операторов: почему без скобок легко ошибиться

Когда в одном условии соединяются `AND` и `OR`, у СУБД должно быть точное правило, что вычислять первым — иначе один и тот же запрос можно было бы прочитать двумя разными способами. В SQL, как и в большинстве языков программирования, у `AND` **более высокий приоритет**, чем у `OR` — это означает, что `AND` «связывает» свои операнды крепче и вычисляется первым, если не указано иное. Рассмотрим пример, в котором это критично: найти товары категории «Периферия», у которых цена больше 1000, **либо** любые товары из категории «Мониторы» (независимо от цены):

```sql
SELECT name, category, price
FROM products
WHERE category = 'Периферия' AND price > 1000 OR category = 'Мониторы';
```

Из-за более высокого приоритета `AND` этот запрос фактически читается так, будто в нём стоят скобки:

```sql
WHERE (category = 'Периферия' AND price > 1000) OR category = 'Мониторы'
```

То есть результат ровно тот, который был задуман: дорогая периферия **или** любой монитор. Но если по ошибке ожидалось другое сочетание — например, «товары из Периферии, у которых либо цена больше 1000, либо категория Мониторы» (что не имеет особого смысла как формулировка, но иллюстрирует проблему), запись без скобок дала бы совершенно другой результат, чем задумывалось. Проблема в том, что неверно расставленный приоритет операторов — одна из самых незаметных ошибок в SQL: запрос не выдаёт ошибку синтаксиса, он просто отбирает не те строки, и заметить это можно только сравнив результат с ожидаемым вручную.

### Скобки — не просто украшение, а обязательный инструмент

Единственный надёжный способ избежать путаницы с приоритетом — **явно расставлять скобки** вокруг логических групп, даже там, где приоритет по умолчанию совпадает с задуманным. Перепишем предыдущий пример со скобками, которые делают намерение автора запроса очевидным любому, кто читает код, без необходимости держать в голове правило приоритета:

```sql
SELECT name, category, price
FROM products
WHERE (category = 'Периферия' AND price > 1000) OR category = 'Мониторы';
```

Смысл запроса не изменился (мы уже выяснили, что скобки здесь совпадают с приоритетом по умолчанию), но читаемость выросла принципиально: теперь любой человек, включая вас самих через полгода, поймёт условие мгновенно, а не будет восстанавливать правило приоритета в уме. Возьмём более сложный, реалистичный пример: найти товары, которые (из категории «Периферия» **и** дороже 1000) **или** (из категории «Мониторы» **и** есть на складе):

```sql
SELECT name, category, price, stock
FROM products
WHERE (category = 'Периферия' AND price > 1000)
   OR (category = 'Мониторы' AND stock > 0);
```

Здесь скобки уже не просто дублируют приоритет по умолчанию — они задают структуру, которую невозможно правильно выразить без них: внутри каждой группы стоит `AND`, а сами группы соединены `OR`. Практическое правило, которое стоит взять с собой на весь курс: **если в одном условии встретились и `AND`, и `OR` — расставляйте скобки явно**, не полагаясь на память о приоритете, даже если вы этот приоритет отлично знаете. Это не запасной вариант «для новичков» — так пишут условия и опытные разработчики, потому что явные скобки читает и проверяет не только автор запроса, но и его коллеги.

### Скобки со вложенным NOT

`NOT` тоже подчиняется правилам приоритета — у него приоритет даже выше, чем у `AND`, то есть без скобок `NOT` «прилипает» к одному соседнему условию, а не ко всей группе за ним. Поэтому если нужно инвертировать именно составное условие целиком, скобки после `NOT` не просто желательны, а необходимы для корректности запроса — без них `NOT` относился бы только к первому условию, а не ко всей задуманной группе, что мы уже показывали в разделе про `NOT`. Комбинация всех трёх операторов вместе выглядит, например, так — товары, которые **не** являются одновременно дешёвыми (`price <= 500`) и отсутствующими на складе (`stock = 0`):

```sql
SELECT name, price, stock
FROM products
WHERE NOT (price <= 500 AND stock = 0);
```

### Логические операторы и NULL: осторожность с трёхзначной логикой

В одиннадцатом уроке «Основ» мы разбирали, что сравнение с `NULL` даёт не `TRUE`/`FALSE`, а «неизвестно» — и это поведение полностью переносится на `AND`/`OR`/`NOT`. Например, если `category IS NULL` (то есть категория не указана), то условие `category = 'Периферия' AND price > 1000` целиком даёт «неизвестно» (а не `FALSE`), потому что первая часть — «неизвестно», и таким строка не попадёт в результат, даже если цена действительно больше 1000. Единственный надёжный способ включить в фильтр и строки с `NULL` в нужном столбце — явно добавить условие `IS NULL` через `OR`, если это действительно требуется по смыслу задачи:

```sql
SELECT name, category, price
FROM products
WHERE category = 'Периферия' OR category IS NULL;
```

### Резюме

- `AND` — истина только когда истинны **оба** условия одновременно; годится для сужения выборки по нескольким требованиям сразу.
- `OR` — истина, если истинно **хотя бы одно** из условий; расширяет выборку, объединяя альтернативы.
- `NOT` инвертирует результат следующего за ним условия; для «не равно» на практике чаще используют `<>`, а `NOT` раскрывается на составных условиях в скобках.
- `AND` имеет более высокий приоритет, чем `OR`: без скобок он вычисляется первым, что может привести к неожиданному результату, если автор запроса думал иначе.
- **Явные скобки** вокруг логических групп — обязательная практика при смешивании `AND` и `OR` в одном условии: они убирают зависимость от приоритета и делают запрос читаемым без домысливания.
- Присутствие `NULL` в столбце, участвующем в условии, «заражает» результат «неизвестностью» (как и в одиночных сравнениях из одиннадцатого урока «Основ») — если строки с `NULL` должны попасть в выборку, это нужно указать явно через `IS NULL`.

## Теоретические задания

### Вопрос 1: В таблице `products` три товара: «Монитор 27"» (категория «Мониторы», 15990.00), «Монитор 24"» («Мониторы», 8990.00) и «Ноутбук» («Ноутбуки», 79990.00). Какие строки вернёт запрос `WHERE category = 'Мониторы' AND price > 10000`?

- ✅ только «Монитор 27"»
<!-- AND пропускает строку, лишь когда истинны оба условия одновременно -->
- ❌ оба монитора — error_text: такой результат дал бы OR — «хотя бы одно из условий»; AND требует истинности обоих, и «Монитор 24"» за 8990.00 проваливает проверку цены (сравнения — урок 8 «Основы», их комбинация — этот урок).
- ❌ «Монитор 27"» и «Ноутбук» — error_text: ноутбук проходит проверку цены, но не проходит проверку категории — этот ответ получился бы применением только условия `price > 10000`; AND не позволяет засчитать строку по одному из двух условий.
- ❌ все три товара — error_text: все три строки вернул бы OR: «Монитор 24"» проходит по категории, «Ноутбук» — по цене; AND отбрасывает каждого из них, потому что вторая часть условия ложна.

### Вопрос 2: Как MySQL прочитает условие `WHERE category = 'Аксессуары' AND price < 500 OR stock = 0` без скобок?

- ✅ `(category = 'Аксессуары' AND price < 500) OR stock = 0`
<!-- у AND приоритет выше, чем у OR: он «связывает» операнды крепче и вычисляется первым -->
- ❌ `category = 'Аксессуары' AND (price < 500 OR stock = 0)` — error_text: так было бы, если бы OR связывал крепче AND; в SQL приоритет AND выше, поэтому сначала вычисляется он; чтобы получить такую группировку, скобки нужно расставить явно.
- ❌ сервер вернёт ошибку: смешивать AND и OR без скобок запрещено — error_text: скобки — обязательная практика читаемости, но не требование синтаксиса; запрос исполнится — просто по правилу «AND первым», и при другой задумке автора молча вернёт не те строки.
- ❌ условия проверяются в порядке написания, и результат зависит от того, какое условие стоит первым — error_text: порядок написания частей условия на вычисление не влияет: у СУБД есть фиксированный приоритет NOT → AND → OR, и она группирует операнды по нему, а не по позиции в строке.

### Вопрос 3: Какое условие равносильно `NOT (price <= 500 AND stock = 0)`?

- ✅ `price > 500 OR stock <> 0`
<!-- NOT (A AND B) = (NOT A) OR (NOT B): отрицание «И» — это «ИЛИ» отрицаний (закон де Моргана) -->
- ❌ `price > 500 AND stock <> 0` — error_text: отрицания верны, но союз нет: NOT (A AND B) равносилен (NOT A) OR (NOT B); вариант с AND строже задуманного — он выкинул бы, например, дешёвый товар, который есть на складе.
- ❌ `price >= 500 OR stock = 0` — error_text: перепутаны знаки сравнений: отрицание `price <= 500` — это строго `price > 500`, а отрицание `stock = 0` — `stock <> 0`; в этом варианте искажены и границы, и направления сравнений.
- ❌ `NOT price <= 500 AND stock = 0` — error_text: без скобок NOT относится только к первому сравнению: получится `(price > 500) AND stock = 0` — «дорогие и отсутствующие», совсем другая выборка; чтобы отрицать составное условие целиком, скобки после NOT обязательны.

### Вопрос 4: В `products` есть строки с `category = NULL`. Запрос `WHERE category = 'Периферия'` их не находит. Как включить эти строки в выборку?

- ✅ добавить `OR category IS NULL`
<!-- NULL проверяется только IS NULL: сравнение = NULL всегда даёт «неизвестно» -->
- ❌ добавить `OR category = NULL` — error_text: сравнение `= NULL` никогда не истинно: для любой строки оно даёт «неизвестно» (урок 11 «Основы»), и покупатели без категории по-прежнему не пройдут; NULL проверяется только конструкцией IS NULL.
- ❌ добавить `AND category IS NULL` — error_text: AND требует истинности обоих условий сразу: категория должна быть одновременно и «Периферией», и NULL — это противоречие, результат окажется пустым.
- ❌ заменить условие на `NOT category <> 'Периферия'` — error_text: двойное отрицание возвращает исходный смысл, но проблема не в знаке: для NULL сравнение `<>` даёт «неизвестно», и NOT от «неизвестно» — по-прежнему «неизвестно», так что строка не пройдёт и здесь.

### Вопрос 5: Нужны товары: ноутбуки дешевле 60000 ИЛИ планшеты, которые есть на складе. Какое условие `WHERE` верно?

- ✅ `(category = 'Ноутбуки' AND price < 60000) OR (category = 'Планшеты' AND stock > 0)`
<!-- две AND-группы, соединённые OR; скобки фиксируют структуру условия -->
- ❌ `(category = 'Ноутбуки' OR category = 'Планшеты') AND (price < 60000 OR stock > 0)` — error_text: другое условие: сюда просочатся «смешанные» комбинации, которые задуманное условие отбрасывает, — например, дорогой ноутбук, который есть на складе, или дешёвый планшет с нулевым остатком.
- ❌ `category = 'Ноутбуки' AND (price < 60000 OR category = 'Планшеты' AND stock > 0)` — error_text: скобка перекрыла только часть условия: первая группа «ноутбуки дешевле 60000» потерялась, планшеты попали внутрь условия про ноутбуки — при `category = 'Ноутбуки' AND ...` планшеты не пройдут вовсе; структура «две группы через OR» разрушена.
- ❌ `category = 'Ноутбуки' AND price < 60000 AND category = 'Планшеты' AND stock > 0` — error_text: вместо союза OR использован AND: категория не может одновременно равняться двум разным значениям — условие противоречиво, и запрос не вернёт ни одной строки.

### Задание 2: Постоянные покупатели

Две группы условий, соединённые OR; каждая группа защищена скобками.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT name, city, bonus, orders_cnt FROM customers WHERE (city = 'Москва' AND bonus >= 500) OR orders_cnt >= 10 ORDER BY name; -->

колонки `name`, `city`, `bonus`, `orders_cnt` для постоянных

### Задание 3: Не столичные покупатели

NOT над составным условием в скобках и поведение строки с NULL.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT name, city FROM customers WHERE NOT (city = 'Москва' OR city = 'Санкт-Петербург') ORDER BY name; -->

**statement:**

Таблица `customers` содержит восемь покупателей; столбец `city` допускает
NULL — у одного покупателя город не указан. Выведите покупателей, которые
живут НЕ в Москве и НЕ в Санкт-Петербурге: колонки `name`, `city`. Строки
отсортируйте по имени. Покупатель без указанного города в выборку попасть
не должен.

**expected_result_text:**

Финальный SELECT возвращает четыре строки. Анна, Мария и Пётр отсеяны
условием в скобках. Ольга Смирнова с `city = NULL` исчезает из результата:
сравнение даёт «неизвестно», и NOT от «неизвестно» — по-прежнему
«неизвестно»; чтобы включить её, потребовалось бы явное `OR city IS NULL`.

**seed_sql:**

```sql
CREATE TABLE customers (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    city VARCHAR(50) NULL
);

INSERT INTO customers (name, city) VALUES

    ('Игорь Морозов', 'Екатеринбург'),
    ('Пётр Соколов', 'Москва'),
    ('Елена Новикова', 'Тверь');
```

**expected_rows:**

| name            | city          |
| --------------- | ------------- |
| Дмитрий Козлов  | Воронеж       |
| Елена Новикова  | Тверь         |
| Иван Сидоров    | Казань        |
| Игорь Морозов   | Екатеринбург  |
