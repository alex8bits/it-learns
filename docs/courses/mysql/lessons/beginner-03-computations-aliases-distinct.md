## Материал

До сих пор в списке `SELECT` мы перечисляли только имена существующих столбцов — `SELECT name, price FROM products`. Но список после `SELECT` на самом деле не ограничен именами столбцов: туда можно поставить **любое выражение**, которое СУБД умеет вычислить, — арифметику, склейку текста, результат функции. Каждое такое выражение вычисляется отдельно для каждой строки результата, и ему можно дать удобное имя — псевдоним. В этом уроке разберём вычисления в `SELECT`, псевдонимы `AS` и оператор `DISTINCT`, убирающий повторяющиеся строки из результата.

### Вычисления в SELECT: арифметика прямо в запросе

Список `SELECT` — это не просто перечисление того, что «уже лежит» в таблице, а описание того, что должно оказаться в **результирующей** таблице, а результирующие столбцы могут быть вычисленными на лету. Например, посчитаем для каждого товара стоимость всей партии на складе — цена умножить на количество:

```sql
SELECT name, price, stock, price * stock
FROM products;
```

СУБД вычислит выражение `price * stock` отдельно для каждой строки таблицы `products` и добавит результат как дополнительный столбец. Доступны все привычные арифметические операции: `+`, `-`, `*`, `/`, а также `%` (остаток от деления). Выражения можно комбинировать и группировать скобками, как в обычной математике:

```sql
SELECT name, price, (price * 1.20) AS price_with_vat
FROM products;
```

Здесь мы прибавили 20% к цене — например, для демонстрации цены с учётом гипотетического налога. Важная деталь про деление: если оба операнда — целые числа (тип `INT`), результат деления `/` в MySQL всё равно окажется **дробным** (в отличие от некоторых языков программирования, где целочисленное деление отбрасывает остаток) — MySQL автоматически подбирает достаточно точный числовой тип для результата. А вот деление на `0` — не ошибка выполнения, а `NULL` (это мы уже видели в одиннадцатом уроке «Основ» в контексте `NULLIF`).

Вычисления можно свободно комбинировать со столбцами из таблицы в одном списке `SELECT`, и в самих условиях `WHERE` их тоже можно использовать напрямую:

```sql
SELECT name, price, stock
FROM products
WHERE price * stock > 50000;
```

### Псевдонимы: AS даёт вычисленному столбцу имя

У вычисленного столбца без псевдонима MySQL сама генерирует техническое имя (обычно это буквальный текст выражения), что неудобно читать и практически невозможно использовать дальше. Псевдоним (alias) задаётся ключевым словом `AS` сразу после выражения и даёт столбцу человекочитаемое имя:

```sql
SELECT name, price, stock, price * stock AS total_value
FROM products;
```

Теперь в результирующей таблице столбец называется `total_value`, а не техническим отображением выражения. Псевдонимы полезны не только для вычислений — их можно давать и обычным столбцам, например, для перевода технических имён в человекочитаемые заголовки отчёта:

```sql
SELECT name AS product_name, price AS product_price
FROM products;
```

Ключевое слово `AS` в MySQL необязательно — псевдоним можно указать и просто через пробел (`price * stock total_value`), но явное `AS` считается более читаемым стилем и рекомендуется как принятая практика: он сразу сигнализирует любому читающему запрос, что перед ним — переименование, а не опечатка или отсутствующая запятая. Если желаемое имя псевдонима содержит пробелы или совпадает со служебным словом SQL, его нужно взять в обратные кавычки (backticks):

```sql
SELECT name, price * stock AS `Общая стоимость`
FROM products;
```

Важный практический нюанс, который стоит запомнить надолго: псевдоним, заданный в `SELECT`, **недоступен** в условии `WHERE` того же запроса — например, `WHERE total_value > 50000` работать не будет, если `total_value` определён через `AS` в том же `SELECT`. Причина в порядке, в котором СУБД фактически обрабатывает запрос: `WHERE` вычисляется раньше, чем формируется итоговый список `SELECT` с его псевдонимами — подробно про эту последовательность обработки мы поговорим в одном из следующих уроков; сейчас достаточно запомнить практическое правило: в `WHERE` условие нужно писать через исходное выражение целиком (`price * stock > 50000`), а не через псевдоним, который для `WHERE` пока не существует.

### Конкатенация: склейка текста в один столбец

Часто нужно объединить несколько текстовых столбцов в одну строку — например, собрать полное отображаемое название товара из категории и имени. В MySQL для этого служит функция `CONCAT`, принимающая произвольное число аргументов и склеивающая их в одну строку:

```sql
SELECT CONCAT(category, ': ', name) AS full_title
FROM products;
```

Для товара с `category = 'Периферия'` и `name = 'Мышь беспроводная'` результат будет `'Периферия: Мышь беспроводная'`. `CONCAT` принимает любое количество аргументов и умеет автоматически преобразовывать нетекстовые значения (числа) к тексту при склейке:

```sql
SELECT CONCAT(name, ' — ', price, ' руб.') AS price_label
FROM products;
```

Отдельное важное поведение `CONCAT` касается `NULL`: если **хотя бы один** из аргументов — `NULL`, результатом всей склейки становится `NULL` целиком, а не строка с пропущенным фрагментом. Это логично с точки зрения трёхзначной логики, знакомой нам из урока про `NULL`: «неизвестное значение», склеенное с чем угодно, по-прежнему остаётся неизвестным целиком. Например, если у товара `sku` — `NULL`, то `CONCAT(name, ' (', sku, ')')` вернёт `NULL`, а не `'Мышь беспроводная ()'`. Если это нежелательно, на помощь приходит уже знакомый нам `COALESCE` из одиннадцатого урока «Основ» — подставим заглушку перед склейкой:

```sql
SELECT CONCAT(name, ' (', COALESCE(sku, 'без артикула'), ')') AS label
FROM products;
```

### DISTINCT: убрать повторяющиеся строки из результата

Оператор `DISTINCT`, указанный сразу после `SELECT`, убирает из результирующей таблицы повторяющиеся строки, оставляя только уникальные комбинации значений выбранных столбцов. Найдём все **уникальные** категории товаров, встречающиеся в таблице:

```sql
SELECT DISTINCT category
FROM products;
```

Без `DISTINCT` этот запрос вернул бы категорию каждого товара — то есть, скорее всего, одна и та же категория повторилась бы много раз (по одному разу на каждый товар этой категории). `DISTINCT` схлопывает такие повторы, оставляя каждое уникальное значение ровно один раз.

Важный нюанс: `DISTINCT` относится **не к одному столбцу**, а ко всей строке результата целиком, если в `SELECT` указано несколько столбцов — уникальность проверяется по **сочетанию** всех выбранных столбцов сразу, а не по каждому отдельно:

```sql
SELECT DISTINCT category, price
FROM products;
```

Этот запрос вернёт каждую уникальную **пару** «категория + цена» — то есть если в категории «Периферия» есть два разных товара по одной и той же цене 1200 рублей, в результате эта пара `('Периферия', 1200)` встретится только один раз, но если у товаров той же категории цены разные, каждая уникальная пара останется в результате отдельной строкой.

Ещё один нюанс, вытекающий из общей логики `NULL`: с точки зрения `DISTINCT` два значения `NULL` считаются **одинаковыми** (хотя формально, как мы помним, `NULL = NULL` даёт «неизвестно», а не `TRUE`) — это специальное практическое правило именно для `DISTINCT`, `GROUP BY` и подобных операций группировки: несколько строк с `NULL` в одном и том же месте схлопнутся в одну строку с `NULL`, а не останутся отдельными строками, как если бы `NULL` считался «непохожим на самого себя».

`DISTINCT` можно сочетать с вычислениями и `CONCAT` из этого же урока:

```sql
SELECT DISTINCT CONCAT(category, ' — ', ROUND(price / 1000), 'к') AS price_bucket
FROM products;
```

### Резюме

- Список `SELECT` может содержать не только имена столбцов, но и произвольные вычисляемые выражения (арифметика `+ - * /`, функции) — они считаются отдельно для каждой строки.
- Псевдоним `AS` даёт вычисленному (или обычному) столбцу читаемое имя в результате; при пробелах или совпадении со служебными словами имя берётся в обратные кавычки.
- Псевдоним из `SELECT` недоступен в `WHERE` того же запроса — там нужно использовать исходное выражение целиком (причина — в порядке обработки запроса, детали — в одном из следующих уроков).
- `CONCAT(a, b, ...)` склеивает текстовые (и автоматически преобразованные числовые) значения в одну строку; если хоть один аргумент — `NULL`, результат всей склейки — `NULL`; для защиты используют `COALESCE`.
- `DISTINCT` убирает повторяющиеся строки результата, где уникальность определяется по **сочетанию всех** выбранных столбцов, а не по каждому отдельно; для `DISTINCT` два `NULL` считаются одинаковыми.

## Теоретические задания

### Вопрос 1: Запрос `SELECT name, price * stock AS total FROM products WHERE total > 50000`. Что произойдёт при его выполнении?

- ✅ ошибка: псевдоним total на момент вычисления WHERE ещё не существует — условие придётся писать через `price * stock > 50000`
<!-- WHERE обрабатывается раньше SELECT; подробный разбор порядка — в уроке 6 «Начинающего» -->
- ❌ запрос вернёт строки, в которых цена × остаток больше 50000 — error_text: для этого WHERE должен «видеть» имя total, но псевдонимы из списка SELECT в WHERE недоступны: сервер откажется выполнять запрос, пожаловавшись на неизвестный столбец.
- ❌ запрос вернёт пустой результат — error_text: пустой результат был бы, если бы условие вычислилось и не нашлось ни одной подходящей строки; здесь условие невозможно даже вычислить — имя столбца неизвестно, и это ошибка, а не «ноль строк».
- ❌ запрос сработает, если написать псевдоним в обратных кавычках: AS `` `total` `` — error_text: обратные кавычки нужны для имён с пробелами и служебных слов; на момент появления псевдонима они не влияют — алиас рождается в SELECT, а WHERE обрабатывается раньше.

### Вопрос 2: У товара `name = 'Мышь беспроводная'`, а `note = NULL`. Что вернёт `CONCAT(name, ' (', note, ')')`?

- ✅ NULL
<!-- NULL в любом аргументе «заражает» всю склейку -->
- ❌ строку «Мышь беспроводная ()» — error_text: так вело бы себя склеивание, которое молча пропускает отсутствующий фрагмент; CONCAT так не работает: если хотя бы один аргумент NULL, результат всей операции — NULL целиком; пустая строка '' дала бы такой ответ, а NULL — нет (урок 11 «Основы»).
- ❌ строку «Мышь беспроводная (NULL)» — error_text: NULL не преобразуется в текст «NULL»: это не значение, а маркировка «значения нет»; перед склейкой его заменяют заглушкой — COALESCE(note, 'примечания нет').
- ❌ ошибку — error_text: CONCAT с NULL-аргументом синтаксически законен и ошибки не порождает; результатом будет NULL.

### Вопрос 3: В таблице шесть строк с парами («категория», «цена»): («Периферия», 1200) — дважды, («Периферия», 1500), («Мониторы», 1200) — дважды, («Мониторы», 1500). Сколько строк вернёт `SELECT DISTINCT category, price`?

- ✅ 4
<!-- уникальность проверяется по сочетанию всех столбцов результата -->
- ❌ 6 — error_text: повторы схлопываются: пара («Периферия», 1200) встречается дважды, и в DISTINCT она останется один раз — то же с («Мониторы», 1200); DISTINCT убирает полностью совпадающие строки результата.
- ❌ 2 — error_text: столько уникальных значений у каждого столбца по отдельности, но DISTINCT применяется не к столбцам раздельно: («Периферия», 1200) и («Мониторы», 1200) — разные строки результата и обе остаются.
- ❌ ошибку: DISTINCT работает только с одним столбцом — error_text: DISTINCT разрешён при любом числе столбцов; правило другое — уникальность проверяется по всей строке, по сочетанию всех перечисленных столбцов сразу.

### Вопрос 4: Что вернёт `SELECT 7 / 2`?

- ✅ 3.5 — деление целых чисел в MySQL всё равно даёт дробный результат
<!-- MySQL сам подбирает достаточно точный тип для результата деления -->
- ❌ 3 — error_text: так работает целочисленное деление во многих языках программирования: остаток отбрасывается; в MySQL оператор `/` дробную часть сохраняет — усечение до целого здесь не происходит.
- ❌ 4 — error_text: деление не округляет результат: 3.5 превратилось бы в 4 только отдельной операцией округления, а само по себе деление её не выполняет.
- ❌ NULL — error_text: NULL при делении появляется только в одном случае — деление на ноль (урок 11 «Основы»); здесь оба операнда — ненулевые целые числа.

### Вопрос 5: В столбце `category` значения: NULL, NULL, 'Мыши', 'Клавиатуры'. Сколько строк вернёт `SELECT DISTINCT category`?

- ✅ 3
<!-- для DISTINCT два NULL считаются одинаковыми и схлопываются в одну строку -->
- ❌ 4 — error_text: в сравнениях NULL не равен даже NULL (урок 11 «Основы»), но у DISTINCT специальное практическое правило: строки с NULL в одном и том же месте считаются одинаковыми и схлопываются в одну строку.
- ❌ 2 — error_text: это подсчёт непустых значений — «Мыши» и «Клавиатуры»; NULL-строки не исчезают из результата: обе строки с NULL сворачиваются в одну и остаются наряду с двумя значениями.
- ❌ ошибку — error_text: DISTINCT нормально работает со строками, где встречается NULL: повторы NULL убираются так же, как повторы обычных значений, ошибки нет.

### Задание 3: Направления доставки
