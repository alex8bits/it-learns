# Что такое БД и СУБД: таблицы, строки, столбцы; где применяется

## Материал

Любая программа, которой есть что запомнить, сталкивается с одной и той же задачей: данные нужно где-то хранить так, чтобы их можно было надёжно найти, изменить и не потерять при перезагрузке компьютера. Список покупок, каталог интернет-магазина, список пользователей мессенджера, история платежей — всё это данные, которые должны переживать перезапуск программы и оставаться доступными для множества процессов одновременно. Именно для решения этой задачи существуют базы данных.

### База данных против файла на диске

Первое, что приходит в голову начинающему разработчику: «а почему не сохранить всё в обычный файл — текстовый или в формате JSON?» Для очень маленьких задач это действительно работает. Но как только данных становится много и с ними нужно работать одновременно нескольким пользователям или процессам, у файлового подхода проявляются серьёзные проблемы:

- **Поиск.** Чтобы найти в текстовом файле строку по условию (например, «все заказы клиента с id = 42»), программе придётся прочитать файл целиком и вручную разобрать каждую строку. Если файл весит гигабайты, такой поиск становится медленным.
- **Одновременный доступ.** Если два процесса одновременно попытаются дописать что-то в конец одного и того же файла, часть данных может быть повреждена или потеряна — файловая система не умеет разруливать такие конфликты сама.
- **Целостность.** Ничто не мешает записать в файл заказ, у которого customer_id ссылается на клиента, которого на самом деле не существует, или число вместо даты. Проверка корректности данных целиком лежит на плечах программиста, и любая ошибка в коде разрушает данные незаметно.
- **Структура и связи.** Данные редко существуют сами по себе: заказ связан с клиентом, товар — с категорией. Описать и поддерживать такие связи в плоском файле неудобно и ненадёжно.

**База данных (БД)** — это организованный набор данных, спроектированный для эффективного хранения, поиска и изменения информации, а также для поддержания её целостности при одновременной работе многих пользователей. Слово «организованный» здесь ключевое: данные в базе данных не сложены в кучу, а разложены по строгой структуре, которая делает поиск и изменение быстрыми и предсказуемыми.

### Что делает СУБД

Сама база данных — это, по сути, файлы на диске, где хранятся данные и вспомогательные структуры для быстрого поиска. Но работать с этими файлами напрямую неудобно и рискованно: один незаметный баг в коде может испортить весь файл. Поэтому между приложением и физическими файлами данных стоит специальная программа — **система управления базами данных (СУБД, англ. DBMS — Database Management System)**.

СУБД — это программное обеспечение, которое:

- принимает запросы от других программ (обычно на языке SQL — про него отдельно ниже) и выполняет их над данными;
- следит за тем, чтобы данные оставались согласованными, даже если несколько пользователей одновременно читают и изменяют одни и те же строки;
- сама решает, как эффективнее найти нужные данные на диске — с помощью внутренних структур, о которых прикладному разработчику в большинстве случаев не нужно думать;
- защищает данные: определяет, кто и что может делать с базой, ведёт журналы изменений для восстановления после сбоя.

MySQL — это именно СУБД: программа, которая работает как отдельный процесс (обычно называемый сервером, `mysqld`) и обслуживает запросы клиентов. Важно различать «базу данных» (сами данные) и «СУБД» (программу, которая ими управляет) — это разные понятия, хотя в разговорной речи их иногда путают. Когда говорят «у нас MySQL», как правило имеют в виду и то и другое: сервер MySQL, который хранит и обслуживает конкретные базы данных.

Кроме MySQL существуют и другие популярные СУБД: PostgreSQL, Microsoft SQL Server, Oracle Database, SQLite. Все они реализуют похожую модель хранения данных и общий язык запросов SQL (с некоторыми различиями в деталях синтаксиса), но отличаются внутренним устройством, производительностью в разных сценариях, лицензией и набором дополнительных возможностей. Освоив принципы работы с одной реляционной СУБД, вы без больших усилий разберётесь и в других — базовые идеи (таблицы, строки, столбцы, SQL) одинаковы для всех.

### Реляционная модель: таблицы, строки, столбцы

MySQL относится к классу **реляционных** СУБД (от англ. relation — «отношение», в математическом смысле таблица данных). В реляционной модели вся информация представляется в виде **таблиц** — двумерных структур, похожих на лист в Excel, но с более строгими правилами.

Возьмём для примера таблицу товаров интернет-магазина `products`:

| id | name | price | stock |
|----|------|-------|-------|
| 1 | Клавиатура механическая | 4500.00 | 12 |
| 2 | Мышь беспроводная | 1200.00 | 30 |
| 3 | Монитор 27" | 21000.00 | 5 |

У этой таблицы есть строгая структура:

- **Столбец (column, поле)** — это именованная характеристика, общая для всех записей таблицы. В нашем примере столбцы — `id`, `name`, `price`, `stock`. У каждого столбца заранее определён тип данных: например, `price` хранит числа с копейками, а `name` — текст. Набор столбцов и их типов называется **схемой** таблицы, и он одинаков для всех строк: нельзя, чтобы у одного товара было поле `price`, а у другого — не было.
- **Строка (row, запись)** — это одна конкретная запись, то есть один товар с конкретными значениями всех столбцов. В таблице выше три строки — три товара.
- **Ячейка** — значение конкретного столбца в конкретной строке, например, `4500.00` — это значение столбца `price` в строке товара с `id = 1`.

Такая табличная структура — не просто удобный способ визуализации. Она позволяет СУБД применять строгие правила: столбец `price` можно ограничить так, чтобы туда невозможно было записать текст вместо числа; столбец `stock` можно запретить оставлять пустым. Про такие ограничения (constraints) мы подробно поговорим в одном из следующих уроков — пока достаточно понимать, что строгая структура таблицы — это основа, на которой держится надёжность данных.

### Почему «реляционная»: несколько таблиц и связи между ними

Настоящая база данных почти никогда не состоит из одной таблицы. У интернет-магазина, например, отдельно хранятся товары, отдельно — категории, отдельно — клиенты, отдельно — заказы. Каждая такая сущность — своя таблица, а между таблицами существуют **связи** (relations): заказ связан с клиентом, который его сделал; товар связан с категорией, к которой он относится.

Например, в таблице заказов `orders` может быть столбец `customer_id`, значение которого указывает на конкретную строку в таблице `customers`. Так одна таблица «ссылается» на другую, и данные не дублируются: имя клиента хранится один раз, в таблице `customers`, а не переписывается заново в каждый его заказ. Про то, как именно устроены такие связи и как получать данные сразу из нескольких таблиц, вы узнаете позже — в этом уроке важно только сформировать общую картину: реляционная база данных — это набор взаимосвязанных таблиц, а не одна большая таблица со всем на свете.

### Таблицы, строки и столбцы в терминах теории множеств

В более формальном изложении таблицу называют **отношением** (relation), строку — **кортежем** (tuple), а столбец — **атрибутом** (attribute). Эти термины вы можете встретить в академической литературе или документации; в повседневной практике и в этом курсе мы будем использовать более привычные слова «таблица», «строка», «столбец», но полезно знать, что это ровно те же понятия, просто выраженные другим языком.

### Как получить данные из таблицы: язык SQL

Чтобы прочитать или изменить данные в таблице, приложение не работает с файлами напрямую — оно посылает СУБД команду на специальном языке запросов. Для реляционных СУБД, включая MySQL, этим языком служит **SQL** (Structured Query Language — «язык структурированных запросов»). SQL — декларативный язык: вы описываете, *какие* данные хотите получить, а не *как* именно их искать на диске — эту работу берёт на себя СУБД.

Самая частая операция — чтение данных — выполняется командой `SELECT`. Вот простейший пример: получить названия и цены всех товаров из таблицы `products`:

```sql
SELECT name, price
FROM products;
```

Результатом будет таблица из двух столбцов — `name` и `price` — и трёх строк (по числу товаров в нашем примере):

| name | price |
|------|-------|
| Клавиатура механическая | 4500.00 |
| Мышь беспроводная | 1200.00 |
| Монитор 27" | 21000.00 |

Обратите внимание: результат `SELECT` — это тоже таблица, даже если в исходной таблице были другие столбцы, которые мы не запросили (в данном случае мы не взяли `id` и `stock`). Именно эта возможность — выбрать ровно те столбцы, которые нужны, а не всю таблицу целиком, — один из первых практических навыков работы с SQL. Подробно про синтаксис, регистр ключевых слов и форматирование запросов мы поговорим в следующем уроке; здесь важно увидеть общую идею: запрос описывает *что* нужно получить, а результат — это новая таблица, построенная на основе данных исходной.

### Где применяются базы данных

Базы данных — не узкоспециализированный инструмент для «айтишников», а фундамент практически любого современного цифрового продукта:

- **Интернет-магазины** хранят каталог товаров, заказы, клиентов, платежи — именно такой пример мы будем использовать на протяжении всего курса.
- **Банковские системы** хранят счета, операции, историю транзакций — здесь особенно критична надёжность и целостность данных (об этом — в теме транзакций на более продвинутом уровне курса).
- **Социальные сети и мессенджеры** хранят пользователей, сообщения, связи «кто с кем дружит» — типичный пример сущностей со сложными связями.
- **Корпоративные системы** — учёт сотрудников, склад, бухгалтерия, CRM — практически любая программа, которая ведёт учёт чего-либо, использует базу данных под капотом.
- **Аналитика и отчётность** — данные из баз данных обрабатываются, агрегируются и превращаются в дашборды и отчёты для принятия решений.

Даже если конечный пользователь никогда не видит слова «SQL» или «MySQL», за кнопкой «Оформить заказ» или «Отправить сообщение» почти всегда стоит запрос к базе данных, который читает или записывает строку в одной или нескольких таблицах.

### Резюме

- **База данных** — организованный набор данных для надёжного хранения, поиска и изменения информации, в отличие от плоских файлов устойчива к одновременному доступу многих пользователей и поддерживает целостность данных.
- **СУБД** (например, MySQL) — программа, которая управляет базами данных: принимает запросы, следит за целостностью и параллельным доступом, отвечает за физическое хранение данных на диске.
- MySQL — **реляционная** СУБД: данные организованы в виде **таблиц**, состоящих из **строк** (записей) и **столбцов** (именованных характеристик с фиксированным типом данных для всех строк).
- Реальная база данных обычно состоит из нескольких связанных таблиц, а не одной большой таблицы — связи между таблицами позволяют не дублировать данные.
- Для чтения и изменения данных используется язык **SQL**; базовая команда для чтения данных — `SELECT столбцы FROM таблица`, результат которой — тоже таблица.
- Базы данных лежат в основе практически любого цифрового продукта: от интернет-магазинов до банковских систем и мессенджеров.

## Теоретические задания

### Вопрос 1: Чем база данных отличается от СУБД?

- ✅ база данных — сами организованные данные, а СУБД — программа, которая ими управляет: принимает запросы, следит за целостностью и хранением
- ❌ СУБД — это хранилище данных, а база данных — программа для работы с ними — error_text: понятия переставлены местами: программой является именно СУБД (например, MySQL), а база данных — сами данные, разложенные по строгой структуре таблиц.
- ❌ это два названия одной и той же программы — error_text: СУБД — программа, база данных — данные, которыми она управляет. В разговорной речи их иногда путают, но у этих понятий разная ответственность.

### Вопрос 2: Что такое строка таблицы в реляционной базе данных?

- ✅ одна конкретная запись — например, один товар со значениями всех столбцов таблицы
- ❌ именованная характеристика, общая для всех записей таблицы — error_text: это определение столбца: столбец — характеристика (название, цена), а строка — один конкретный объект со значениями всех столбцов сразу.
- ❌ значение конкретного столбца в конкретной строке — error_text: это ячейка — пересечение одного столбца и одной строки. Строка же содержит значения всех столбцов таблицы.

### Вопрос 3: Что называют схемой таблицы?

- ✅ набор столбцов и их типов, одинаковый для всех строк таблицы
- ❌ перечень связей таблицы с другими таблицами базы — error_text: связи между таблицами — отдельное понятие реляционной модели; схема же описывает устройство самой таблицы: какие у неё столбцы и какого они типа.
- ❌ количество строк таблицы и их текущий порядок — error_text: строки появляются и удаляются, а схема фиксирована: набор столбцов и их типов одинаков для всех строк и не зависит от того, сколько строк в таблице сейчас.

### Вопрос 4: Зачем в строке заказа хранить `customer_id` — номер клиента, — а не копировать имя и город клиента в каждый его заказ?

- ✅ чтобы не дублировать данные: имя клиента хранится один раз в таблице клиентов, а заказ лишь ссылается на её строку
- ❌ чтобы таблица заказов занимала меньше места: короткое число вместо длинного текста — error_text: экономия места — лишь побочный эффект. Главное — единая копия данных: иначе при смене имени клиента пришлось бы править все его заказы, и копии легко разошлись бы между собой.
- ❌ потому что в таблице заказов разрешены только числовые столбцы — error_text: тип каждого столбца выбирается свободно, и текст в таблице заказов встречаться может. Причина ссылки на клиента по номеру — недопущение дублирования данных, а не запрет на текстовые столбцы.

### Вопрос 5: Что вернёт запрос `SELECT name, price FROM products;`?

- ✅ таблицу из двух столбцов — `name` и `price` — со всеми строками таблицы `products`
- ❌ таблицу со всеми столбцами `products`, включая `id` и `stock` — error_text: SELECT возвращает ровно те столбцы, которые перечислены после него; остальные столбцы исходной таблицы в результат не попадают.
- ❌ одну строку — name и price первого товара — error_text: без ограничений запрос возвращает все строки исходной таблицы: по одной на каждый товар, а не только первый.

### Задание 1: Названия и цены товаров

Первый SELECT курса: выбор заданных столбцов из готовой таблицы.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT name, price FROM products; -->

**statement:**

В таблице `products` интернет-магазина хранятся товары: `id`, `name`,
`price`, `stock`. Выведите список всех товаров — столбцы `name` и `price`,
в этом порядке.

**expected_result_text:**

```sql
CREATE TABLE products (
    id INT NOT NULL,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2) NOT NULL,
    stock INT NOT NULL
);

INSERT INTO products (id, name, price, stock) VALUES
    (1, 'Наушники накладные', 3490.00, 18),
    (2, 'Флеш-накопитель 64 ГБ', 790.00, 55),
    (3, 'Роутер Wi-Fi 6', 5990.00, 7),
    (4, 'Веб-камера 1080p', 2790.00, 25),
    (5, 'USB-удлинитель 3 метра', 450.00, 40);
```

**expected_rows:**

| name                   | price   |

| Роутер Wi-Fi 6         | 5990.00 |

### Задание 2: Кто наши покупатели

Комбинация из трёх столбцов готовой таблицы.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT name, city, email FROM customers; -->

**statement:**

Таблица `customers` хранит покупателей: `id`, `name`, `city`, `email`.
Выведите каждого покупателя тремя столбцами — `name`, `city`, `email`,
