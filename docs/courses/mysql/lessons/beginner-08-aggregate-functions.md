## Материал

Все функции, которые мы изучали до сих пор — `UPPER`, `ROUND`, `CASE` и другие, — вычисляют результат **для каждой строки отдельно**: одна строка на входе, одно значение на выходе. В этом уроке мы знакомимся с принципиально другим классом функций — **агрегатными**: они принимают на входе **множество строк** (весь результат запроса или, как мы увидим в следующем уроке, отдельную группу строк) и возвращают **одно** итоговое значение — сумму, среднее, количество, минимум или максимум. Это фундаментальный переход от «посмотреть на каждую строку» к «посчитать статистику по набору строк», лежащий в основе практически всей аналитики и отчётности.

### COUNT: подсчёт строк

Функция `COUNT` считает количество строк. У неё есть две принципиально разные формы записи с разным поведением.

`COUNT(*)` считает **все** строки в результате, независимо от того, есть ли в них `NULL` в каком-либо столбце:

```sql
SELECT COUNT(*) AS total_products
FROM products;
```

Этот запрос вернёт одну строку с одним числом — общее количество товаров в таблице.

`COUNT(имя_столбца)` считает только строки, где значение **этого конкретного столбца не `NULL`** — строки с `NULL` в указанном столбце в подсчёт не попадают:

```sql
SELECT COUNT(sku) AS products_with_sku
FROM products;
```

Если у части товаров `sku` — `NULL` (артикул не назначен, как мы видели в примерах одиннадцатого урока «Основ»), `COUNT(sku)` посчитает только те товары, у которых артикул реально указан, — и это число будет **меньше**, чем `COUNT(*)` по той же таблице. Разница между `COUNT(*)` и `COUNT(sku)` — это, по сути, готовый и очень частый на практике способ узнать, у скольких строк отсутствует значение в конкретном столбце, без явного `WHERE sku IS NULL`:

```sql
SELECT COUNT(*) AS total, COUNT(sku) AS with_sku
FROM products;
-- разница total - with_sku = количество товаров без sku
```

Есть и `COUNT(DISTINCT столбец)` — считает количество **уникальных** не-`NULL` значений столбца, а не всех строк подряд:

```sql
SELECT COUNT(DISTINCT category) AS unique_categories
FROM products;
```

Это вернёт число уникальных категорий, встречающихся в таблице, даже если у многих товаров категории повторяются.

### SUM: сумма значений столбца

Функция `SUM` складывает все значения указанного числового столбца по всем строкам:

```sql
SELECT SUM(price * stock) AS total_inventory_value
FROM products;
```

Здесь мы сначала вычисляем стоимость партии для каждого товара (`price * stock`, знакомое выражение из третьего урока), а затем складываем эти значения по всем товарам — получаем общую стоимость всего складского запаса одним числом.

### AVG: среднее значение

Функция `AVG` вычисляет среднее арифметическое значений столбца по всем строкам:

```sql
SELECT AVG(price) AS average_price
FROM products;
```

`AVG` эквивалентна (хотя и вычисляется эффективнее) делению `SUM(столбец)` на `COUNT(столбец)` — то есть сумме всех значений, поделённой на их количество, с уже знакомым нам поведением: если в столбце есть `NULL`, эти строки просто не участвуют ни в сумме, ни в количестве (подробнее — в разделе про `NULL` ниже).

### MIN и MAX: минимальное и максимальное значение

`MIN` и `MAX` возвращают наименьшее и наибольшее значение столбца соответственно:

```sql
SELECT MIN(price) AS cheapest, MAX(price) AS most_expensive
FROM products;
```

Важно, что `MIN`/`MAX` работают не только с числами — они применимы и к текстовым столбцам (в этом случае сравнение идёт по правилам сортировки текста, как в `ORDER BY`), и к датам (сравнение по хронологии):

```sql
SELECT MIN(registered_at) AS earliest_registration, MAX(registered_at) AS latest_registration
FROM customers;
```

```sql
SELECT MIN(name) AS first_alphabetically
FROM products;
```

### Несколько агрегатов в одном запросе

Все перечисленные функции свободно комбинируются в одном списке `SELECT`, каждая вычисляется независимо по всему набору строк, а результатом всё равно оказывается **одна** строка с несколькими итоговыми значениями:

```sql
SELECT
    COUNT(*) AS total_products,
    SUM(stock) AS total_stock,
    ROUND(AVG(price), 2) AS average_price,
    MIN(price) AS min_price,
    MAX(price) AS max_price
FROM products;
```

Обратите внимание, что `ROUND` из пятого урока применён прямо к результату `AVG` — агрегатные функции возвращают обычное значение, к которому можно применять другие функции точно так же, как к значению любого столбца.

### Агрегаты можно сочетать с WHERE

`WHERE` полностью совместим с агрегатными функциями — фильтрация происходит **до** агрегирования (что напрямую следует из логического порядка выполнения, разобранного в шестом уроке: `WHERE` — шаг 2, а вычисление `SELECT`, включая агрегаты, — шаг 5, позже). Например, посчитаем среднюю цену только по товарам, которые есть в наличии:

```sql
SELECT AVG(price) AS average_price_in_stock
FROM products
WHERE stock > 0;
```

Строки, отфильтрованные `WHERE` (товары с `stock = 0`), не участвуют в вычислении `AVG` вообще — они просто исключены из набора данных раньше, чем агрегатная функция успевает их увидеть.

### Важный нюанс: агрегаты и NULL

Все агрегатные функции этого урока, кроме `COUNT(*)`, при вычислении **пропускают** строки с `NULL` в аргументе — они не участвуют ни в сумме, ни в количестве, ни в поиске минимума/максимума, как если бы этих строк не существовало для данной конкретной функции:

```sql
SELECT AVG(price) FROM products;
```

Если у одного товара из десяти `price` внезапно оказался `NULL` (в реальности такое исключено ограничением `NOT NULL` из шестого урока «Основ», но представим гипотетическую таблицу без такого ограничения), `AVG` посчитает среднее по **девяти** оставшимся товарам, а не по десяти с условным нулём вместо `NULL` — это принципиально разные числа. Именно поэтому, если требуется узнать «среднюю цену среди всех товаров, считая недостающие как 0», нужно явно обернуть столбец в `COALESCE(price, 0)` перед агрегированием:

```sql
SELECT AVG(COALESCE(price, 0)) AS average_with_nulls_as_zero
FROM products;
```

Отдельный и часто удивляющий новичков случай — что возвращает агрегатная функция, если **вообще нет ни одной строки** для агрегирования (например, `WHERE` отфильтровал абсолютно все строки). `COUNT(*)` в этом случае возвращает `0` — она действительно считает строки, и если строк ноль, результат ноль, это осмысленное число. А вот `SUM`, `AVG`, `MIN`, `MAX` в этом же случае возвращают `NULL`, а не `0` — потому что «сумма пустого набора чисел» или «среднее пустого набора» логически неопределены, и SQL честно сообщает об этом через `NULL`, а не подставляет произвольный ноль, который мог бы быть принят за настоящий результат.

### Резюме

- Агрегатные функции сворачивают **множество строк** в **одно** итоговое значение — в отличие от построчных функций предыдущих уроков.
- `COUNT(*)` считает все строки; `COUNT(столбец)` считает только строки с не-`NULL` значением этого столбца; `COUNT(DISTINCT столбец)` считает уникальные не-`NULL` значения.
- `SUM`, `AVG` — сумма и среднее числового столбца; `MIN`/`MAX` — минимум и максимум (работают и с числами, и с текстом, и с датами).
- Агрегаты свободно комбинируются друг с другом в одном `SELECT` и с `WHERE`, который фильтрует строки **до** агрегирования (следствие логического порядка выполнения из шестого урока).
- Все агрегаты, кроме `COUNT(*)`, игнорируют строки с `NULL` в аргументе; при полном отсутствии строк `COUNT(*)` возвращает `0`, а `SUM`/`AVG`/`MIN`/`MAX` возвращают `NULL`.

## Теоретические задания

### Вопрос 1: В таблице 10 товаров, у четырёх из них sku = NULL. Что вернёт `SELECT COUNT(sku) FROM products;`?

- ✅ 6
<!-- COUNT(столбец) пропускает строки, где значение этого столбца NULL -->
- ❌ 10 — error_text: 10 вернул бы `COUNT(*)` — он считает все строки независимо от NULL в столбцах. `COUNT(sku)` считает только строки, где sku не NULL: 10 − 4 = 6.
- ❌ 4 — error_text: 4 — это как раз товары без артикула. `COUNT(sku)` их пропускает; количество «пустых» находят разностью `COUNT(*) - COUNT(sku)` или фильтром `WHERE sku IS NULL` (урок 11 «Основ»).
- ❌ ошибку — COUNT не принимает столбец с NULL — error_text: NULL в аргументе агрегата — штатная ситуация, а не ошибка: `COUNT(столбец)` просто не учитывает такие строки при подсчёте, запрос выполняется.

### Вопрос 2: Из десяти товаров у одного price = NULL. Что вернёт AVG(price)?

- ✅ среднее по девяти товарам — строка с NULL не участвует ни в сумме, ни в количестве
<!-- агрегаты, кроме COUNT(*), игнорируют строки с NULL в аргументе -->
- ❌ среднее по десяти товарам, где NULL посчитан как 0 — error_text: AVG не подставляет ноль вместо NULL: строка полностью исключается и из суммы, и из количества, поэтому среднее считается по девяти значениям. Среднее «с NULL как 0» получают явно — `AVG(COALESCE(price, 0))`.
- ❌ NULL — error_text: AVG вернул бы NULL только при полном отсутствии строк для агрегирования — например, если WHERE отфильтровал всё. Здесь девять не-NULL цен есть, и по ним считается среднее.
- ❌ ошибку — error_text: NULL в аргументе агрегата не делает запрос ошибочным: все агрегаты, кроме COUNT(*), просто пропускают такие строки, как будто их нет.

### Вопрос 3: WHERE отфильтровал все строки таблицы. Что вернут COUNT(*) и SUM(price) в одном SELECT?

- ✅ COUNT(*) — 0, SUM(price) — NULL
<!-- пустой набор: счёт строк осмыслен и равен нулю; сумма пустого набора неопределена -->
- ❌ оба вернут 0 — error_text: COUNT(*) действительно вернёт 0 — строк нет, счёт нулевой. Но SUM не возвращает 0 для пустого набора: «сумма ничего» логически неопределена, и SQL сообщает об этом через NULL — иначе ноль было бы не отличить от настоящей суммы.
- ❌ оба вернут NULL — error_text: NULL вернули бы SUM/AVG/MIN/MAX, но не COUNT(*): он действительно считает строки и для нуля строк честно возвращает 0 — осмысленное число.
- ❌ MySQL вернёт ошибку «пустой результат» — error_text: пустой набор — не ошибка, а нормальная ситуация: запрос выполняется и возвращает одну строку с итогами по пустому набору строк.

### Вопрос 4: Что вернёт `SELECT MIN(name) FROM products;`?

- ✅ первое название по алфавиту
<!-- MIN/MAX работают не только с числами: текст сравнивается по правилам сортировки строк -->
- ❌ ошибку — MIN применим только к числам — error_text: MIN и MAX работают с текстом и датами тоже: текст сравнивается по правилам сортировки строк, как в ORDER BY (урок 9 «Основ»), даты — по хронологии.
- ❌ название самого дешёвого товара — error_text: MIN сравнивает значения того столбца, который ему передан, — здесь сами названия, а не цены. Название самого дешёвого товара нашлось бы иначе: `ORDER BY price LIMIT 1`.
- ❌ самую короткую строку из name — error_text: сравнение текста идёт по алфавиту, как в ORDER BY, а не по длине: 'Абракадабра' меньше, чем 'Яблоко'. Длину строк считают LENGTH/CHAR_LENGTH из урока 4 «Начинающего».

### Вопрос 5: В products 100 товаров, категория принимает пять разных значений, повторяясь много раз. Что вернёт COUNT(DISTINCT category)?

- ✅ 5
<!-- DISTINCT внутри COUNT схлопывает повторы до уникальных значений -->
- ❌ 100 — error_text: 100 — это COUNT(*): все строки подряд. DISTINCT внутри COUNT убирает повторяющиеся значения категории — остаются пять уникальных.
- ❌ 20 — error_text: 20 вышло бы при равномерном распределении как «строк на категорию», но COUNT(DISTINCT ...) не делит и не усредняет: он просто перечисляет уникальные не-NULL значения столбца.
- ❌ ошибку — DISTINCT нельзя использовать внутри COUNT — error_text: `COUNT(DISTINCT столбец)` — законная форма: считает количество уникальных не-NULL значений столбца, а не всех строк.
