## Материал

Функция `COALESCE`, которую мы изучили в одиннадцатом уроке «Основ», решает частный случай условной логики: «подставь запасное значение, если исходное — `NULL`». Но реальные задачи часто требуют более гибкой условной логики: «если цена меньше 1000 — категория "бюджетный", если от 1000 до 5000 — "средний", иначе — "премиум"». Для произвольных условий в SQL есть выражение `CASE WHEN` — аналог конструкции `if/elif/else`, знакомой из большинства языков программирования, но записываемой как **выражение**, возвращающее значение, а не как управляющая конструкция, меняющая поток исполнения программы.

### Поисковый CASE: проверка произвольных условий

Самая гибкая и часто используемая форма — **поисковый** (searched) `CASE`, в котором после каждого `WHEN` стоит произвольное логическое условие (в точности такое же, какие мы уже писали в `WHERE`):

```sql
SELECT name, price,
    CASE
        WHEN price < 1000 THEN 'бюджетный'
        WHEN price < 5000 THEN 'средний'
        ELSE 'премиум'
    END AS price_segment
FROM products;
```

Выражение вычисляется построчно: для каждой строки таблицы `products` условия `WHEN` проверяются **по порядку сверху вниз**, и как только находится первое истинное условие, `CASE` возвращает значение из соответствующего `THEN` и **немедленно прекращает** проверку последующих условий — даже если они тоже оказались бы истинными. Именно поэтому во втором условии достаточно написать `WHEN price < 5000`, а не `WHEN price >= 1000 AND price < 5000` — раз мы дошли до второго условия, значит первое (`price < 1000`) уже дало `FALSE`, то есть цена гарантированно не меньше 1000, а проверка `< 5000` довершает диапазон. Порядок условий в `CASE` — не формальность, а часть логики: если случайно поменять условия местами, начиная с более широкого, более узкие условия попросту никогда не будут достигнуты.

Ветка `ELSE` — необязательная, но крайне рекомендуемая: она задаёт значение для всех строк, не подошедших ни под одно из условий `WHEN`. Если `ELSE` не указан, а ни одно условие не оказалось истинным, `CASE` возвращает `NULL` — это не ошибка, но часто неожиданный результат, если про такую возможность забыли:

```sql
SELECT name, price,
    CASE
        WHEN price < 1000 THEN 'бюджетный'
        WHEN price < 5000 THEN 'средний'
    END AS price_segment
FROM products;
-- товары дороже 5000 получат NULL в price_segment, а не 'премиум'
```

### Простой CASE: сравнение одного выражения со списком значений

Есть и более компактная форма — **простой** (simple) `CASE`, когда одно и то же выражение сравнивается на равенство с несколькими конкретными значениями:

```sql
SELECT name, category,
    CASE category
        WHEN 'Периферия' THEN 'Аксессуары для ПК'
        WHEN 'Мониторы' THEN 'Экраны'
        ELSE 'Другое'
    END AS category_display
FROM products;
```

Это в точности эквивалент поискового `CASE` с условиями равенства, записанный короче — `CASE category WHEN 'Периферия' THEN ...` полностью равносилен `CASE WHEN category = 'Периферия' THEN ...`. Простую форму стоит использовать именно тогда, когда речь идёт про сравнение одного и того же значения с несколькими вариантами через равенство — как только нужны неравенства, диапазоны или условия с разными столбцами, требуется уже поисковая форма.

### CASE как обычное выражение — можно использовать почти везде

`CASE` — это **выражение**, а не отдельная команда, и оно ведёт себя так же, как любое другое выражение из третьего урока (арифметика, `CONCAT`, строковые функции): его можно использовать в `SELECT`, в `WHERE`, комбинировать с другими функциями, вкладывать одно в другое. Например, используем `CASE` прямо в `WHERE`, чтобы отфильтровать «премиальные» товары без явного повторения условия дважды:

```sql
SELECT name, price
FROM products
WHERE (CASE WHEN price >= 5000 THEN 1 ELSE 0 END) = 1;
```

Этот пример скорее иллюстративный — в реальности такое условие проще и естественнее написать напрямую как `WHERE price >= 5000`, но он показывает, что `CASE` — полноценное выражение, а не специальная конструкция, доступная только внутри `SELECT`. Более практичный пример — комбинирование `CASE` с уже знакомым нам `CONCAT` и функцией `COALESCE`:

```sql
SELECT name,
    CONCAT(name, ' — ', CASE WHEN stock > 0 THEN 'в наличии' ELSE 'нет в наличии' END) AS availability_label
FROM products;
```

### CASE внутри ORDER BY: условная сортировка

Одно из самых полезных нестандартных применений `CASE` — сортировка по условной логике, которую невозможно выразить через простой `ORDER BY column`. Классический пример — «сначала показать товары в наличии, а среди них — отсортировать по возрастанию цены, а товары не в наличии — отправить в конец списка, независимо от их цены»:

```sql
SELECT name, price, stock
FROM products
ORDER BY
    CASE WHEN stock > 0 THEN 0 ELSE 1 END,
    price ASC;
```

Здесь `CASE` вычисляет для каждой строки временное «служебное» число — `0` для товаров в наличии и `1` для отсутствующих — и `ORDER BY` сортирует прежде всего по этому числу (все нули окажутся раньше всех единиц), а при равенстве этого числа — по цене. Обратите внимание, что у `ORDER BY` здесь два «уровня» сортировки, разделённые запятой — этот приём (сортировка сначала по одному критерию, а при совпадении — по следующему) мы уже видели в девятом уроке «Основ», просто здесь первый критерий — не обычный столбец, а вычисленное `CASE`-выражение.

Другой распространённый пример — сортировка по нестандартному порядку значений, который не совпадает ни с алфавитным, ни с числовым порядком самого столбца — например, вывести заказы в порядке важности статуса, а не в алфавитном порядке названий статусов:

```sql
SELECT id, status
FROM orders
ORDER BY
    CASE status
        WHEN 'new' THEN 1
        WHEN 'processing' THEN 2
        WHEN 'shipped' THEN 3
        WHEN 'delivered' THEN 4
        ELSE 5
    END;
```

Без такого `CASE` обычная сортировка `ORDER BY status` расставила бы статусы в алфавитном порядке текста (`'delivered'`, `'new'`, `'processing'`, `'shipped'`), что почти никогда совпадает с желаемым порядком по смыслу бизнес-процесса.

### Резюме

- `CASE WHEN условие THEN значение ... ELSE значение END` — поисковый `CASE`: условия проверяются по порядку сверху вниз, возвращается значение из первого истинного `WHEN`; последующие условия не проверяются.
- `CASE выражение WHEN значение THEN результат ... END` — простой `CASE`: компактная запись для сравнения одного выражения на равенство с несколькими вариантами; эквивалент поискового `CASE` с условиями равенства.
- Ветка `ELSE` необязательна, но без неё несовпавшие строки получат `NULL` — это легко забыть и получить неожиданный результат.
- `CASE` — обычное выражение, а не отдельная команда: его можно использовать в `SELECT`, `WHERE`, комбинировать с `CONCAT` и другими функциями.
- `CASE` внутри `ORDER BY` позволяет задать произвольный, нестандартный порядок сортировки (например, «сначала в наличии, затем по цене» или пользовательский порядок статусов), не выражаемый простым `ORDER BY column`.

## Теоретические задания

### Вопрос 1: Цена товара — 500 рублей. Что вернёт для этой строки выражение `CASE WHEN price < 5000 THEN 'средний' WHEN price < 1000 THEN 'бюджетный' ELSE 'премиум' END`?

- ✅ 'средний'
<!-- условия WHEN проверяются по порядку сверху вниз; первое истинное выигрывает, остальные не проверяются -->
- ❌ 'бюджетный' — error_text: «бюджетный» был бы при обратном порядке условий. CASE проверяет WHEN строго по порядку и возвращает значение первого истинного: для цены 500 условие `price < 5000` уже истинно, и до проверки `price < 1000` очередь не доходит. Узкие условия нужно ставить раньше широких.
- ❌ 'премиум' — error_text: ELSE срабатывает, только когда ни одно из условий WHEN не оказалось истинным. Условие `price < 5000` для цены 500 истинно, поэтому до ELSE дело не доходит.
- ❌ MySQL откажет выполнять запрос — пересекающиеся условия в CASE запрещены — error_text: пересечение условий не запрещено: CASE спокойно возвращает значение первого истинного WHEN, а остальные игнорирует. Запрос выполнится — но результат будет неожиданным, потому что порядок WHEN — часть логики.

### Вопрос 2: Что вернёт `CASE WHEN price < 1000 THEN 'бюджетный' WHEN price < 5000 THEN 'средний' END` для товара ценой 12000 рублей?

- ✅ NULL
<!-- без ELSE строки, не подошедшие ни под одно WHEN, получают NULL — не ошибку -->
- ❌ 'премиум' — error_text: 'премиум' возвращал бы CASE с веткой `ELSE 'премиум'`. Здесь ELSE не написан, а значение CASE по умолчанию для несовпавших строк — NULL: «значения нет» в терминологии урока 11 «Основ».
- ❌ 'средний' — error_text: до второго WHEN доходят только строки, не прошедшие первое условие, — но 12000 не меньше и 5000: условие `price < 5000` ложно, ни одна ветка THEN не срабатывает.
- ❌ ошибку — выражение без ELSE неполно — error_text: ELSE необязателен, CASE без него синтаксически корректен. Цена ошибки в другом: молчаливый NULL в результатах, который легко не заметить при чтении отчёта.

### Вопрос 3: Для какой задачи уместна простая форма CASE — `CASE category WHEN 'Мониторы' THEN ... WHEN 'Периферия' THEN ... END`?

- ✅ сравнение одного и того же выражения на равенство с несколькими конкретными значениями
<!-- простой CASE — компактная запись поискового CASE с условиями равенства -->
- ❌ проверка условий с диапазонами и неравенствами — error_text: для произвольных условий нужен поисковый CASE — `CASE WHEN price < 1000 THEN ...`. В простой форме после WHEN стоит значение для сравнения на равенство, а не логическое условие.
- ❌ подстановка запасного значения вместо NULL — error_text: это задача COALESCE из урока 11 «Основ» — частный случай условной логики со своим компактным инструментом. CASE умеет то же и многое другое, но его простая форма — именно про равенство.
- ❌ сортировка строк в нестандартном порядке — error_text: условная сортировка — применение CASE внутри ORDER BY, но обе формы CASE — способ вычислить значение по условию, а не инструмент сортировки. Сама простая форма — сравнение на равенство.

### Вопрос 4: Зачем в ORDER BY пишут `CASE status WHEN 'new' THEN 1 WHEN 'processing' THEN 2 WHEN 'shipped' THEN 3 ELSE 5 END`?

- ✅ чтобы отсортировать заказы в порядке бизнес-процесса, а не по алфавиту статусов
<!-- CASE вычисляет служебное число — ключ сортировки для каждой строки -->
- ❌ чтобы отфильтровать заказы с нестандартными статусами — error_text: фильтрация строк — работа WHERE (урок 8 «Основ»). CASE в ORDER BY только вычисляет ключ сортировки; все строки остаются в результате, просто меняют порядок.
- ❌ чтобы переименовать статусы в выводе — error_text: CASE в ORDER BY не меняет то, что попадает в SELECT: значения status в выводе останутся прежними. Переименование — CASE в списке SELECT с псевдонимом.
- ❌ чтобы ORDER BY вообще смог отсортировать текстовый столбец — error_text: ORDER BY сортирует текст и без CASE — по алфавиту. Проблема не в способности, а в порядке: алфавитная последовательность 'delivered', 'new', 'processing' не совпадает с порядком бизнес-процесса.

### Вопрос 5: Почему в `CASE WHEN price < 1000 THEN 'бюджетный' WHEN price < 5000 THEN 'средний' ...` во втором WHEN не нужно дополнительно проверять `price >= 1000`?

- ✅ до второго WHEN доходят только строки, где первое условие уже ложно, — их цена гарантированно не меньше 1000
<!-- первое истинное условие завершает CASE: дошли до второго WHEN — значит, первый ложен -->
- ❌ SQL сам достраивает недостающую часть диапазона — error_text: сервер ничего не достраивает: он просто проверяет WHEN по порядку и останавливается на первом истинном. Эффект «цена уже не меньше 1000» — логическое следствие порядка условий, а не работа оптимизатора.
- ❌ цена ровно 1000 в данных невозможна — error_text: возможна — и попадёт в 'средний': первое условие `price < 1000` для неё ложно. Граничные значения от CASE не исчезают и экономию во втором условии не объясняют.
- ❌ такая запись — ошибка, MySQL вернёт неверный результат — error_text: запрос корректен и работает верно: все цены меньше 1000 остановятся на первом WHEN, остальные дойдут до второго. Ошибкой была бы перестановка условий — широкое раньше узкого.

больше нуля — текст вида `осталось: 12 шт.` (слово «осталось: », число
штук, « шт.»), если остаток нулевой — текст `нет в наличии`. Строки
отсортируйте по алфавиту названий.

**expected_result_text:**

Финальный SELECT возвращает шесть строк. У четырёх товаров остаток есть
— метка с числом штук; клавиатура и микрофон с нулевым остатком
получают «нет в наличии».

**seed_sql:**

```sql
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    stock INT NOT NULL DEFAULT 0
);

INSERT INTO products (name, stock) VALUES
    ('Мышь беспроводная', 12),
    ('Клавиатура механическая', 0),
    ('Наушники накладные', 7),
    ('Микрофон студийный', 0),
    ('Веб-камера Full HD', 25),
    ('Колонки настольные', 3);
```

### Задание 3: Сначала доступное

CASE в ORDER BY: товары в наличии — наверх, дальше по цене.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT name, price, stock FROM products ORDER BY CASE WHEN stock > 0 THEN 0 ELSE 1 END, price; -->

**statement:**

Таблица `products` содержит шесть товаров с ценами и остатками. Выведите
`name`, `price`, `stock` так, чтобы сначала шли товары в наличии
(`stock > 0`), отсортированные по возрастанию цены, а за ними —
отсутствующие, тоже по возрастанию цены.

**expected_result_text:**

Финальный SELECT возвращает шесть строк. Первые три — товары в наличии
по возрастанию цены (590.00, 1690.00, 2490.00), затем три отсутствующих
(990.00, 3490.00, 19990.00): служебный CASE отправляет их в конец
списка независимо от цены.

**seed_sql:**

```sql
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10,2) NOT NULL,
    stock INT NOT NULL DEFAULT 0
);

INSERT INTO products (name, price, stock) VALUES
    ('Коврик для мыши', 590.00, 40),
    ('Мышь игровая', 3490.00, 0),
    ('Клавиатура мембранная', 1690.00, 15),
    ('Монитор 27"', 19990.00, 0),
    ('Веб-камера', 2490.00, 8),
    ('USB-хаб', 990.00, 0);
```

**expected_rows:**

| name                   | price    | stock |
| ---------------------- | -------- | ----- |
| Коврик для мыши        | 590.00   | 40    |
| Клавиатура мембранная  | 1690.00  | 15    |
| Веб-камера             | 2490.00  | 8     |
| USB-хаб                | 990.00   | 0     |
| Мышь игровая           | 3490.00  | 0     |
| Монитор 27"            | 19990.00 | 0     |

**runtime:** mysql
