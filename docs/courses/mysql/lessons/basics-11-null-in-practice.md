## Материал

На протяжении всего курса мы несколько раз упоминали `NULL`, откладывая подробный разбор «на потом» — теперь пришло время разобраться в нём как следует. `NULL` — одно из самых важных и одновременно самых частых источников ошибок в SQL для начинающих, потому что интуиция, выработанная в обычных языках программирования, здесь работает не так, как ожидается. В этом уроке разберём, что такое `NULL` на самом деле, чем он принципиально отличается от нуля и пустой строки, как правильно проверять его наличие, как он ведёт себя в сравнениях и сортировке, и познакомимся с функциями `COALESCE` и `NULLIF`, которые помогают работать с ним удобно.

### NULL — это не значение, это отсутствие значения

Ключевая идея, которую стоит усвоить сразу: **`NULL` не является каким-то особым значением** (как, например, число 0 или пустая строка `''`) — это специальная маркировка «значение неизвестно» или «значение отсутствует». `NULL` может появиться в столбце по разным причинам:

- поле было необязательным, и при `INSERT` для него не указали значение (если столбец не объявлен `NOT NULL`, как мы разбирали в шестом уроке);
- значение просто неизвестно на момент внесения записи — например, у клиента ещё нет второго телефона, хотя в принципе он может завестись позже;
- поле логически неприменимо к конкретной строке — например, столбец «дата отмены заказа» осмыслен только для отменённых заказов, а для всех остальных заказов там будет `NULL`, потому что отмены не было и не может быть указана никакая конкретная дата.

Во всех этих случаях `NULL` говорит: «здесь не 0, не пустая строка, не какая-то конкретная дата — сюда просто не удаётся, не нужно или не имеет смысла поставить конкретное значение».

### NULL — не то же самое, что 0 или пустая строка

Это самое частое заблуждение новичков, и его важно развеять сразу конкретным примером. Рассмотрим три разных значения столбца `phone` у трёх клиентов:

| customer | phone |
|---|---|
| Клиент A | `'+7 900 123 45 67'` |
| Клиент B | `''` |
| Клиент C | `NULL` |

Все три значения выглядят по-разному, и означают разные вещи:

- у клиента A есть конкретный номер телефона — это обычное текстовое значение;
- у клиента B столбец `phone` содержит **пустую строку** — это *известное* значение: ноль символов текста. С точки зрения базы данных это вполне конкретная, определённая строка (просто состоящая из нуля символов), а не «нет значения»;
- у клиента C столбец `phone` содержит `NULL` — это означает, что значение **неизвестно, не указано или не применимо**, а не то, что оно «равно нулю символов».

Аналогичная путаница часто возникает с числами: столбец `discount_percent = 0` означает «скидка есть, и она равна нулю процентов» — это конкретное известное число. А `discount_percent = NULL` означает «неизвестно, есть ли скидка вообще, и если есть, то какая» — это принципиально другая ситуация, которую нельзя перепутать с «скидки нет» без потери смысла данных.

Понимание этого различия критически важно для проектирования таблиц: решение о том, разрешать ли `NULL` в столбце (то есть не помечать его `NOT NULL`), не должно быть случайным — оно должно отражать, действительно ли «неизвестность» значения — законное состояние для этого поля, отличное от «нуля» или «пустой строки».

### Проверка NULL: IS NULL и IS NOT NULL

Раз `NULL` — это не значение, а особая маркировка «неизвестности», привычный оператор равенства `=` для его проверки **не работает** так, как можно было бы ожидать интуитивно:

```sql
-- НЕПРАВИЛЬНО: это условие никогда не будет истинным!
SELECT * FROM customers WHERE phone = NULL;
```

Этот запрос **не найдёт** ни одной строки, даже если в таблице есть клиенты с `NULL` в `phone` — потому что сравнение *любого* значения (включая сам `NULL`) с `NULL` через `=` в SQL возвращает не `TRUE` и не `FALSE`, а особый третий результат — **неизвестно** (об этом чуть подробнее — в следующем разделе). Чтобы правильно проверить, есть ли в столбце значение `NULL`, используются специальные операторы:

```sql
-- правильно: находит клиентов без указанного телефона
SELECT * FROM customers WHERE phone IS NULL;
```

```sql
-- правильно: находит клиентов с указанным телефоном (любым, кроме NULL)
SELECT * FROM customers WHERE phone IS NOT NULL;
```

`IS NULL` и `IS NOT NULL` — не операторы сравнения в обычном смысле, а специальная синтаксическая конструкция именно для проверки «неизвестности» значения. Запомнить это правило стоит буквально навсегда: **`NULL` проверяется только через `IS NULL`/`IS NOT NULL`, никогда через `= NULL` или `<> NULL`.**

### Трёхзначная логика: TRUE, FALSE и NULL (неизвестно)

Причина, по которой `= NULL` не работает, глубже, чем просто «особое правило SQL» — она связана с тем, что логика сравнений в SQL формально **трёхзначна**, а не двузначна, как в большинстве языков программирования. Любое сравнение с участием `NULL` (через `=`, `<>`, `<`, `>` и другие) даёт не `TRUE` и не `FALSE`, а третий результат, который можно условно назвать «неизвестно» (UNKNOWN) — потому что сервер буквально не знает, чему равно неизвестное значение, и не может утверждать ни что оно равно чему-то, ни что не равно.

В условии `WHERE` строки, для которых итоговый результат условия — «неизвестно», ведут себя так же, как строки с результатом `FALSE`: они **не попадают** в результат запроса. Именно поэтому `WHERE phone = NULL` не находит вообще никаких строк — результат сравнения для каждой строки оказывается «неизвестно», а не `TRUE`, независимо от того, что реально хранится в `phone`.

Эта логика распространяется и на составные условия с `AND`/`OR` (подробно про них — на уровне «Начинающий»), но уже сейчас полезно знать: присутствие `NULL` в вычислениях почти всегда «заражает» результат неопределённостью, если не обработать его явно — отсюда и важность инструментов, к которым мы сейчас перейдём.

### NULL в сортировке

Раз `NULL` не является ни числом, ни текстом, ни датой, как он ведёт себя при `ORDER BY`? MySQL следует конкретному правилу: **`NULL` считается меньше любого не-`NULL` значения**. Это означает, что при сортировке по возрастанию (`ASC`, по умолчанию) строки с `NULL` в сортируемом столбце окажутся **первыми**, а при сортировке по убыванию (`DESC`) — **последними**:

```sql
SELECT name, phone
FROM customers
ORDER BY phone;
-- клиенты без телефона (NULL) окажутся в начале результата
```

Это важный практический нюанс: если в отчёте важно, чтобы строки без значения не «мешались» в начале списка при сортировке по возрастанию, нужно либо явно предусмотреть это в запросе, либо (что чаще встречается на практике) заменить `NULL` на осмысленное значение для целей отображения — с этим нам помогут функции ниже.

### COALESCE: подставить значение, если NULL

Функция `COALESCE` принимает список аргументов и возвращает **первый из них, который не является `NULL`**. Самый частый практический случай — два аргумента: реальное значение столбца и «запасное» значение для случая, если столбец пуст:

```sql
SELECT name, COALESCE(phone, 'не указан') AS phone_display
FROM customers;
```

Если у клиента есть `phone`, в результат попадёт именно это значение; если `phone` — `NULL`, в результат попадёт строка `'не указан'`. Функция `COALESCE` — удобный и распространённый способ «замаскировать» отсутствие значения понятным для человека текстом при отображении данных, не изменяя при этом реальные данные в таблице (сама таблица `customers` при выполнении `SELECT` никак не меняется — как мы помним, `SELECT` данные только читает).

`COALESCE` может принимать больше двух аргументов и возвращает первый не-`NULL` слева: `COALESCE(a, b, c)` вернёт `a`, если оно не `NULL`; иначе — `b`, если оно не `NULL`; иначе — `c` (даже если `c` окажется `NULL`, если все предыдущие тоже были `NULL`, результатом всё равно останется `NULL`, потому что заменить его больше нечем).

### NULLIF: сделать значение NULL по условию

`NULLIF` работает в некотором смысле противоположно `COALESCE`: она принимает два аргумента и возвращает `NULL`, если они **равны**, а иначе — возвращает первый аргумент без изменений:

```sql
SELECT price / NULLIF(quantity, 0) AS price_per_unit
FROM order_items;
```

Здесь `NULLIF(quantity, 0)` возвращает `NULL`, если `quantity` равно `0`, и само значение `quantity` — во всех остальных случаях. Зачем это нужно? Деление на ноль в SQL, в отличие от многих языков программирования, где оно вызывает ошибку выполнения (exception), в MySQL по умолчанию просто возвращает `NULL`, а не останавливает выполнение запроса с ошибкой. `NULLIF(quantity, 0)` в данном случае используется как явный, понятный код читающему человеку способ защититься от деления на ноль: если количество равно нулю, `NULLIF` заранее превращает его в `NULL`, и деление на `NULL` тоже даёт `NULL` — предсказуемо и без падения всего запроса, вместо того чтобы полагаться на неявное поведение сервера при делении на буквальный `0`.

### COALESCE и NULLIF можно комбинировать

Эти две функции часто используют вместе, чтобы получить полностью читаемый результат без единого технического `NULL` на выходе:

```sql
SELECT
    name,
    COALESCE(price / NULLIF(quantity, 0), 0) AS price_per_unit
FROM order_items;
```

Здесь сначала `NULLIF` защищает от деления на ноль, превращая проблемное количество в `NULL`; затем деление даёт `NULL`, если знаменатель был `NULL`; и, наконец, внешний `COALESCE` подменяет итоговый `NULL` на понятный `0` для отображения. Такая цепочка — распространённый паттерн «безопасного вычисления» в реальных SQL-запросах.

### Резюме

- `NULL` — не значение, а маркировка «значение неизвестно/отсутствует/неприменимо»; он принципиально отличается от `0` (конкретное число) и от пустой строки `''` (конкретный, хотя и пустой текст) — оба этих значения известны и определены, а `NULL` — нет.
- `NULL` нельзя проверить оператором `=` или `<>` — такие сравнения с `NULL` дают не `TRUE`/`FALSE`, а «неизвестно», и строка не попадёт в результат `WHERE`. Для проверки используются `IS NULL` и `IS NOT NULL`.
- Логика сравнений в SQL — трёхзначная (`TRUE`/`FALSE`/«неизвестно»); строки с результатом условия «неизвестно» ведут себя как `FALSE` и не попадают в результат.
- При `ORDER BY` строки со значением `NULL` считаются «меньше» любого известного значения: они окажутся первыми при `ASC` и последними при `DESC`.
- `COALESCE(a, b, ...)` возвращает первый не-`NULL` аргумент из списка — удобно для подстановки «запасного» значения вместо отсутствующего.
- `NULLIF(a, b)` возвращает `NULL`, если `a` равно `b`, иначе — само `a`; классический пример применения — защита от деления на ноль через `NULLIF(делитель, 0)`.

## Теоретические задания

### Вопрос 1: В `phone` некоторых строк — NULL. Что вернёт `SELECT * FROM customers WHERE phone = NULL;`?

- ✅ ни одной строки: сравнение с NULL через = даёт «неизвестно», а не TRUE
- ❌ все строки, у которых phone — NULL — error_text: = NULL не проверяет наличие NULL: результат сравнения — «неизвестно», и такие строки не попадают в результат; для проверки существует специальная конструкция IS NULL.
- ❌ ошибку синтаксиса: NULL нельзя писать в WHERE — error_text: запрос синтаксически корректен и выполнится — но молча вернёт пустой результат; в этом и коварство = NULL.

### Вопрос 2: В столбце `phone` хранятся пустая строка '' и NULL. Эквивалентны ли эти состояния?

- ✅ нет: '' — известное текстовое значение из нуля символов, NULL — маркировка «значение отсутствует»
- ❌ да: пустая строка — это и есть способ записать NULL в текстовый столбец — error_text: это два разных состояния: пустая строка определена («текста нет, и это известно»), NULL — «значение неизвестно или неприменимо»; путать их — терять смысл данных.
- ❌ да: сервер сам превращает '' в NULL при вставке — error_text: сервер хранит значения как есть: '' остаётся пустой строкой, NULL — NULL; автоматической замены одного на другого не происходит.

### Вопрос 3: Где окажутся строки с NULL в сортируемом столбце при `ORDER BY discount ASC`?

- ✅ в начале результата: NULL считается меньше любого известного значения
- ❌ в конце результата: NULL — «самое большое» значение — error_text: правило MySQL обратное: NULL меньше любого не-NULL; последними такие строки оказываются при сортировке по убыванию (DESC).
- ❌ ни в начале, ни в конце: ORDER BY отбрасывает строки с NULL — error_text: ORDER BY ничего не отбрасывает: строки с NULL сортируются наравне со всеми — по правилу «NULL меньше любого значения» они идут первыми при сортировке по возрастанию.

### Вопрос 4: Что вернёт `COALESCE(NULL, 'б', 'в')`?

- ✅ 'б' — первый аргумент слева, который не является NULL
- ❌ NULL — первый аргумент задаёт результат — error_text: COALESCE как раз «перескакивает» NULL-аргументы: возвращается первый аргумент, у которого есть значение; здесь это 'б', а не NULL.
- ❌ 'в' — последний аргумент списка — error_text: обход идёт слева направо: 'б' встречается раньше 'в' и не равен NULL — он и станет результатом.

### Вопрос 5: Что делает выражение `NULLIF(quantity, 0)`?

- ✅ возвращает NULL, если quantity равно 0, иначе — само значение quantity
- ❌ возвращает 0, если quantity — NULL, иначе quantity — error_text: аргументы сравниваются в прямом порядке: NULLIF(a, b) даёт NULL при a = b и a в остальных случаях; он «заменяет ноль на NULL», а не наоборот — подстановку значения вместо NULL выполняет COALESCE.
- ❌ возвращает NULL для всех строк, где quantity не равно 0 — error_text: наоборот: NULL возникает только при равенстве аргументов; во всех остальных случаях возвращается первый аргумент без изменений — например, 5 при quantity = 5.

### Задание 3: Цена за штуку

NULLIF и COALESCE вместе: безопасное деление при нулевом количестве.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT product, COALESCE(total / NULLIF(quantity, 0), 0) AS unit_price FROM order_items ORDER BY id; -->

**statement:**

В таблице `order_items` пять позиций заказа: total — сумма позиции,
quantity — количество штук. Выведите product и unit_price — цену за
штуку (total / quantity); для позиций с нулевым количеством вместо
деления на ноль должен получиться 0.

**expected_result_text:**

Пять строк: у позиций с quantity = 0 (кабель и внешний SSD) unit_price —
0.000000: NULLIF превращает делитель в NULL, деление даёт NULL, внешний
COALESCE подменяет его нулём. Остальные позиции — результат деления
суммы на количество.

**seed_sql:**

```sql
CREATE TABLE order_items (
    id INT AUTO_INCREMENT PRIMARY KEY,
    product VARCHAR(100) NOT NULL,
    total DECIMAL(10,2) NOT NULL,
    quantity INT NOT NULL
);

    ('Внешний SSD 1 ТБ', 6990.00, 0),
    ('Коврик для мыши', 390.00, 6);
```
