# Правила составления урока (курс MySQL)

> Применяется к урокам курса по плану [mysql.md](mysql.md).
> Урок сначала составляется как markdown-файл по этим правилам, затем переносится в админку.

**Главный принцип: файл — единственный источник правды.** Урок создаётся **только
как markdown-файл**: на этапе составления никаких записей в БД и никаких сидеров.
При этом файл обязан быть машиночитаемым — строго по шаблону раздела 5, так чтобы по
нему можно было механически создать урок в БД: через админку, сгенерированный по
файлам сидер или бот. Всё, чего нет в файле, в БД не попадёт.

При составлении урока необходимо написать три части: материал, теоретическую проверку
и (если для урока предусмотрена практика) практические задания.

---

## 1. Материал урока

- **Исчерпывающая статья по теме урока**: определения, синтаксис, примеры запросов,
  типичные ошибки и подводные камни. Читатель, не знакомый с темой, должен понять её
  по одному этому тексту, без внешних источников.
- **Ориентир объёма: 1500–3000 слов (≈12–18 минут чтения).** Тонкая «выжимка» на
  3–4 минуты — не исчерпывающая статья: разворачивайте мотивацию, историю вопроса,
  сравнения с альтернативами, терминологию-синонимы, граничные случаи и «когда это
  не нужно». При этом вода недопустима: каждый абзац должен сообщать что-то новое.
  Практический тест: если абзац можно удалить, и тема всё равно понятна, а вопросы
  урока отвечаются — это вода, удаляйте. Не добирайте объём украшениями (награды
  и регалии, вымышленная статистика, повторы уже сказанного другими словами).
- Структура: «Ранее в курсе» (со второго урока курса) → короткое введение
  (зачем эта тема) → разделы с примерами SQL → резюме (ключевые мысли
  списком).
- **«Ранее в курсе» — краткое содержание всех предыдущих уроков курса.**
  Первый подраздел секции `## Материал`; заголовок фиксированный —
  `### Ранее в курсе`; переносится в БД как начало `lessons.material`.
  Формат — маркированный список с одним пунктом на каждый предыдущий урок
  **всего курса**, в порядке прохождения: «Урок <N> уровня «<Уровень>»
  «<Тема>» — одна фраза сути (что ученик теперь знает или умеет)»; пункты
  предыдущих уровней не выбрасываются. В самом первом уроке курса раздела
  нет. Ограничения: только пройденный материал (границы тем — §4), без
  новых терминов, не больше строки на урок — это повторение и ориентация,
  а не конспект. Назначение двойное: ученику — повторение, ревьюеру и
  автору — явная карта разобранного: текущий урок может опираться на
  перечисленное без пересказа, и это не пробел материала.
- Примеры запросов по возможности пишем на сквозном датасете курса (интернет-магазин:
  `products`, `categories`, `customers`, `orders`, `order_items` и т.д. — см. [mysql.md](mysql.md)).
- Опираться только на уже пройденные темы и общую компьютерную грамотность; новые термины
  вводятся и объясняются в самом материале.

## 2. Теоретическая проверка

- **3–5 вопросов** на урок; один вопрос — одна идея.
- У каждого вопроса **несколько вариантов ответа** (рекомендуется 3–4), из которых
  **ровно один правильный**.
- **К каждому неправильному варианту — комментарий** (`error_text` в админке), который
  увидит пользователь, выбрав его. В комментарии указать, **почему именно этот вариант
  неверен** — конкретно и обучающе, а не «неверно, попробуйте ещё раз». Правдоподобные
  «ловушки» (перепутанные концепции, отличающиеся на одну деталь формулировки) ценятся
  выше очевидно абсурдных вариантов.
- Формат в markdown-файле (строгий — парсится при переносе в БД):

```markdown
### Вопрос N: текст вопроса?

- ✅ правильный вариант
- ❌ неверный вариант — error_text: почему именно этот вариант неверен
- ❌ неверный вариант — error_text: ...
```

- ✅-строка содержит **только текст варианта** (без авторских пояснений);
  пояснения, если нужны, — HTML-комментарием `<!-- … -->` на отдельной строке:
  при переносе в БД комментарии игнорируются.

## 3. Практические задания

- Только если для урока в плане ([mysql.md](mysql.md), колонка «Практика») **не стоит «—»**.
- **1–3 задания** нарастающей сложности.
- Для каждого задания указать:
  - **формулировку** — что нужно получить, с контекстом датасета;
  - **ожидаемый результат** — словесное описание + пример результирующей таблицы
    (это основа для `expected_result_text` и эталона в админке);
  - **сид-данные** — какие таблицы/строки нужны (или «стандартный датасет уровня»,
    если хватает сквозного);
  - при переносе в админку практика выполняется с `runtime = mysql`.

### Платформенная механика (обязательно учитывать)

При составлении заданий опираемся на логику и таблицы приложения:

- Задание живёт в `practice_tasks` с полями: `statement` (формулировка),
  `expected_result_text` (человекочитаемое описание результата), `seed_sql`
  (скрипт подготовки среды), `expected_rows` (точный ожидаемый результат —
  массив строк «колонка → значение»), `expected_hash` (вычисляется из
  `expected_rows` каноническим сериализатором), `runtime`, `order`, `is_published`.
- Изолированная среда под каждую попытку поднимается **с нуля из `seed_sql`** —
  скрипт каждого задания самодостаточен: все таблицы и строки создаются им самим,
  общего состояния между заданиями и попытками нет.
- Решение студента исполняется в этой среде, итоговый result set сравнивается
  с `expected_rows` по каноническому хешу; при несовпадении студент видит diff
  «Эталон / Ваш результат». Поэтому `expected_rows` — это **результат эталонного
  решения, который автор обязан реально прогнать**, а не сконструировать в голове:
  лишняя/пропущенная строка, другое значение или другой набор колонок сделают
  задание нерешаемым.
- Отсюда же следует требование детерминированности ниже.
- Результат запроса должен быть **детерминированным**: явный `ORDER BY`, без reliance
  на «порядок вставки», по возможности без `NOW()`-зависимостей (или зафиксированные
  даты в сид-данных).
- Решение может состоять из **нескольких SQL-инструкций**, разделённых `;`
  (для `runtime = mysql|postgres`): все исполняются в одной client-сессии
  движка — доступны эффекты друг друга (вставленные строки, транзакции,
  временные таблицы). Лимит числа инструкций и blacklist запрещённых команд —
  на стороне платформы.
- **Контракт результата:** зачёт по result set **последней** инструкции;
  инструкции до неё не должны возвращать данных (типовой паттерн пишущего
  задания — изменения, затем финальный `SELECT`).
- Для пишущих заданий эталон — `INSERT/UPDATE/…; SELECT …;`, а `expected_rows` —
  таблица, которую возвращает финальный `SELECT` (пост-состояние); такой эталон
  так же обязательно реально прогнать.
- `runtime = sqlite` (демо-курс) — по-прежнему одна инструкция.

## 4. Границы тем (обязательное правило)

- Теоретические вопросы (квиз) и практика должны **в основном касаться темы текущего урока**.
- **Допустимо и порой желательно**, чтобы они **косвенно касались ранее пройденного
  материала** (повторение и закрепление).
- **Недопустимо**, чтобы они касались **ещё не пройденных тем** — порядок определяется
  планом: уровень за уровнем, урок за уроком ([mysql.md](mysql.md)).
  Пример: в уроке «WHERE» нельзя требовать `GROUP BY` (уровень «Начинающий»), но можно
  попросить отфильтровать таблицу, созданную в уроке «CREATE TABLE».

## 5. Сохранение урока

Составленный урок сохраняется по пути:

```
docs/<course>/<level>-<lesson number>-<lesson theme>.md
```

Для курса MySQL:

- `<course>` = `mysql`;
- `<level>` — латинский slug уровня:

  | Уровень (в плане) | slug |
  |---|---|
  | Основы | `basics` |
  | Начинающий | `beginner` |
  | Средний | `intermediate` |
  | Продвинутый | `advanced` |

- `<lesson number>` — двузначный номер урока из плана (`01`, `02`, …);
- `<lesson theme>` — тема урока латиницей в kebab-case.

Примеры: `docs/mysql/basics-01-what-is-a-database.md`,
`docs/mysql/beginner-09-group-by.md`, `docs/mysql/advanced-02-explain.md`.

Шаблон файла (строгий, машиночитаемый — по нему создаётся урок в БД):

````markdown
---
course: mysql
level: Начинающий          # Основы | Начинающий | Средний | Продвинутый
level_slug: beginner
lesson: 9
title: GROUP BY: группировка строк
practice: yes              # yes | no — по колонке «Практика» в docs/mysql.md
---

# <Тема урока>

## Материал

### Ранее в курсе

- Урок 1 уровня «Основы» «…» — <одна фраза сути>
- Урок 2 уровня «Основы» «…» — <одна фраза сути>
- … — <все предыдущие уроки курса, в порядке прохождения>

(далее — исчерпывающая статья по теме: введение, разделы с примерами SQL,
резюме. Всё содержимое секции `## Материал`, включая «Ранее в курсе»,
переносится в lessons.material. В первом уроке курса раздела нет.)

## Теоретические задания

### Вопрос 1: <текст вопроса>

- ✅ <текст правильного варианта>
- ❌ <текст неверного варианта> — error_text: <почему именно этот вариант неверен>
- ❌ <текст неверного варианта> — error_text: <…>

## Практические задания

### Задание 1: <краткое название>

**statement:**

<формулировка задания для студента>

**expected_result_text:**

<человекочитаемое описание ожидаемого результата>

**seed_sql:**

```sql
<самодостаточный SQL подготовки изолированной среды>
```

**expected_rows:**

| <колонка> | <колонка> |
| --------- | --------- |
| <значение> | <значение> |

**runtime:** mysql
````

Перенос «файл → БД» (для админки, генератора сидеров или бота) — источник каждого поля:

| Поле БД | Откуда в файле |
|---|---|
| `lessons.title` / `lessons.order` / `lessons.material` | frontmatter `title` / `lesson` / содержимое секции `## Материал` |
| `lessons.slug` | `<lesson theme>` из имени файла |
| курс и уровень | frontmatter `course`, `level_slug` |
| `theory_tasks.question`, `.order` | `### Вопрос N` — текст и номер |
| `theory_task_options.text`, `.is_correct`, `.error_text`, `.order` | строки-варианты: текст; `✅` = верный, `❌` = неверный; текст после `— error_text:`; позиция строки в списке |
| `practice_tasks.statement` | текст под маркером `**statement:**` |
| `practice_tasks.expected_result_text` | текст под маркером `**expected_result_text:**` |
| `practice_tasks.seed_sql` | SQL-блок после маркера `**seed_sql:**` |
| `practice_tasks.expected_rows` | markdown-таблица после маркера `**expected_rows:**` |
| `practice_tasks.runtime` / `.order` | строка `**runtime:**` / номер в `### Задание N` |

Требования к машиночитаемости:

- frontmatter обязателен и заполнен полностью; секции идут в фиксированном порядке:
  `## Материал` → `## Теоретические задания` → `## Практические задания`
  (последней нет при `practice: no`);
- со второго урока курса первый подраздел `## Материал` — строго
  `### Ранее в курсе` (требования к разделу — §1);
- внутри тел вопросов и заданий не использовать заголовки `###` и маркеры вида
  `**statement:**` / `**seed_sql:**`;
- `expected_rows` — markdown-таблица точного результата эталонного прогона
  (см. раздел 3): одна строка таблицы = одна строка результата;
- всё нужное для БД есть в файле: перенос не требует домысливания.

## Чек-лист перед сдачей урока

- [ ] Материал — исчерпывающая статья, понятная без внешних источников.
- [ ] Со второго урока курса материал открывается разделом «Ранее в курсе»:
      по одному краткому пункту на каждый предыдущий урок всего курса,
      в порядке прохождения (первый урок курса — без раздела).
- [ ] Объём материала — в ориентире 1500–3000 слов (≈12–18 минут чтения), без воды.
- [ ] 3–5 теоретических вопросов; в каждом ровно один правильный вариант.
- [ ] У каждого неверного варианта есть обучающий комментарий «почему неверен».
- [ ] Если `practice: yes` — 1–3 задания с формулировкой, ожидаемым результатом и сид-данными.
- [ ] Для каждого практического задания `seed_sql` самодостаточен (среда поднимается
      с нуля), а `expected_rows` — прогнанный результат эталонного решения
      (в заданиях из нескольких инструкций — результат финального `SELECT`).
- [ ] Ни в теории, ни в практике нет ещё не пройденных тем; ранее пройденное — только косвенно.
- [ ] Файл сохранён по пути `docs/mysql/<level>-<NN>-<theme>.md`, frontmatter заполнен.
- [ ] Урок создан **только в файле** — ничего не писалось в БД и в сидеры; формат
      строго машиночитаем: по файлу можно сгенерировать сидер или создать урок ботом.
