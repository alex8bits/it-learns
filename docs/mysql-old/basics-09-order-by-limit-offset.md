# Сортировка и страницы

## Материал

### Обещание из урока 8

Урок 8 закончился честной оговоркой: без сортировки порядок строк в
результате формально не гарантирован, и «первые» из `LIMIT` — это «первые
из вернувшихся», а не «самые…». Сегодня закрываем этот долг: учимся
управлять порядком строк командой `ORDER BY`, а затем строим на ней два
классических приёма — «топ-N» (самые дорогие, самые новые) и «страницы»
(каталог по три товара на страницу).

Порядок редко нужен сам по себе — он нужен, чтобы первым делом было видно
главное: каталог от дешёвых к дорогим, свежие заказы сверху, лучшие
товары впереди. Все эти сценарии — одна и та же команда с разными
столбцами и направлением.

Это последний кусочек пазла из урока 3: тогда `LIMIT` обрезал «просто
строки», теперь — строки в заданном порядке.

### ORDER BY: порядок становится обещанием

```sql
SELECT name, price
FROM products
ORDER BY price;
```

`ORDER BY столбец` выстраивает результат по значениям столбца. По
умолчанию — **по возрастанию**: от меньшего к большему. Направление можно
написать и явно словом `ASC` (ascending, «восходящая»): `ORDER BY price
ASC` — то же самое, что без него. Для убывания — `DESC` (descending):
от большего к меньшему. Стиль курса: `ASC` опускаем (он и так по
умолчанию), `DESC` пишем всегда.

На наших шести товарах:

```sql
SELECT name, price FROM products ORDER BY price;
SELECT name, price FROM products ORDER BY price DESC;
```

```text
+--------------------------+----------+
| name                     | price    |
+--------------------------+----------+
| Кабель HDMI 2 м          |   450.00 |
| Коврик для мыши          |   690.00 |
| Мышь беспроводная        | 1290.50  |
| Веб-камера               | 2450.00  |
| Клавиатура механическая  | 4990.00  |
| Монитор 27"              | 15990.00 |
+--------------------------+----------+
```

Строки идут от самого дешёвого к самому дорогому; с `DESC` порядок был бы
обратным. Сортировать можно по столбцу, которого нет в списке `SELECT`, —
симметрия с `WHERE` из урока 8: список после `SELECT` решает, какие
столбцы показать, `ORDER BY` — в каком порядке идти строкам.

Опечатка в имени столбца ловится знакомой ошибкой:

```text
ERROR 1054 (42S22): Unknown column 'prise' in 'order clause'
```

Та же 1054, что и без кавычек в `WHERE` урока 8, — только теперь сервер
ищет столбец для сортировки. Схема разбора не меняется: код → текст → имя.

И когда сортировка не нужна: упорядочить сто тысяч строк серверу дороже,
чем просто отдать их. Если порядок безразличен — проверить, есть ли
вообще такие строки, выгрузить всё разом, — `ORDER BY` не пишут: не
нагружайте сервер без повода.

### Что как сортируется

Правила те же, что для сравнений в `WHERE`, — сортировка и есть серия
сравнений:

- числа — по величине: 450 < 690 < 1290.50;
- даты — по календарю: раньше — меньше (урок 8);
- строки — по алфавиту: Казань, Москва, Новосибирск, Санкт-Петербург;
- флаги — как числа урока 5: FALSE (0) встанет раньше TRUE (1).

Для строк порядок определяет та же настройка сравнения (collation), что
отвечала за регистронезависимость в уроке 8: «Анна» и «анна» для
сортировки равны, кириллица идёт по алфавиту. А как расставляет строки
без значений (`NULL`) — отдельный вопрос, его разберём в уроке 11 вместе
со всем NULL.

Самый ходовой случай с датами — «новые сверху»:

```sql
SELECT customer, created_at
FROM orders
ORDER BY created_at DESC
LIMIT 3;
```

```text
+-----------------------------+------------+
| customer                    | created_at |
+-----------------------------+------------+
| Пётр Иванов                 | 2026-08-11 |
| Ольга Смирнова              | 2026-07-05 |
| Дмитрий Козлов              | 2026-06-27 |
+-----------------------------+------------+
```

Дата позже — «больше» (урок 8), поэтому `DESC` ставит свежие наверх, а
`LIMIT` отрезает троих первых. «Самые новые N» и «самые дорогие N» — один
и тот же приём, отличается только столбец.

### Несколько столбцов: главный и запасной

Сортировать по одному столбцу хорошо, пока значения не повторяются. А если
в таблице три москвича? Порядок строк с равным городом не гарантирован —
знакомая оговорка. Второй столбец её снимает:

```sql
SELECT name, city
FROM customers
ORDER BY city, name;
```

```text
+-----------------------------+-------------------------------+
| name                        | city                          |
+-----------------------------+-------------------------------+
| Иван Сидоров                | Казань                        |
| Анна Петрова                | Москва                        |
| Мария Волкова               | Москва                        |
| Пётр Иванов                 | Москва                        |
| Ольга Смирнова              | Новосибирск                   |
| Дмитрий Козлов              | Санкт-Петербург               |
+-----------------------------+-------------------------------+
```

Читается так: сортируй по `city`, а при равных городах — по `name`.
Столбцы работают по приоритету слева направо: первый — главный, второй —
запасной, включается только для равных. Поменяли местами (`ORDER BY name,
city`) — получите совсем другую сортировку: имена по алфавиту, имя
разрешает равные города.

`DESC` принадлежит конкретному столбцу, а не всей сортировке:

```sql
SELECT name, city FROM customers ORDER BY city DESC, name;
```

Города пойдут в обратном порядке (Санкт-Петербург → Казань), но внутри
Москвы имена останутся по алфавиту — `DESC` висит на `city`, а у `name`
направление своё, по умолчанию восходящее.

Столбцов в списке может быть и больше двух — читаются так же: слева
направо, каждый следующий включается при равенстве всех предыдущих.
Практическое правило для полной определённости: заканчивайте список
столбцом-развязкой вроде `id` — `ORDER BY city, name, id`. Равных `id` не
бывает (урок 6), значит, и неопределённости не останется ни при каких
данных.

### Топ-N: ORDER BY + LIMIT

«Самые дорогие три товара» — самая частая задача с сортировкой. Решение —
два знакомых инструмента подряд:

```sql
SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 3;
```

```text
+--------------------------+----------+
| name                     | price    |
+--------------------------+----------+
| Монитор 27"              | 15990.00 |
| Клавиатура механическая  |  4990.00 |
| Веб-камера               |  2450.00 |
+--------------------------+----------+
```

Сначала `ORDER BY price DESC` ставит самые дорогие наверх, затем `LIMIT 3`
оставляет троих первых. Забытый `DESC` — классика: `ORDER BY price LIMIT 3`
вернёт три самых дешёвых, и запрос «выглядит рабочим», пока не взглянешь
на цены. Зеркальный случай — «самые дешёвые» — делается тем же приёмом,
только без `DESC`: направление по умолчанию восходящее. Проверяйте
направление по задаче: «дорогие, новые, лучшие» — почти всегда `DESC`,
«дешёвые, старые, первые по алфавиту» — почти всегда восходящая.

Теперь можно собрать всю инструкцию целиком — все части курса в одном
запросе:

```sql
SELECT name, price
FROM products
WHERE price > 1000
ORDER BY price DESC
LIMIT 2;
```

Порядок частей не произволен и в тексте, и по смыслу: `WHERE` отбирает
подходящие строки → `ORDER BY` выстраивает их → `LIMIT` обрезает результат.
Два самых дорогих товара дороже тысячи — так это читается.

Соберём анатомию `SELECT`, накопленную курсом, — теперь в инструкции есть
все пять частей:

| Часть            | Отвечает за…          | Урок |
| ---------------- | --------------------- | ---- |
| `SELECT столбцы` | какие столбцы показать | 1    |
| `FROM таблица`   | где брать строки       | 1    |
| `WHERE условие`  | какие строки подходят  | 8    |
| `ORDER BY`       | в каком порядке идут   | 9    |
| `LIMIT/OFFSET`   | сколько строк взять    | 3, 9 |

Каждая часть — один простой вопрос к результату; даже сложные запросы
будут собираться из этих же кирпичей.

### Страницы: OFFSET

Каталог на сотни товаров не показывают целиком — его листают страницами.
Страница — это «пропустить столько-то, взять столько-то»:

```sql
SELECT name, price
FROM products
ORDER BY price
LIMIT 3 OFFSET 3;
```

```text
+--------------------------+----------+
| name                     | price    |
+--------------------------+----------+
| Веб-камера               | 2450.00  |
| Клавиатура механическая  |  4990.00 |
| Монитор 27"              | 15990.00 |
+--------------------------+----------+
```

`LIMIT 3` — взять три строки, `OFFSET 3` — сначала пропустить три; сам по
себе `OFFSET` не пишут — он существует только в паре с `LIMIT`. Каталог
отсортирован по цене по возрастанию, страница №1 — три самых дешёвых,
наш запрос — страница №2. Формула страницы: при размере страницы `k`
страница №`p` — это `LIMIT k OFFSET (p−1)·k`: первая страница — `OFFSET 0`
(пропустить нечего), вторая пропускает одну страницу, третья — две.

И одна цена приёма: `OFFSET` не бесплатен — серверу приходится пройти
и отбросить все пропускаемые строки, поэтому страница №500 читается дольше
первой. Для наших таблиц это незаметно, но на больших данных глубокое
листание — известная дорогая операция.

В чужом коде встретится короткая форма `LIMIT 3, 3` — это то же `OFFSET 3`
с последующим `LIMIT 3`: сначала смещение, потом количество. Перепутать
порядок легко, поэтому в курсе пишем развёрнуто — `LIMIT … OFFSET …`.

Две мелочи в духе урока 8: `OFFSET` за пределами таблицы — не ошибка,
а пустой результат: пропустить можно и больше, чем есть строк. Так,
страница №3 нашего каталога (`LIMIT 3 OFFSET 6`) вернёт пустой результат:
шести товарам хватает двух страниц ровно. И страницы имеют смысл только поверх `ORDER BY` — без
сортировки «страница №2» не обещает показать то, что не попало на первую.
Сам приём листания страницами называют пагинацией (от английского page —
страница).

### Резюме

- `ORDER BY столбец` задаёт порядок результата; по умолчанию — по
  возрастанию (`ASC`), `DESC` — по убыванию; `ASC` опускаем, `DESC` пишем.
- Числа — по величине, даты — по календарю, строки — по алфавиту (правила
  те же, что у сравнений `WHERE`); NULL в сортировке — урок 11.
- Сортировать можно по столбцу вне списка `SELECT`; опечатка — та же 1054,
  теперь `in 'order clause'`.
- Несколько столбцов: приоритет слева направо, второй разрешает равные
  значения первого; `DESC` у каждого столбца свой.
- Развязка по `id` в конце списка столбцов делает порядок полностью
  определённым.
- Топ-N = `ORDER BY … DESC` + `LIMIT N`; забытый `DESC` молча вернёт
  «низ» вместо «верха».
- Полный порядок частей: `WHERE` → `ORDER BY` → `LIMIT` — и в тексте
  запроса, и по смыслу.
- Страница №p размером k: `LIMIT k OFFSET (p−1)·k`; короткая форма
  `LIMIT смещение, количество` — встретится в чужом коде.
- `OFFSET` за концом таблицы — пустой результат, не ошибка; страницы —
  только поверх `ORDER BY`.

## Теоретические задания

### Вопрос 1: `SELECT name, price FROM products ORDER BY price;` В каком порядке вернутся строки?

- ✅ по возрастанию price — это направление по умолчанию
- ❌ по убыванию price: ORDER BY всегда ведёт от больших к меньшим — error_text: по умолчанию сортировка восходящая (ASC); для убывания нужен явный DESC — «от дорогих к дешёвым» не случится само собой.
- ❌ в том же порядке, в каком строки хранились: ORDER BY ничего не гарантирует — error_text: наоборот: без ORDER BY порядок не гарантирован (урок 8), а с ним — гарантирован заданный; «как хранились» — не вариант.

### Вопрос 2: Нужно вывести три самых дорогих товара. Какой запрос верен?

- ✅ `SELECT name, price FROM products ORDER BY price DESC LIMIT 3;`
- ❌ `SELECT name, price FROM products ORDER BY price LIMIT 3;` — error_text: без DESC сортировка идёт по возрастанию — вернутся три самых дешёвых товара; запрос выглядит рабочим, но отвечает на другой вопрос.
- ❌ `SELECT name, price FROM products LIMIT 3 ORDER BY price DESC;` — error_text: порядок частей инструкции строгий: LIMIT пишется последним, после ORDER BY; иначе — синтаксическая ошибка.

### Вопрос 3: В `ORDER BY city, name` какую роль играет столбец name?

- ✅ разрешает порядок среди строк с одинаковым city
- ❌ сортировка идёт только по name, а city игнорируется — error_text: столбцы работают по приоритету слева направо: главный — city; name вступает в дело только там, где city совпали.
- ❌ строки сортируются сначала по name, потом по city — error_text: порядок обратный: первым делом сравнивается city, а name — запасной ключ для равных городов.

### Вопрос 4: Каталог отсортирован по цене по возрастанию, страницы по 3 товара. Какой запрос вернёт страницу №2?

- ✅ `LIMIT 3 OFFSET 3`
- ❌ `LIMIT 3 OFFSET 2` — error_text: смещение — это число пропускаемых строк: страница №1 заняла 3 строки, значит вторая начинается после смещения 3, а не 2.
- ❌ `LIMIT 2 OFFSET 3` — error_text: числа перепутаны ролями: в LIMIT — размер страницы (3), в OFFSET — сколько пропустить (3); LIMIT 2 вернул бы страницу из двух товаров.

### Вопрос 5: В таблице 6 строк. Что вернёт `SELECT name FROM products LIMIT 3 OFFSET 100;`?

- ✅ пустой результат — это не ошибка
- ❌ ошибку: смещение больше числа строк — error_text: выйти смещением за конец таблицы — штатная ситуация: пропустить можно и больше, чем есть строк; результат — пустой, как у ни к чему не подошедшего WHERE урока 8.
- ❌ последние три строки таблицы — error_text: OFFSET не «останавливается у конца»: он честно пропускает 100 строк — которых нет — и берёт следующие 3, а их тоже нет; пусто.
