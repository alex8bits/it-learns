# NULL на практике

## Материал

### Урок, которого все ждали

`NULL` появлялся в каждом втором уроке — всегда на минуту и с обещанием
«полноценно разберём в уроке 11». Урок 5 сказал: NULL — «значение
отсутствует». Урок 6 запретил его для обязательных столбцов (`NOT NULL`,
ошибка 1048) и напомнил: `DEFAULT` заменяет пропуск, но не явный NULL.
Урок 8 обнаружил, что сравнения `NULL` не ловят, а пустая строка — не NULL.
Урок 9 пообещал объяснить, куда встают NULL-строки при сортировке. Пора
закрыть все долги разом: что NULL такое на самом деле, как его искать
(`IS NULL`), как он ведёт себя в сравнениях и сортировке — и два
инструмента-помощника, `COALESCE` и `NULLIF`.

Почему бы не обойтись без NULL — писать пустую строку или ноль? Потому что
«нет ответа» и «ответ — пустой» — разные факты о мире. Если у половины
покупателей телефон записан пустой строкой, вы больше не отличите «не
спросили» от «спросили — отказался». Если у неизвестной цены писать ноль,
каталог начнёт уверенно сообщать, что монитор бесплатен. NULL — честная
запись отсутствия: значение неизвестно или неприменимо (как дата
окончания у бессрочной подписки). За честность приходится платить
особыми правилами, которые сегодня и разбираем.

### NULL: значение, которого нет

Героиня урока — таблица покупателей с необязательным телефоном:

```sql
CREATE TABLE customers (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    city VARCHAR(50) NOT NULL,
    phone VARCHAR(20)
);
```

У столбца `phone` нет `NOT NULL` — телефон можно и не указывать. Состав —
знакомые по урокам 8–9 покупатели без Петра Иванова: демо-наборы каждого
урока самостоятельны (как и партии `products` ниже), пятёрки для темы
достаточно. Смотрим, что накопилось:

```sql
SELECT id, name, phone FROM customers;
```

```text
+----+-----------------------------+---------------+
| id | name                        | phone         |
+----+-----------------------------+---------------+
|  1 | Анна Петрова                | NULL          |
|  2 | Иван Сидоров                | 912-345-67-89 |
|  3 | Мария Волкова               | NULL          |
|  4 | Дмитрий Козлов              |               |
|  5 | Ольга Смирнова              | NULL          |
+----+-----------------------------+---------------+
```

Здесь все три состояния необязательного столбца сразу. У Ивана телефон
есть. У Дмитрия стоит **пустая строка** `''` — значение есть, просто из
нуля символов (ячейка выглядит пустой, но это «есть»). У Анны, Марии и
Ольги стоит `NULL` — значения **нет**: не «пусто», не «ноль», а «ответа
на вопрос не существует». Для чисел картина та же: `price = 0` — «бесплатно»,
`price = NULL` — «цена неизвестна»; это разные дела, и путать их опасно.

| Запись | Что это | Когда уместно |
| ------ | ------- | ------------- |
| `NULL` | значения нет | телефон не спросили, цена неизвестна |
| `''` | пустая строка — значение | телефон спросили, ответили «никакого» |
| `0` | ноль — значение | товара бесплатно / в количестве ноль штук |

NULL — не «пустое значение», а отсутствие значения как такового. Именно
поэтому урок 6 разрешал `NOT NULL`-столбцам защищаться ошибкой 1048, а
строка `NULL` в `INSERT` означала «не заполняй» для счётчика и «нарушение»
для обязательных столбцов.

### Откуда NULL берётся и куда исчезает

Появляется отсутствие тремя путями, и все уже пройдены: пропустить
необязательный столбец в `INSERT` (урок 4); указать `NULL` явно в списке
значений; и третий, из урока 10, — стереть значение изменением:
`UPDATE customers SET phone = NULL WHERE id = 2;` читается «телефон
отменён». Если столбец под охраной `NOT NULL`, не пройдёт ни один путь —
знакомая ошибка 1048 (урок 6). Круг замкнулся: значение в необязательном
столбце можно задать, изменить и стереть — NULL полноправная часть жизни
данных.

### Сравнения молчат

Поищем всех, кроме Ивана:

```sql
SELECT name FROM customers WHERE phone <> '912-345-67-89';
```

```text
+-----------------+
| name            |
+-----------------+
| Дмитрий Козлов  |
+-----------------+
```

Дмитрий нашёлся: пустая строка — обычное значение, она «не равна»
Иванову телефону. А Анна, Мария и Ольга? Не вернулись — и это не ошибка
запроса, а главное правило NULL: **сравнение с NULL не даёт ни «да», ни
«нет» — оно даёт «неизвестно»**. А `WHERE`, вспомните урок 8, пропускает
в результат только строки, ответившие «да». «Неизвестно» — не «да»,
NULL-строки выпадают из любого сравнения: `=`, `<>`, `<`, `<=`, `>`, `>=` —
без разницы. Для наглядности — три возможных ответа на вопрос
`phone = '912-345-67-89'?`:

| Что в `phone`      | Ответ         | Пройдёт `WHERE`? |
| ------------------ | ------------- | ---------------- |
| сам этот номер     | да            | да               |
| другой номер       | нет           | нет              |
| NULL (телефона нет) | неизвестно   | нет              |

Самый контринтуитивный случай:

```sql
SELECT name FROM customers WHERE phone = NULL;
```

Пустой результат. Даже «NULL равен NULL» — «неизвестно»: два отсутствия
не равны и не неравны друг другу — их просто нет, сравнивать нечего.
Отсюда практический вывод: NULL невидим для операторов сравнения, и
«достать» его сравнением невозможно в принципе.

### IS NULL и IS NOT NULL

Раз сравнения бессильны, у NULL свой способ вопроса — без знака равенства:

```sql
SELECT name FROM customers WHERE phone IS NULL;
SELECT name FROM customers WHERE phone IS NOT NULL;
```

```text
+-----------------+     +-----------------+
| name            |     | name            |
+-----------------+     +-----------------+
| Анна Петрова    |     | Иван Сидоров    |
| Мария Волкова   |     | Дмитрий Козлов  |
| Ольга Смирнова  |     +-----------------+
+-----------------+
```

`IS NULL` — «значения нет?»; `IS NOT NULL` — «значение есть?». Обратите
внимание на Дмитрия во втором списке: пустая строка — это «есть». Форма
без знака — не каприз: `= NULL` не работает (предыдущий раздел), отсутствие
спрашивают конструкциями `IS NULL` и `IS NOT NULL`. Это пара к `NOT NULL` из урока 6 —
там ограничение требовало «чтобы было», здесь вопрос проверяет «а есть ли».

### NULL в сортировке

Обещание урока 9: куда встают NULL-строки? Проверяем:

```sql
SELECT name, phone FROM customers ORDER BY phone;
```

```text
+-----------------------------+---------------+
| name                        | phone         |
+-----------------------------+---------------+
| Анна Петрова                | NULL          |
| Мария Волкова               | NULL          |
| Ольга Смирнова              | NULL          |
| Дмитрий Козлов              |               |
| Иван Сидоров                | 912-345-67-89 |
+-----------------------------+---------------+
```

При сортировке по возрастанию NULL-строки идут первыми — раньше пустой
строки, раньше любого телефона; при `DESC` — соответственно последними.
Модель простая: в очереди сортировки «нет значения» стоит раньше любого
значения. Правило это — именно о расстановке, не о величине: в сравнениях
NULL по-прежнему «неизвестно», `NULL < 5` — не «да». Если NULL
мешает в верхушке списка — отфильтруйте его `IS NOT NULL` или подмените
следующим инструментом.

### COALESCE: первое настоящее значение

Показывать людям таблицу с NULL некрасиво: «телефон: NULL» — так не
говорят. Хочется: «телефон: не указан». Для замены отсутствия на
человекочитаемое — функция `COALESCE` (читается «коалэс», означает
«объединяет»): она возвращает **первый не-NULL** из своих аргументов:

```sql
SELECT name, COALESCE(phone, 'не указан') FROM customers;
```

```text
+-----------------------------+--------------------------------------+
| name                        | COALESCE(phone, 'не указан')         |
+-----------------------------+--------------------------------------+
| Анна Петрова                | не указан                            |
| Иван Сидоров                | 912-345-67-89                        |
| Мария Волкова               | не указан                            |
| Дмитрий Козлов              |                                      |
| Ольга Смирнова              | не указан                            |
+-----------------------------+--------------------------------------+
```

Читается: «телефон, а если его нет — "не указан"». Снова привет
различию: Дмитрий с пустой строкой остался с пустой строкой — его значение
«есть», COALESCE подменяет только NULL. Аргументов может быть несколько:
`COALESCE(phone, email, 'нет контактов')` — сначала телефон, при
отсутствии — email, нет и его — заглушка. И с числами так же:
`COALESCE(discount, 0)` — «скидка, если указана, иначе ноль» — типовая
заготовка, когда отсутствие числа мешает показать его людям. Заголовок
колонки в результате — просто текст выражения; как давать колонкам
красивые имена, покажет следующий уровень (псевдонимы).

### NULLIF: ноль, который хочет стать NULL

`COALESCE` превращает NULL в значение; `NULLIF(a, b)` — наоборот:
«верни `a`, если `a` не равно `b`, иначе NULL»:

```text
+--------------+--------------+--------------+
| NULLIF(0, 0) | NULLIF(5, 0) | NULLIF(5, 5) |
+--------------+--------------+--------------+
|         NULL |            5 |         NULL |
+--------------+--------------+--------------+
```

Зачем превращать значение в отсутствие? Классика — цена за штуку.
Демо-таблица раздела — партии товара: `products(name, price, quantity)`,
где `price` — цена всей партии, `quantity` — число штук в ней (в уроках 8
и 10 у `products` был складской `stock` — остаток склада, это другая
история). Считаем:

```sql
SELECT name, price, quantity, price / NULLIF(quantity, 0)
FROM products
ORDER BY id;
```

```text
+-----------------------------+----------+----------+-----------------------------+
| name                        | price    | quantity | price / NULLIF(quantity, 0) |
+-----------------------------+----------+----------+-----------------------------+
| Клавиатура механическая     |  4990.00 |       10 |                  499.000000 |
| Мышь беспроводная           |  1290.50 |        5 |                  258.100000 |
| Веб-камера                  |  2450.00 |        0 |                        NULL |
| Монитор 27"                 | 15990.00 |        3 |                  5330.000000 |
+-----------------------------+----------+----------+-----------------------------+
```

У веб-камеры количество — ноль, и делить нельзя. Просто `price /
quantity` в этом месте вернёт NULL, но с предупреждением 1365 `Division
by 0`. Хитрость с `NULLIF(quantity, 0)` превращает ноль в NULL **до**
деления: `2450 / NULL` — это «неизвестно», а не ошибка, и результат NULL
рождается без единого предупреждения. Семантика безупречна: там, где
количества нет, цены за штуку тоже нет. (Много знаков после запятой у
частного — это обычная дробь, а не поломка.)

### Когда без NULL лучше обойтись

Честность незнания не отменяет чувства меры: NULL — для «неизвестно» и
«неприменимо», а не для лени. Если у столбца есть осмыслённое нулевое
состояние — ноль штук на складе, пустая заметка — лучше хранить значение
или сразу задать `DEFAULT` (урок 6). Каждый необязательный столбец — это
все правила этого урока, которые придётся помнить при каждом запросе;
плодите их осознанно.

### Резюме

- NULL — отсутствие значения; не путать с пустой строкой `''` (значение
  есть) и с нулём `0` (значение есть).
- Сравнения `= <> < <= > >=` с NULL дают «неизвестно» — NULL-строки
  выпадают из любого сравнения; даже `NULL = NULL` — не «да».
- Искать отсутствие — только `IS NULL` / `IS NOT NULL`; пустая строка
  проходит в `IS NOT NULL`.
- При сортировке по возрастанию NULL — первые, при убывании — последние;
  правило расстановки, не сравнения: `NULL < 5` — по-прежнему «неизвестно».
- `COALESCE(a, b, …)` — первый не-NULL; подменяет отсутствие, не трогая
  пустые строки.
- `NULLIF(a, b)` — `a`, если `a ≠ b`, иначе NULL; `price / NULLIF(quantity, 0)`
  — честная «цена за штуку» без деления на ноль и без предупреждений.
- Вперёд: агрегаты и `COUNT` по NULL-строкам — следующий уровень; правила
  `NOT NULL` и 1048 — урок 6.

## Теоретические задания

### Вопрос 1: Чем NULL отличается от пустой строки `''`?

- ✅ NULL — значения нет вовсе; `''` — значение, состоящее из нуля символов
- ❌ ничем: это два способа записать «пусто» — error_text: это разные состояния: пустая строка — значение («телефон спросили, ответили "никакого"»), NULL — отсутствие значения («телефон не спрашивали»); их по-разному ищут и по-разному сортируют.
- ❌ NULL — это ноль для строковых столбцов — error_text: ноль — тоже значение: цена 0 — «бесплатно», цена NULL — «неизвестна»; NULL не является ни нулём, ни пустой строкой.

### Вопрос 2: `WHERE city <> 'Москва'` — попадут ли в результат строки с `city = NULL`?

- ✅ нет: сравнение с NULL даёт «неизвестно», а WHERE пропускает только «да»
- ❌ попадут: NULL ведь не равен «Москва» — error_text: логика соблазнительная, но NULL не участвует в сравнении: «не равно» с NULL — «неизвестно», а не «да»; NULL-строки выпадают из любого сравнения.
- ❌ сервер вернёт ошибку — error_text: ошибки нет: запрос корректен, просто NULL-строки молча не проходят фильтр — в этом и коварство.

### Вопрос 3: Как найти покупателей, у которых телефон не указан (phone может быть NULL)?

- ✅ `WHERE phone IS NULL`
- ❌ `WHERE phone = NULL` — error_text: сравнение с NULL никогда не даёт «да» — даже с самим NULL: запрос синтаксически корректен, но всегда возвращает пустой результат.
- ❌ `WHERE phone = ''` — error_text: так найдутся записи с пустой строкой — это значение, «телефон есть, но пустой»; отсутствие значения ищется только IS NULL.

### Вопрос 4: Что вернёт `COALESCE(phone, email, 'нет контактов')`, если phone = NULL, а email = 'anna@example.com'?

- ✅ anna@example.com — первый не-NULL аргумент
- ❌ нет контактов — error_text: заглушка достаётся только если NULL и телефон, и email; COALESCE идёт по списку до первого настоящего значения.
- ❌ NULL — error_text: NULL вернулся бы, только будь все аргументы NULL; здесь email — значение, оно и победит.

### Вопрос 5: `ORDER BY price` по возрастанию при нескольких строках с `price = NULL` — где окажутся NULL-строки?

- ✅ в самом начале результата: при сортировке по возрастанию MySQL ставит NULL раньше любого значения
- ❌ в самом конце — error_text: в конце NULL-строки оказываются при DESC; по возрастанию MySQL ставит «отсутствие значения» раньше любого значения — обещание урока 9 закрыто.
- ❌ сортировка с NULL невозможна — error_text: возможна и штатна: NULL участвует в сортировке наравне со всеми — при ASC его ставят первым, при DESC — последним.

### Задание 3: Цена за штуку

NULLIF в деле: деление без деления на ноль.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT name, price, quantity, price / NULLIF(quantity, 0) FROM products ORDER BY id; -->

**statement:**

Таблица `products` хранит партии товаров: цена партии и количество штук.
Выведите name, цену, количество и цену за штуку — столбец `price /
NULLIF(quantity, 0)`, — в порядке id. У товаров с нулевым количеством
цены за штуку нет: пусть будет NULL.

**expected_result_text:**

Финальный SELECT возвращает четыре строки: цена за штуку — частное от
деления (у него много знаков после запятой — это нормально), а у
веб-камеры с quantity = 0 — NULL: NULLIF превратил ноль в NULL до деления,
предупреждений нет.

**seed_sql:**

```sql
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(8,2) NOT NULL,
    quantity INT NOT NULL DEFAULT 0
);

INSERT INTO products (name, price, quantity) VALUES
    ('Клавиатура механическая', 4990.00, 10),
    ('Мышь беспроводная', 1290.50, 5),
    ('Веб-камера', 2450.00, 0),
    ('Монитор 27"', 15990.00, 3);
```

**expected_rows:**

| name                    | price    | quantity | price / NULLIF(quantity, 0) |
| ----------------------- | -------- | -------- | --------------------------- |
| Клавиатура механическая | 4990.00  | 10       | 499.000000                  |
| Мышь беспроводная       | 1290.50  | 5        | 258.100000                  |
| Веб-камера              | 2450.00  | 0        | NULL                        |
| Монитор 27"             | 15990.00 | 3        | 5330.000000                 |
