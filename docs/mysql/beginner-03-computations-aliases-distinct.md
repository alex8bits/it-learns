### SELECT умеет считать

До сих пор SELECT показывал столбцы таблицы как они есть: выбрали список,
отфильтровали `WHERE`, отсортировали `ORDER BY`. Но живые отчёты спрашивают
другое: «сколько стоит всё, что лежит на складе», «цена со скидкой», «имя
и город одной строкой», «в каких городах живут покупатели — без повторов».
В таблице таких данных нет — и не нужно: всё это вычисляется на лету,
прямо в списке SELECT. Сегодня он учится считать, давать столбцам имена,
склеивать строки и убирать повторы. И как всегда: всё перечисленное —
про результат; таблицу SELECT не меняет, как не менял её `WHERE` урока 8.

Кстати, зачем считать именно в SQL, а не в приложении, которое всё равно
обработает результат? Потому что сервер считает сразу над всеми строками
и отдаёт готовые числа: приложению не пришлось бы тащить цену и остаток
сотни товаров, чтобы перемножить их в цикле. «Данные фильтрует и считает
сервер, приложение показывает» — принцип курса с урока 8, когда фильтрацию
из электронной таблицы забрал WHERE; сегодня к фильтрации присоединяются
вычисления.

### Столбец из выражения

«Сколько стоит остаток каждого товара» — цена, умноженная на количество.
Такого столбца в таблице нет, но его можно собрать прямо в списке SELECT:

```sql
SELECT name, price, stock, price * stock
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+----------+-------+---------------+
| name                                          | price    | stock | price * stock |
+-----------------------------------------------+----------+-------+---------------+
| Коврик для мыши                               |   690.00 |    34 |      23460.00 |
| Мышь беспроводная                             |  1290.50 |    12 |      15486.00 |
| Клавиатура механическая                       |  4990.00 |     0 |          0.00 |
| Монитор 27"                                   | 15990.00 |     3 |      47970.00 |
| Кабель HDMI 2 м                               |   450.00 |    51 |      22950.00 |
| Веб-камера                                    |  2450.00 |    12 |      29400.00 |
+-----------------------------------------------+----------+-------+---------------+
```

Три наблюдения. Выражение — полноправный элемент списка: стоит со столбцами
через запятую. Вычисляется оно **построчно** — как `WHERE` задавал вопрос
каждой строке (урок 8 «Основ»), так выражение считается для каждой строки
отдельно; строк в результате ровно столько, сколько в таблице. И таблица не
изменилась: произведение живёт только в результате — это витрина, а не
`UPDATE` урока 10.

Заголовок колонки — просто текст выражения: `price * stock`. Знакомая
картинка: у COALESCE урока 11 заголовком была вся формула. Человекочитаемые
заголовки вернутся в разделе про `AS`.

Арифметика — привычная: `+ - * /`, скобки, школьный приоритет (умножение
сильнее сложения — как в логике урока 1 `AND` был сильнее `OR`, у каждого
набора операторов своя иерархия):

```sql
SELECT 2 + 3 * 4 AS без_скобок, (2 + 3) * 4 AS со_скобками;
```

```text
+------------+-------------+
| без_скобок | со_скобками |
+------------+-------------+
|         14 |          20 |
+------------+-------------+
```

В выражении смешиваются столбцы и литералы. «Цена со скидкой десять
процентов»:

```sql
SELECT name, price * 0.9 AS price_discounted
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+------------------+
| name                                          | price_discounted |
+-----------------------------------------------+------------------+
| Коврик для мыши                               |          621.000 |
| Мышь беспроводная                             |         1161.450 |
| Клавиатура механическая                       |         4491.000 |
| Монитор 27"                                   |        14391.000 |
| Кабель HDMI 2 м                               |          405.000 |
| Веб-камера                                    |         2205.000 |
+-----------------------------------------------+------------------+
```

Три знака после запятой — не поломка, а честность `DECIMAL`: у `price` два
знака, у литерала `0.9` — один, произведение хранит три (урок 5: деньги
точны до копейки и не теряют хвостов). Округлять будут функции урока 5
уровня; пока принимаем точность как есть.

Выражения живут не только в списке SELECT. То же произведение можно
использовать в WHERE — «товары, чей остаток стоит больше 20 тысяч»:

```sql
SELECT name, price * stock AS stock_value
FROM products
WHERE price * stock > 20000
ORDER BY id;
```

```text
+------------------------------+-------------+
| name                         | stock_value |
+------------------------------+-------------+
| Коврик для мыши              |    23460.00 |
| Монитор 27"                  |    47970.00 |
| Кабель HDMI 2 м              |    22950.00 |
| Веб-камера                   |    29400.00 |
+------------------------------+-------------+
```

Обратите внимание: в WHERE выражение написано целиком, по исходным
столбцам — почему псевдоним там не работает, разберём в разделе про AS.

### NULL и ноль: тонкости арифметики

Первое: **NULL заражает выражение**. `100 + NULL` — NULL. Правило урока 11
работает и в арифметике: неизвестное слагаемое — неизвестная сумма. Если бы
у части товаров цены не было, произведение у них тоже оказалось бы NULL.

Второе: деления — целых три оператора:

```sql
SELECT 5 / 2 AS обычное, 5 DIV 2 AS целое, 5 % 2 AS остаток;
```

```text
+---------+--------+---------+
| обычное | целое  | остаток |
+---------+--------+---------+
| 2.5000  |      2 |       1 |
+---------+--------+---------+
```

`/` не отбрасывает дробную часть: `5 / 2` — это 2.5000, а не 2. Нужна
только целая — берите `DIV`; остаток от деления — `%`. Практический пример
для `DIV`: «сколько полных пар товара можно собрать со склада»:

```sql
SELECT name, stock DIV 2 AS pairs
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+-------+
| name                                          | pairs |
+-----------------------------------------------+-------+
| Коврик для мыши                               |    17 |
| Мышь беспроводная                             |     6 |
| Клавиатура механическая                       |     0 |
| Монитор 27"                                   |     1 |
| Кабель HDMI 2 м                               |    25 |
| Веб-камера                                    |     6 |
+-----------------------------------------------+-------+
```

Третье: деление на ноль. Цена за штуку — `price / stock`, а у клавиатуры
`stock = 0`:

```sql
SELECT name, price / stock
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+---------------+
| name                                          | price / stock |
+-----------------------------------------------+---------------+
| Коврик для мыши                               |     20.294118 |
| Мышь беспроводная                             |    107.541667 |
| Клавиатура механическая                       |          NULL |
| Монитор 27"                                   |   5330.000000 |
| Кабель HDMI 2 м                               |      8.823529 |
| Веб-камера                                    |    204.166667 |
+-----------------------------------------------+---------------+
```

Не ошибка, а NULL — и предупреждение 1365 «Division by 0» в журнале:
сервер продолжает работу. (Длинные дробные хвосты у деления — снова
точность, а не поломка.) Лучший рецепт остаётся из урока 11:
`price / NULLIF(stock, 0)` — результат тот же, предупреждения нет, а
семантика честнее: где количества нет, цены за штуку нет.

### AS: имя для вычисленного столбца

Заголовок `price * stock` ещё терпим; `price / NULLIF(stock, 0)` в
заголовке — уже нет. Столбцу результата дают **псевдоним** — `AS имя`:

```sql
SELECT name AS товар, price цена
FROM products
ORDER BY id
LIMIT 2;
```

```text
+-----------------------------------+----------+
| товар                             | цена     |
+-----------------------------------+----------+
| Коврик для мыши                   |   690.00 |
| Мышь беспроводная                 |  1290.50 |
+-----------------------------------+----------+
```

Здесь сразу три факта. Кириллица в псевдонимах законна. Слово `AS`
можно опустить (`price цена` работает) — но без него соседние слова
выглядят как опечатка; стиль курса — всегда с `AS`. И псевдоним можно
давать не только выражению, но и обычному столбцу: `name AS товар`. И ещё:
псевдоним — имя колонки результата, а не таблицы. После запроса он
исчезает вместе с результатом; в следующий SELECT придётся написать
выражение заново. Записать вычисленное значение в таблицу — работа
операций изменения данных (уроки 4 и 10 «Основ»), а не SELECT:
сегодняшний урок ничего не записывает.

Если очень хочется пробел внутри имени — берите имя в обратные кавычки:

```sql
SELECT name, price * 0.9 AS `Цена со скидкой`
FROM products
ORDER BY id
LIMIT 2;
```

```text
+-----------------------------------+------------------------------+
| name                              | Цена со скидкой              |
+-----------------------------------+------------------------------+
| Коврик для мыши                   |                      621.000 |
| Мышь беспроводная                 |                     1161.450 |
+-----------------------------------+------------------------------+
```

Обратные кавычки в MySQL заключают «имена с капризами» — пробелами,
ключевыми словами. Работает, но проще жить без пробелов: `price_discounted`
читается не хуже, а кавычек не требует.

Псевдоним понятен `ORDER BY` — сортировать по вычисленному столбцу можно
по имени:

```sql
SELECT name, price * 0.9 AS discounted
FROM products
ORDER BY discounted DESC;
```

```text
+-----------------------------------------------+------------+
| name                                          | discounted |
+-----------------------------------------------+------------+
| Монитор 27"                                   |  14391.000 |
| Клавиатура механическая                       |   4491.000 |
| Веб-камера                                    |   2205.000 |
| Мышь беспроводная                             |   1161.450 |
| Коврик для мыши                               |    621.000 |
| Кабель HDMI 2 м                               |    405.000 |
+-----------------------------------------------+------------+
```

А вот `WHERE` псевдонима не видит. `WHERE discounted < 1000` закончится
ошибкой 1054 — unknown column: для `WHERE` столбца `discounted` не
существует. Почему так — отдельный разговор урока 6, там мы разберём
порядок выполнения SELECT; пока правило: псевдоним живёт в списке SELECT
и в `ORDER BY`, а в `WHERE` условие пишут по исходным столбцам таблицы.

### DISTINCT: без повторов

«В каких городах живут покупатели»:

```sql
SELECT city FROM customers ORDER BY city;
```

```text
+-----------------+
| city            |
+-----------------+
| Казань          |
| Москва          |
| Москва          |
| Новосибирск     |
| Санкт-Петербург |
+-----------------+
```

Пять строк, Москва — дважды: для списка городов повтор — мусор.
Модификатор `DISTINCT` убирает дубликаты:

```sql
SELECT DISTINCT city
FROM customers
ORDER BY city;
```

```text
+-----------------+
| city            |
+-----------------+
| Казань          |
| Москва          |
| Новосибирск     |
| Санкт-Петербург |
+-----------------+
```

Заметьте: `DISTINCT` — не функция, скобок нет; пишется сразу после
`SELECT`. И работает он по **всему списку**: `SELECT DISTINCT city, phone`
возвращает уникальные комбинации строки результата — схлопываются только
полностью совпавшие:

```sql
SELECT DISTINCT city, phone
FROM customers
ORDER BY city;
```

```text
+-----------------+---------------+
| city            | phone         |
+-----------------+---------------+
| Казань          | 912-345-67-89 |
| Москва          | NULL          |
| Новосибирск     | NULL          |
| Санкт-Петербург |               |
+-----------------+---------------+
```

Четыре строки вместо пяти: две московские слились — у обеих город Москва
и телефон NULL, а несколько NULL в списке DISTINCT схлопываются в один.
Это правило группировки, не сравнения: `NULL = NULL` по-прежнему
«неизвестно» (урок 11) — DISTINCT просто не размножает неразличимые
строки. А `(Новосибирск, NULL)` от `(Москва, NULL)` отличается — город
другой. Частая ошибка — ждать от `DISTINCT` «уникальности по первому
столбцу»: он дедуплицирует строку результата целиком, сколько бы столбцов
ни было в списке. Со выражениями работает так же — `SELECT DISTINCT
price * 0.9` покажет, какие скидочные цены вообще встречаются; а «сколько
уникальных» — это уже подсчёт, `COUNT` урока 8.

### Конкатенация: строки вместе

«Имя и город одной строкой» — «Анна Петрова (Москва)». Склеивание строк
называется конкатенацией, и делает его функция `CONCAT` — первая функция
курса. Функция — это имя со скобками, в скобках аргументы через запятую;
`CONCAT` принимает их сколько угодно и возвращает одну строку — все
аргументы подряд:

```sql
SELECT CONCAT(name, ' (', city, ')') AS buyer
FROM customers
ORDER BY id;
```

```text
+---------------------------------+
| buyer                           |
+---------------------------------+
| Анна Петрова (Москва)           |
| Иван Сидоров (Казань)           |
| Мария Волкова (Москва)          |
| Дмитрий Козлов (Санкт-Петербург)|
| Ольга Смирнова (Новосибирск)    |
+---------------------------------+
```

Аргументы — столбцы, литералы, выражения — вперемешку. Числа приводятся
к строке сами:

```sql
SELECT CONCAT('К оплате: ', price * stock) AS line
FROM products
ORDER BY id
LIMIT 3;
```

```text
+---------------------+
| line                |
+---------------------+
| К оплате: 23460.00  |
| К оплате: 15486.00  |
| К оплате: 0.00      |
+---------------------+
```

И главная тонкость — NULL, правило урока 11 на новом месте: **если хоть
один аргумент CONCAT — NULL, весь результат NULL**. Склеим имя с
телефоном:

```sql
SELECT CONCAT(name, ' — ', phone) AS contact
FROM customers
ORDER BY id;
```

```text
+--------------------------------+
| contact                        |
+--------------------------------+
| NULL                           |
| Иван Сидоров — 912-345-67-89   |
| NULL                           |
| Дмитрий Козлов —               |
| NULL                           |
+--------------------------------+
```

У Анны, Марии и Ольги — NULL: телефона нет, «неизвестное» утаскивает всю
склейку. У Дмитрия хвост пуст — его phone, пустая строка, склеилась как
пустая: она значение, а не отсутствие (урок 11: `''` ≠ NULL). Разница
налицо: пустая строка оставляет конструкцию целой, NULL ломает всю
склейку. Мешает — выручает знакомый COALESCE:
`CONCAT(name, ' — ', COALESCE(phone, 'не указан'))`.

Со строками мы теперь умеем главное — склеивать; полный строковый
инструментарий (UPPER, SUBSTRING, TRIM, REPLACE, LENGTH) — следующий урок.

### Всё вместе

Витрина «что лежит в аксессуарах и периферии дороже пятисота»:

```sql
SELECT CONCAT(name, ': ', price * stock) AS stock_line
FROM products
WHERE category_id IN (1, 2) AND price > 500
ORDER BY id;
```

```text
+---------------------------------+
| stock_line                      |
+---------------------------------+
| Коврик для мыши: 23460.00       |
| Мышь беспроводная: 15486.00     |
| Клавиатура механическая: 0.00   |
| Веб-камера: 29400.00            |
+---------------------------------+
```

Считаем (сегодня), называем (`AS`), фильтруем (`IN` — урок 2, `AND` —
урок 1), выводим строкой (`CONCAT`), сортируем (урок 9 «Основ»).

### Чего в этом уроке нет

- строковые функции — UPPER, LOWER, SUBSTRING, TRIM, REPLACE, LENGTH —
  урок 4;
- функции чисел и дат — ROUND, NOW, DATEDIFF и другие — урок 5;
- почему псевдоним из SELECT не виден в WHERE — порядок выполнения
  SELECT, урок 6;
- COUNT и подсчёт «сколько уникальных» — урок 8.

### Резюме

- Выражение в списке SELECT — полноправный столбец результата:
  `+ - * /`, скобки, литералы; вычисляется построчно, таблицу не меняет;
  заголовок — текст выражения. Работает и в WHERE/ORDER BY — но пишется
  там по исходным столбцам, без псевдонима.
- NULL в арифметике заражает выражение; деление на ноль — NULL
  с предупреждением 1365; честный щит — `NULLIF(stock, 0)` (урок 11).
- `/` не отбрасывает дробную часть (2.5000); целая — `DIV`; остаток — `%`.
- `AS` даёт столбцу имя: кириллица можно, пробел — в обратных кавычках;
  псевдоним работает в `ORDER BY`, а в `WHERE` невидим — ошибка 1054,
  почему — урок 6.
- `DISTINCT` убирает повторы; по нескольким столбцам — уникальные
  комбинации, несколько NULL дают одну строку — правило группировки,
  не сравнения; это модификатор, а не функция.
- `CONCAT` склеивает аргументы (числа приводятся сами); NULL в любом
  аргументе — весь результат NULL; пустая строка склеивается как пустая.

## Теоретические задания

### Вопрос 1: `SELECT name, price * stock FROM products;` — что делает запрос?

- ✅ выводит каждый товар и произведение его цены на остаток отдельным столбцом
<!-- выражение вычисляется построчно: строк в результате столько же, сколько в таблице -->
- ❌ считает общую стоимость всех товаров одной строкой — error_text: это работа агрегатных функций (SUM и COUNT — урок 8); выражение в списке SELECT считается для каждой строки отдельно, а не один раз по всей таблице.
- ❌ записывает произведение в таблицу — error_text: SELECT ничего не пишет: выражение живёт только в результате; изменение данных — UPDATE урока 10.
- ❌ выводит только товары с ненулевым остатком — error_text: фильтрация — работа WHERE; без WHERE в результат попадают все строки, включая клавиатуру с произведением 0.00.

### Вопрос 2: `SELECT name, price / stock FROM products;` — что вернёт запрос для клавиатуры (stock = 0)?

- ✅ NULL в колонке выражения, с предупреждением «Division by 0»
<!-- деление на ноль в SELECT — не ошибка, а NULL с предупреждением 1365 -->
- ❌ ошибку: запрос не выполнится — error_text: запрос выполнится: деление на ноль возвращает NULL с предупреждением 1365, но не останавливает выполнение.
- ❌ 0 — error_text: ноль был бы значением, а деления на ноль не существует; MySQL отвечает NULL — «неизвестно» (правило урока 11).
- ❌ строка клавиатуры выпадет из результата — error_text: SELECT не выбрасывает строки: строка останется, в колонке выражения будет NULL; убирать строки умеет только WHERE.

### Вопрос 3: `SELECT name, price * 0.9 AS discounted FROM products WHERE discounted < 1000;` — что произойдёт?

- ✅ сервер вернёт ошибку 1054
<!-- для WHERE столбца discounted не существует: алиас из списка SELECT нельзя использовать в WHERE того же запроса; причина — порядок выполнения SELECT, урок 6 -->
- ❌ запрос вернёт товары со скидочной ценой ниже 1000 — error_text: так работал бы запрос с условием по исходным данным: WHERE price * 0.9 < 1000; псевдоним в WHERE того же запроса не виден.
- ❌ ошибка синтаксиса около AS — error_text: синтаксически запрос корректен; сервер споткнётся не об AS, а о discounted — неизвестный столбец, 1054.
- ❌ сервер молча проигнорирует условие — error_text: невидимый псевдоним — ошибка, а не тихий пропуск: запрос не выполнится вовсе.

### Вопрос 4: В таблице 5 покупателей, двое из них из Москвы. Что вернёт `SELECT DISTINCT city FROM customers;`?

- ✅ 4 строки, Москва один раз
<!-- дубликаты значений схлопываются: две московские строки дают одну -->
- ❌ 5 строк: Москва — дважды — error_text: именно повторы DISTINCT и убирает: одинаковые значения списка схлопываются в одну строку результата.
- ❌ по одной полной строке покупателя на город, с именами — error_text: список SELECT определяет столбцы результата — здесь только city; DISTINCT дедуплицирует значения списка, а не строки таблицы со всеми столбцами.
- ❌ ошибку: DISTINCT требует скобок — error_text: DISTINCT — не функция, а модификатор SELECT: пишется без скобок, сразу после SELECT.

### Вопрос 5: `SELECT CONCAT(name, ' — ', phone) FROM customers;` — у Анны phone = NULL. Что будет в её строке результата?

- ✅ NULL
<!-- если хоть один аргумент CONCAT — NULL, весь результат NULL -->
- ❌ Анна Петрова — NULL — error_text: NULL не превращается в текст «NULL»: отсутствие значения заражает всю склейку — результат NULL целиком, а не строка с упоминанием NULL.
- ❌ Анна Петрова — (пустой хвост) — error_text: пустой хвост вышел бы у пустой строки '' — она значение и склеивается как пустая; NULL — не строка, а отсутствие значения.
- ❌ её строка выпадет из результата — error_text: SELECT не выбрасывает строки: строка Анны останется в результате, но в колонке будет NULL.
