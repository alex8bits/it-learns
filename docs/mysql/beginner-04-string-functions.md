### Грязные данные и чистый вывод

Урок 3 познакомил с первой функцией курса — `CONCAT` — и пообещал:
«полный строковый инструментарий — следующий урок». Выполняем.

Зачем нужен инструментарий? Демо-таблицы курса до сих пор были ухоженными.
Реальные данные так не выглядят: они приходят из форм, импортов и рук —
с пробелами по краям, капсом вперемешку с нижним регистром, двойными
пробелами внутри, дефисами в телефонах там, где нужны цифры. Строковые
функции закрывают две задачи: **чистку** (привести кривое к единому виду)
и **форматирование** (показать аккуратно людям). Всё, что урок 3 сказал
про выражения, относится к функциям дословно: вычисляются построчно,
живут в списке SELECT, в WHERE и ORDER BY, таблицу не меняют,
человекочитаемый заголовок — через `AS`.

И вилка, которую стоит проговорить сразу: чистить **вывод** или чинить
**сами данные**? Если кривые данные мешают всем и навсегда — рано или
поздно их исправят в таблице (UPDATE, урок 10 «Основ»). Если кривой
оказалась одна выгрузка — чистим на лету, таблицу не трогаем: сегодня
работаем только так.

### Актёры урока

Каталог и покупатели прежние. Новичок — таблица подписчиков рассылки,
записанных «как попало»:

```sql
SELECT id, CONCAT('[', name, ']') AS имя_в_скобках, email
FROM subscribers
ORDER BY id;
```

```text
+----+---------------------------------+----------------+
| id | имя_в_скобках                   | email          |
+----+---------------------------------+----------------+
|  1 | [  Анна Петрова  ]              | anna@mail.ru   |
|  2 | [ ИВАН СИДОРОВ]                 | ivan@mail.ru   |
|  3 | [мария волкова  ]               | maria@mail.ru  |
|  4 | [Дмитрий  Козлов]               | dmitry@mail.ru |
|  5 | [  Ольга Смирнова]              | olga@mail.ru   |
+----+---------------------------------+----------------+
```

Обратите внимание на приём: пробелы по краям значения невидимы, поэтому
мы заключили имя в скобки через `CONCAT('[', name, ']')` — теперь края
видны как на ладони. Приём стоит взять на вооружение: это способ
«подсвечить» невидимые символы при отладке любых данных.

### UPPER и LOWER: единый регистр

`UPPER` поднимает регистр строки, `LOWER` опускает:

```sql
SELECT name, UPPER(name) AS up, LOWER(name) AS low
FROM subscribers
ORDER BY id;
```

```text
+-------------------------------+-------------------------------+-------------------------------+
| name                          | up                            | low                           |
+-------------------------------+-------------------------------+-------------------------------+
|   Анна Петрова                |   АННА ПЕТРОВА                |   анна петрова                |
|  ИВАН СИДОРОВ                 |  ИВАН СИДОРОВ                 |  иван сидоров                 |
| мария волкова                 | МАРИЯ ВОЛКОВА                 | мария волкова                 |
| Дмитрий  Козлов               | ДМИТРИЙ  КОЗЛОВ               | дмитрий  козлов               |
|   Ольга Смирнова              |   ОЛЬГА СМИРНОВА              |   ольга смирнова              |
+-------------------------------+-------------------------------+-------------------------------+
```

Три наблюдения. Функция меняет вывод, не данные: в таблице «ИВАН
СИДОРОВ» остался капсом. Кириллица — полноценный участник: UPPER и LOWER
умеют и русский алфавит. И — смотрите на Анну — регистр сменился, а
пробелы по краям остались: у каждой функции своя работа, одна другую не
заменяет.

Наверное, вы помните из урока 8 «Основ», что сравнения строк регистр не
различают (collation). Зачем тогда UPPER и LOWER? Для единообразия
вывода: «АННА ПЕТРОВА» и «анна петрова» в одной выгрузке — бардак, а
сравнение «бардак не видит». Когда регистр действительно важен при
сравнении — это разговор о коллациях, продвинутый уровень.

### TRIM: срезать края — и только края

`TRIM` срезает пробелы слева и справа от строки:

```sql
SELECT CONCAT('[', name, ']') AS до, CONCAT('[', TRIM(name), ']') AS после
FROM subscribers
ORDER BY id;
```

```text
+---------------------------------+--------------------------------+
| до                              | после                          |
+---------------------------------+--------------------------------+
| [  Анна Петрова  ]              | [Анна Петрова]                 |
| [ ИВАН СИДОРОВ]                 | [ИВАН СИДОРОВ]                 |
| [мария волкова  ]               | [мария волкова]                |
| [Дмитрий  Козлов]               | [Дмитрий  Козлов]              |
| [  Ольга Смирнова]              | [Ольга Смирнова]               |
+---------------------------------+--------------------------------+
```

Четыре имени очистились. А Дмитрий — нет: его двойной пробел стоит
**внутри** строки, а TRIM работает только по краям. Сколько бы пробелов
ни было слева и справа — срежутся все; внутренние неприкосновенны. Для
них нужен следующий инструмент. (Есть и вариации: LTRIM — только слева,
RTRIM — только справа; полный TRIM — оба края.)

### REPLACE: найти и заменить

`REPLACE(строка, что_искать, на_что_заменить)` заменяет **все** вхождения
подстроки. Двойной пробел Дмитрия — вот его работа:

```sql
SELECT CONCAT('[', REPLACE(TRIM(name), '  ', ' '), ']') AS fixed
FROM subscribers
ORDER BY id;
```

```text
+-------------------------------+
| fixed                         |
+-------------------------------+
| [Анна Петрова]                |
| [ИВАН СИДОРОВ]                |
| [мария волкова]               |
| [Дмитрий Козлов]              |
| [Ольга Смирнова]              |
+-------------------------------+
```

Заметили? Внутри уже стоит конвейер: сначала TRIM срезал края, потом
REPLACE схлопнул двойной пробел — об этой вложенности отдельный раздел
ниже. Второй классический сюжет для REPLACE — **удаление** лишнего:
замена на пустую строку вырезает найденное. Дефисы из телефона:

```sql
SELECT name, phone, REPLACE(phone, '-', '') AS digits
FROM customers
WHERE phone IS NOT NULL
ORDER BY id;
```

```text
+-----------------------------+---------------+------------+
| name                        | phone         | digits     |
+-----------------------------+---------------+------------+
| Иван Сидоров                | 912-345-67-89 | 9123456789 |
| Дмитрий Козлов              |               |            |
+-----------------------------+---------------+------------+
```

У Ивана дефисы вырезаны — «замена на ничего» сработала как удаление. У
Дмитрия телефон — пустая строка: REPLACE от пустой возвращает пустую
(пустая строка — значение, урок 11). NULL-строки отфильтрованы `IS NOT
NULL` — не потому, что функциям нельзя отдавать NULL (можно, и ответом
будет NULL — об этом ниже), а потому, что примеру нужны настоящие
телефоны.

Кстати, сравните два способа борьбы с пробелами: TRIM срезает пробелы
только по краям, а REPLACE(name, ' ', '') вырежет вообще все — и края,
и внутренние. «Убрать только края» и «убрать все» — разные задачи, и
инструменты под них разные. REPLACE годится и для маскировки:
REPLACE(email, '@mail.ru', '@***') — скрыть домен в выгрузке логов,
не трогая таблицу.

### SUBSTRING: вырезать кусок

`SUBSTRING(строка, позиция, длина)` вырезает из строки кусок, начиная с
`позиция`, длиной `длина` символов. Главная ловушка — нумерация: **позиции
начинаются с 1**, не с 0, как привыкли многие языки программирования:

```sql
SELECT name, SUBSTRING(name, 1, 3) AS first3, SUBSTRING(name, 2, 3) AS from2
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+--------+--------+
| name                                          | first3 | from2  |
+-----------------------------------------------+--------+--------+
| Коврик для мыши                               | Ков    | овр    |
| Мышь беспроводная                             | Мыш    | ышь    |
| Клавиатура механическая                       | Кла    | лав    |
| Монитор 27"                                   | Мон    | они    |
| Кабель HDMI 2 м                               | Каб    | абе    |
| Веб-камера                                    | Веб    | еб-    |
+-----------------------------------------------+--------+--------+
```

`SUBSTRING(name, 1, 3)` — «первые три символа» (позиция 1, длина 3).
`SUBSTRING(name, 2, 3)` — «три символа, начиная со второго»: «овр» у
коврика. А что не работает — так это позиция 0: она не «первая», а
«до первой»:

```sql
SELECT SUBSTRING('MySQL', 0, 3) AS zero_pos, SUBSTRING('MySQL', -3) AS negative_pos;
```

```text
+----------+--------------+
| zero_pos | negative_pos |
+----------+--------------+
|          | SQL          |
+----------+--------------+
```

Позиция 0 даёт пустую строку — не первый символ. Отрицательная позиция —
экзотика, но полезная: отсчёт с конца (`-3` — «начиная с третьего с
конца, до конца»). Третий аргумент можно опустить — тогда вырезается всё
до конца строки: `SUBSTRING('MySQL', 3)` — это `SQL`.

### LENGTH и CHAR_LENGTH: байты против символов

`LENGTH` возвращает длину строки — и вот главный подвох дня: **в
байтах, а не в символах**. Кириллица в кодировке utf8mb4 (урок 5 «Основ»)
занимает два байта на букву:

```sql
SELECT 'Анна' AS s, LENGTH('Анна') AS байты, CHAR_LENGTH('Анна') AS символы;
```

```text
+------+-------+----------+
| s    | байты | символы  |
+------+-------+----------+
| Анна |     8 |        4 |
+------+-------+----------+
```

Четыре буквы — восемь байт. Посчитать именно символы умеет соседняя
функция — `CHAR_LENGTH`. Разница видна на каждом кириллическом названии:

```sql
SELECT name, LENGTH(name) AS байты, CHAR_LENGTH(name) AS символы
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+-------+----------+
| name                                          | байты | символы  |
+-----------------------------------------------+-------+----------+
| Коврик для мыши                               |    28 |       15 |
| Мышь беспроводная                             |    33 |       17 |
| Клавиатура механическая                       |    45 |       23 |
| Монитор 27"                                   |    18 |       11 |
| Кабель HDMI 2 м                               |    22 |       15 |
| Веб-камера                                    |    19 |       10 |
+-----------------------------------------------+-------+----------+
```

«Кабель HDMI 2 м»: латиница и цифры — по байту, кириллица — по два:
15 символов, 22 байта. Какую функцию брать: правило простое. Ограничение
«не длиннее 10 **символов**», длина для людей — `CHAR_LENGTH`; размер
хранимых данных в байтах — `LENGTH`. В уроках и задачах курса почти
всегда имеется в виду первая.

Крайние случаи для полной картины: у латиницы и цифр байт и символ —
одно и то же (`LENGTH('HDMI')` = `CHAR_LENGTH('HDMI')` = 4), а длина
пустой строки — честный ноль: `LENGTH('')` = 0. Ноль и NULL — по-прежнему
разные истории (урок 11): ноль — «строка есть, она пустая», NULL —
«строки нет».

### Композиция: функции внутри функций

Результат функции — такое же значение, как столбец или литерал. Значит,
его можно отдать другой функции. В арифметике урока 3 выражение читалось
изнутри наружу — `(2 + 3) * 4`: сначала скобки, потом умножение. С
функциями так же. «Складской код: первые три символа названия в верхнем
регистре, дефис и номер»:

```sql
SELECT name, CONCAT(UPPER(SUBSTRING(name, 1, 3)), '-', id) AS code
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+----------+
| name                                          | code     |
+-----------------------------------------------+----------+
| Коврик для мыши                               | КОВ-1    |
| Мышь беспроводная                             | МЫШ-2    |
| Клавиатура механическая                       | КЛА-3    |
| Монитор 27"                                   | МОН-4    |
| Кабель HDMI 2 м                               | КАБ-5    |
| Веб-камера                                    | ВЕБ-6    |
+-----------------------------------------------+----------+
```

Читаем с самого внутреннего: `SUBSTRING(name, 1, 3)` вырезал «Ков»,
`UPPER` поднял регистр — «КОВ», `CONCAT` приклеил дефис и id — «КОВ-1».

Полный конвейер чистки имени подписчика: срезать края, схлопнуть двойные
пробелы, первую букву — заглавной, остальное — нижним:

```sql
SELECT
    CONCAT(UPPER(SUBSTRING(REPLACE(TRIM(name), '  ', ' '), 1, 1)),
           LOWER(SUBSTRING(REPLACE(TRIM(name), '  ', ' '), 2))) AS imya
FROM subscribers
ORDER BY id;
```

```text
+-----------------------------+
| imya                        |
+-----------------------------+
| Анна петрова                |
| Иван сидоров                |
| Мария волкова               |
| Дмитрий козлов              |
| Ольга смирнова              |
+-----------------------------+
```

Честная оговорка: фамилия вышла строчной — «первая буква заглавная,
остальное нижним» так и работает. Сделать заглавной **каждое** слово
сложнее: для этого нужно найти пробелы внутри строки, а поиска подстроки
в нашем наборе функций нет. В реальных системах такую чистку делают
приложением или заранее, при загрузке данных.

И про читаемость: вложенность глубже двух-трёх уровней читать тяжело —
глаза путаются в скобках. В сегодняшних примерах мы терпели; настоящие
запросы разбивают такие башни на шаги с промежуточными выборками — эти
инструменты ждут в среднем уровне, а пока просто не гонитесь за глубиной.

### Функции — обычные выражения

Всё, что урок 3 говорил про выражения, работает для функций наравне с
арифметикой. Фильтр по вычисленному — в WHERE:

```sql
SELECT name, CHAR_LENGTH(name) AS символы
FROM products
WHERE CHAR_LENGTH(name) > 12
ORDER BY id;
```

```text
+-----------------------------------------------+----------+
| name                                          | символы  |
+-----------------------------------------------+----------+
| Коврик для мыши                               |       15 |
| Мышь беспроводная                             |       17 |
| Клавиатура механическая                       |       23 |
| Кабель HDMI 2 м                               |       15 |
+-----------------------------------------------+----------+
```

ORDER BY понимает и функцию, и псевдоним (`ORDER BY символы` — урок 3).
Псевдонимы через AS — как раньше. Сортировка по длине названия — от
коротких к длинным:

```sql
SELECT name, CHAR_LENGTH(name) AS symb
FROM products
ORDER BY CHAR_LENGTH(name), id;
```

```text
+-----------------------------------------------+------+
| name                                          | symb |
+-----------------------------------------------+------+
| Веб-камера                                    |   10 |
| Монитор 27"                                   |   11 |
| Коврик для мыши                               |   15 |
| Кабель HDMI 2 м                               |   15 |
| Мышь беспроводная                             |   17 |
| Клавиатура механическая                       |   23 |
+-----------------------------------------------+------+
```

У двух товаров длина одинаковая — 15 символов; вторым ключом стоит id,
чтобы порядок при равных длинах был предсказуемым: детерминизм урока 9
работает и с функциями. И NULL: любая функция, получившая
NULL, вернёт NULL — «неизвестное» на входе даёт «неизвестное» на выходе
(урок 11; то же показал CONCAT урока 3):

```sql
SELECT LENGTH(NULL) AS l, UPPER(NULL) AS u;
```

```text
+------+------+
| l    | u    |
+------+------+
| NULL | NULL |
+------+------+
```

Если NULL мешает — по-прежнему выручает COALESCE. И напоследок граница:
функция **над столбцом** в WHERE (как `CHAR_LENGTH(name) > 12`) заставляет
сервер вычислить её для каждой строки — индекс тут не помощник, как и у
ведущего `%` урока 2; подробности — продвинутый уровень.

### Резюме

- UPPER / LOWER — единый регистр вывода; сравнения и так нечувствительны
  к регистру (collation, урок 8).
- TRIM срезает пробелы по краям — только по краям: двойной пробел внутри
  остаётся; LTRIM/RTRIM — односторонние варианты.
- REPLACE(строка, что, на что) заменяет все вхождения; замена на пустую
  строку — удаление.
- SUBSTRING(строка, позиция, длина): позиции с 1; позиция 0 — пустая
  строка; без длины — до конца; отрицательная позиция — с конца.
- LENGTH — байты (кириллица utf8mb4 — по два на букву), CHAR_LENGTH —
  символы; для «длины для людей» — CHAR_LENGTH.
- Функции вкладываются друг в друга, порядок чтения — изнутри наружу,
  как скобки в арифметике.
- Функция — обычное выражение: SELECT, WHERE, ORDER BY, AS; NULL на
  входе — NULL на выходе; таблицу не меняют.

## Теоретические задания

### Вопрос 1: Что вернёт `SUBSTRING('Клавиатура', 2, 3)`?

- ✅ лав
<!-- позиция 2 — второй символ «л» (нумерация с 1), длина 3: «лав» -->
- ❌ Кла — error_text: так было бы при нумерации с нуля; в MySQL строки нумеруются с 1, и позиция 2 — это второй символ, «л».
- ❌ ав — error_text: длина — второй аргумент, здесь 3: вырезаются «лав»; «ав» получилось бы при длине 2.
- ❌ пустую строку — error_text: пустую строку вернула бы позиция 0 — «до первого символа» (так работает SUBSTRING('MySQL', 0, 3)), но не позиция 2.

### Вопрос 2: Кодировка utf8mb4. Что вернёт `LENGTH('Анна')`?

- ✅ 8
<!-- LENGTH считает байты, кириллица в utf8mb4 — по два байта на букву -->
- ❌ 4 — error_text: 4 — это CHAR_LENGTH: символов четыре, но LENGTH меряет байты, а кириллическая буква занимает два.
- ❌ и 4, и 8 — без кодировки функция не определена — error_text: функция определена всегда: LENGTH возвращает байты значения в его кодировке (в курсе это utf8mb4); неоднозначности нет.
- ❌ 2 — error_text: 2 — это количество байтов на один кириллический символ, а не длина строки из четырёх букв.

### Вопрос 3: В строке 'Дмитрий␣␣Козлов' двойной пробел внутри. Что вернёт `TRIM` от этой строки?

- ✅ ту же строку с двойным пробелом внутри
<!-- TRIM срезает пробелы только по краям, внутренние не трогает -->
- ❌ строку с одинарным пробелом — error_text: TRIM работает только по краям; внутренние двойные пробелы схлопывает REPLACE(строка, '  ', ' ').
- ❌ строку вовсе без пробелов — error_text: TRIM не трогает внутренние символы, даже лишние; удалить пробелы можно REPLACE(строка, ' ', ''), но это уже не TRIM.
- ❌ ошибку: двойной пробел внутри строки запрещён — error_text: двойной пробел — законное содержимое строки; TRIM выполнится спокойно, просто не заметив его внутри.

### Вопрос 4: Что вернёт `LENGTH(NULL)`?

- ✅ NULL
<!-- NULL на входе функции — NULL на выходе: правило урока 11, как у CONCAT урока 3 -->
- ❌ 0 — error_text: ноль был бы значением — «длина пустой строки» (LENGTH('') действительно 0); NULL — отсутствие значения, и функция честно отвечает NULL.
- ❌ ошибку — error_text: ошибки нет: функции спокойно принимают NULL и возвращают NULL — молча, без сбоя.
- ❌ пустую строку — error_text: LENGTH возвращает число, а не строку; пустая строка тут даже не того типа, NULL — единственный честный ответ про длину отсутствующего.

### Вопрос 5: Что вернёт `REPLACE('912-345-67-89', '-', '')`?

- ✅ 9123456789
<!-- замена на пустую строку удаляет все вхождения дефиса -->
- ❌ 912 345 67 89 — error_text: дефисы заменились бы пробелами, если бы третьим аргументом стояла строка с пробелом; здесь третий аргумент — пустая строка, «ничего».
- ❌ исходную строку без изменений — error_text: REPLACE с пустой заменой — штатный способ удалить подстроку: найденные дефисы заменяются на «ничего».
- ❌ ошибку: пустая строка в REPLACE запрещена — error_text: пустая строка — законное значение (урок 11); заменять «на ничего» можно, именно так и удаляют.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT name, UPPER(name) AS name_upper FROM products ORDER BY id; -->

### Задание 2: Чистка подписчиков

Краевые пробелы — срезать, двойные внутри — схлопнуть.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT REPLACE(TRIM(name), '  ', ' ') AS clean_name FROM subscribers ORDER BY id; -->

**statement:**

Таблица `subscribers` хранит имена подписчиков, записанные неаккуратно:
лишние пробелы по краям и двойные пробелы внутри. Подготовьте выгрузку
имён: срежьте пробелы по краям и замените двойные пробелы одинарными —
один столбец `clean_name`, в порядке id. Регистр не трогайте.

**expected_result_text:**
