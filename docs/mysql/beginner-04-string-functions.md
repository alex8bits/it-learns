В прошлом уроке мы познакомились с `CONCAT` — функцией, которая склеивает несколько строк в одну. Это лишь одна из большого набора **строковых функций** MySQL — готовых инструментов для обработки текста прямо внутри SQL-запроса, без необходимости выгружать данные и обрабатывать их в отдельной программе. В этом уроке разберём самые часто используемые: смену регистра, извлечение подстроки, удаление лишних пробелов, замену фрагментов и подсчёт длины текста.

### UPPER и LOWER: смена регистра

Функции `UPPER` и `LOWER` переводят текст в верхний и нижний регистр соответственно:

```sql
SELECT name, UPPER(name) AS name_upper, LOWER(name) AS name_lower
FROM products;
```

Для `name = 'Мышь беспроводная'` `UPPER(name)` вернёт `'МЫШЬ БЕСПРОВОДНАЯ'`, а `LOWER(name)` — `'мышь беспроводная'`. Обе функции корректно работают и с кириллицей при кодировке `utf8mb4`, знакомой нам из пятого урока «Основ». Практическое применение таких функций — не только оформление вывода: приведение к единому регистру часто используется для **регистронезависимого сравнения** значений, если реальные настройки сравнения (collation) столбца по какой-то причине чувствительны к регистру:

```sql
SELECT name
FROM products
WHERE LOWER(category) = LOWER('периферия');
```

Такая запись гарантированно найдёт совпадение независимо от того, как именно был введён регистр в данных или в самом условии.

### LENGTH и CHAR_LENGTH: длина строки в байтах и в символах

Функция `LENGTH` возвращает длину строки в **байтах**, а `CHAR_LENGTH` (синоним — `CHARACTER_LENGTH`) — длину в **символах**. Для строк из одних латинских букв и цифр в кодировке `utf8mb4` эти два числа совпадают, потому что каждый такой символ занимает ровно один байт:

```sql
SELECT LENGTH('KB-001'), CHAR_LENGTH('KB-001');
-- оба вернут 6
```

Но для кириллицы и многих других не-латинских алфавитов в `utf8mb4` каждый символ занимает **несколько байт** (обычно 2 байта для кириллицы), и числа начинают различаться:

```sql
SELECT LENGTH('Мышь'), CHAR_LENGTH('Мышь');
-- LENGTH вернёт 8 (4 символа × 2 байта), CHAR_LENGTH вернёт 4
```

Это различие — не случайность и не ошибка, а прямое следствие того, что `utf8mb4` — переменная по числу байт на символ кодировка (о ней шла речь в пятом уроке «Основ»). Практический вывод простой: если нужно узнать, **сколько символов** видит человек, глядя на строку (например, для проверки «название товара не длиннее 50 символов»), нужно использовать `CHAR_LENGTH`, а не `LENGTH`; `LENGTH` больше пригождается, когда важен именно объём хранимых данных в байтах, например, при анализе объёма занимаемого места.

```sql
SELECT name, CHAR_LENGTH(name) AS name_length
FROM products
WHERE CHAR_LENGTH(name) > 20;
```

### SUBSTRING: извлечение части строки

Функция `SUBSTRING` (доступен и более короткий синоним `SUBSTR`) извлекает часть строки, начиная с заданной позиции и заданной длины. Синтаксис: `SUBSTRING(строка, начальная_позиция, длина)`, причём **нумерация позиций начинается с 1**, а не с 0, в отличие от многих языков программирования:

```sql
SELECT SUBSTRING('KB-001', 1, 2) AS prefix;
-- вернёт 'KB'
```

Здесь мы извлекли первые два символа строки. Третий аргумент (длина) можно не указывать — тогда `SUBSTRING` вернёт весь остаток строки начиная с указанной позиции до самого конца:

```sql
SELECT SUBSTRING('KB-001', 4) AS numeric_part;
-- вернёт '001'
```

`SUBSTRING` также принимает **отрицательную** начальную позицию — в этом случае отсчёт идёт с конца строки, что удобно для извлечения последних символов без предварительного вычисления длины строки:

```sql
SELECT SUBSTRING('KB-001', -3) AS last_three_chars;
-- вернёт '001' — последние три символа строки
```

Практический пример на данных каталога — извлечь буквенный префикс артикула (всё до дефиса), если известно, что префикс всегда состоит ровно из двух символов:

```sql
SELECT sku, SUBSTRING(sku, 1, 2) AS sku_prefix
FROM products
WHERE sku IS NOT NULL;
```

### TRIM: удаление пробелов по краям строки

Данные, поступающие из внешних источников (веб-формы, импорт из файлов, ручной ввод), часто содержат лишние пробелы в начале или в конце строки, которые визуально незаметны, но могут ломать сравнения на равенство. Функция `TRIM` убирает такие пробелы по краям строки, оставляя пробелы внутри неё без изменений:

```sql
SELECT TRIM('  Мышь беспроводная   ') AS cleaned;
-- вернёт 'Мышь беспроводная' — без пробелов по краям, но с пробелом посередине
```

У `TRIM` есть более гибкие формы с явным указанием, с какой стороны убирать символы (`LEADING` — только слева, `TRAILING` — только справа, `BOTH` — с обеих сторон, это значение по умолчанию), и что именно убирать (по умолчанию — пробелы, но можно указать любой другой символ):

```sql
SELECT TRIM(LEADING '0' FROM '00042') AS trimmed_zeros;
-- вернёт '42' — убраны ведущие нули
```

Практическая польза `TRIM` особенно заметна при поиске: если в таблице случайно оказались строки с пробелами по краям, точное сравнение `name = 'Мышь беспроводная'` не найдёт `'Мышь беспроводная '` (с пробелом в конце), потому что для SQL это два разных значения. `TRIM` в условии сравнения помогает устранить такую нестыковку:

```sql
SELECT name
FROM products
WHERE TRIM(name) = 'Мышь беспроводная';
```

### REPLACE: замена фрагмента строки

Функция `REPLACE(строка, что_искать, на_что_заменить)` заменяет **все** вхождения искомого фрагмента на новый текст:

```sql
SELECT REPLACE('Клавиатура механическая', 'механическая', 'мембранная') AS renamed;
-- вернёт 'Клавиатура мембранная'
```

`REPLACE` заменяет все совпадения по всей строке, а не только первое:

```sql
SELECT REPLACE('2024-03-15', '-', '/') AS formatted_date;
-- вернёт '2024/03/15' — оба дефиса заменены на слэш
```

Если искомый фрагмент не найден в строке, `REPLACE` вернёт исходную строку без изменений — функция не завершается ошибкой при отсутствии совпадения:

```sql
SELECT REPLACE('Мышь', 'клавиатура', 'X') AS result;
-- вернёт 'Мышь' без изменений
```

Практический пример на каталоге товаров — нормализовать написание единиц измерения перед выводом отчёта, заменив дюймовый значок `"` на слово «дюйм»:

```sql
SELECT REPLACE(name, '"', ' дюйм') AS name_normalized
FROM products
WHERE name LIKE '%"%';
```

### Комбинирование строковых функций

Строковые функции, как и любые выражения из третьего урока, свободно вкладываются друг в друга и комбинируются с `CONCAT`. Например, соберём аккуратную «визитку» товара: обрежем пробелы по краям названия, приведём категорию к верхнему регистру и склеим всё в одну строку с указанием длины названия для внутренней отчётности:

```sql
SELECT CONCAT(
    UPPER(category), ': ',
    TRIM(name), ' (', CHAR_LENGTH(TRIM(name)), ' симв.)'
) AS catalog_entry
FROM products;
```

Здесь `TRIM(name)` вычисляется дважды (один раз для самого текста, второй раз — чтобы посчитать его длину именно после удаления пробелов, а не до) — вложенность функций друг в друга, как и вложенность математических выражений, вычисляется от внутренних скобок к внешним, для каждой строки таблицы отдельно.

### Резюме

- `UPPER`/`LOWER` меняют регистр текста; полезны и для отображения, и для регистронезависимого сравнения через `LOWER(a) = LOWER(b)`.
- `LENGTH` возвращает длину строки в **байтах**, `CHAR_LENGTH` — в **символах**; для многобайтовых кодировок (кириллица в `utf8mb4`) эти числа различаются, и для «человеческой» длины нужен именно `CHAR_LENGTH`.
- `SUBSTRING(строка, позиция, [длина])` извлекает часть строки; нумерация позиций начинается с 1; отрицательная позиция отсчитывается с конца строки; без третьего аргумента возвращается остаток строки до конца.
- `TRIM` убирает пробелы (или другой указанный символ) по краям строки; формы `LEADING`/`TRAILING`/`BOTH` уточняют, с какой стороны.
- `REPLACE(строка, что, на_что)` заменяет **все** вхождения искомого фрагмента; при отсутствии совпадений возвращает исходную строку без ошибки.
- Строковые функции свободно комбинируются друг с другом и с `CONCAT`, вычисляясь для каждой строки результата отдельно, от внутренних вложений к внешним.

## Теоретические задания

### Вопрос 1: Что вернут `LENGTH('Мышь')` и `CHAR_LENGTH('Мышь')` в базе с кодировкой utf8mb4?

- ✅ 8 и 4
<!-- кириллица в utf8mb4 — 2 байта на символ: LENGTH считает байты, CHAR_LENGTH — символы -->
- ❌ 4 и 4 — error_text: так было бы для латиницы, где символ занимает один байт; кириллица в utf8mb4 — многобайтовая, и LENGTH честно насчитает 4 символа × 2 байта = 8.
- ❌ 8 и 8 — error_text: CHAR_LENGTH считает символы, как их видит человек, — их 4; 8 — это байтовая длина, которую возвращает LENGTH.
- ❌ 4 и 8 — error_text: функции перепутаны местами: байтовая длина (LENGTH) — 8, символьная (CHAR_LENGTH) — 4; для «человеческой» длины названия нужен именно CHAR_LENGTH.

### Вопрос 2: Что вернёт `SUBSTRING('KB-0042', 4)`?

- ✅ '0042'
<!-- нумерация позиций начинается с 1; без третьего аргумента — остаток строки до конца -->
- ❌ '042' — error_text: нумерация позиций в SQL начинается с 1, а не с 0: K — 1, B — 2, «-» — 3, поэтому четвёртый символ — первый ноль, и ответ длиннее на один символ.
- ❌ 'KB-' — error_text: SUBSTRING возвращает часть строки начиная с заданной позиции, а не до неё; «первые три символа» — это SUBSTRING('KB-0042', 1, 3).
- ❌ ошибку: не указан обязательный третий аргумент «длина» — error_text: длина — необязательный аргумент; без него функция возвращает остаток строки от указанной позиции до конца — ошибки нет.

### Вопрос 3: Что вернёт `TRIM('  Мышь беспроводная  ')`?

- ✅ «Мышь беспроводная» — без пробелов по краям, с сохранением пробела между словами
<!-- TRIM по умолчанию чистит обе стороны строки, не трогая внутренние символы -->
- ❌ «Мышьбеспроводная» — строка без единого пробела — error_text: TRIM убирает пробелы только по краям строки; пробел между словами — часть содержимого, и он остаётся на месте.
- ❌ «Мышь беспроводная» только с очищенным левым краем — error_text: по умолчанию TRIM работает как BOTH — чистит обе стороны; только слева чистила бы форма TRIM(LEADING ' ' FROM …).
- ❌ пустую строку — error_text: строка не состоит из одних пробелов; TRIM не уничтожает содержимое — он снимает краевые пробелы, а «Мышь беспроводная» остаётся.

### Вопрос 4: Что вернёт `REPLACE('2026-09-28', '-', '.')`?

- ✅ '2026.09.28' — заменены оба дефиса
<!-- REPLACE заменяет все вхождения искомого фрагмента -->
- ❌ '2026.09-28' — error_text: REPLACE заменяет все вхождения фрагмента, а не только первое, — в отличие от привычки из некоторых языков программирования; оба дефиса превратятся в точки.
- ❌ '2026 09 28' — error_text: третий аргумент — на что заменять; в этом вызове это точка. Пустая строка на месте замены удаляла бы дефисы, но такой вызов здесь не написан.
- ❌ '2026-09-28' — исходную строку без изменений — error_text: искомый фрагмент «-» в строке есть, поэтому замена произойдёт; REPLACE возвращает исходную строку без изменений только когда совпадений не нашлось.

### Вопрос 5: Зачем в условии `WHERE LOWER(email) = LOWER('Ivan@Mail.RU')` приводят обе части к нижнему регистру?

- ✅ чтобы сравнение прошло независимо от регистра — даже если настройки сравнения (collation) чувствительны к нему
<!-- LOWER(a) = LOWER(b) — гарантированная регистронезависимость сравнения -->
- ❌ чтобы вывести значение email в нижнем регистре — error_text: выражение находится внутри WHERE и влияет только на проверку условия; к колонкам результата оно не попадает — смена регистра вывода делается в списке SELECT, а не в фильтре.
- ❌ чтобы запрос работал быстрее — error_text: функция в условии не инструмент скорости; регистронезависимое сравнение даёт collation с суфф suffix `_ci`, а LOWER — способ получить ту же независимость гарантированно, любой ценой скорости здесь и не пахнет.
- ❌ без LOWER сравнение текстовых значений в SQL невозможно — error_text: обычное сравнение строк работает всегда — вопрос лишь в том, как collation обрабатывает регистр; LOWER страхует от несовпадения «Иван» и «иван», когда регистр в данных разнобой.

### Задание 2: Разбор артикулов

SUBSTRING с началом и длиной, SUBSTRING до конца строки и CHAR_LENGTH.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT sku, SUBSTRING(sku, 1, 2) AS vendor, SUBSTRING(sku, 4) AS item_no, CHAR_LENGTH(sku) AS sku_len FROM products WHERE sku IS NOT NULL ORDER BY sku; -->

**statement:**

Таблица `products` содержит семь товаров; артикул `sku`, где указан,
состоит из двухбуквенного кода поставщика, дефиса и номера: «MS-1042».
Для товаров с заполненным артикулом выведите: сам артикул `sku`, код
поставщика `vendor` (первые два символа), номер `item_no` (всё, начиная
с четвёртой позиции) и длину артикула в символах `sku_len`. Строки
отсортируйте по артикулу.

**expected_result_text:**

Финальный SELECT возвращает шесть строк: веб-камера без артикула отсеяна
условием IS NOT NULL. У короткого артикула MS-99 номер «99», а длина — 5
символов; остальные артикулы семисимвольные.

**seed_sql:**

```sql
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    sku VARCHAR(20) NULL,
    price DECIMAL(10,2) NOT NULL
);

INSERT INTO products (name, sku, price) VALUES
    ('Мышь беспроводная', 'MS-1042', 1340.00),
    ('Клавиатура', 'KB-0120', 1890.00),
    ('Наушники', 'HP-0501', 2490.00),
    ('Монитор 24"', 'MN-2401', 9990.00),
    ('Колонка', 'SP-0009', 3190.00),
    ('Веб-камера', NULL, 2680.00),
    ('Мышь проводная', 'MS-99', 540.00);
```

**expected_rows:**

| sku     | vendor | item_no | sku_len |
| ------- | ------ | ------- | ------- |
| HP-0501 | HP     | 0501    | 7       |
| KB-0120 | KB     | 0120    | 7       |
| MN-2401 | MN     | 2401    | 7       |
| MS-1042 | MS     | 1042    | 7       |
| MS-99   | MS     | 99      | 5       |
| SP-0009 | SP     | 0009    | 7       |

### Задание 3: Дюймы словами

REPLACE всех вхождений символа плюс отбор строк с ним через LIKE.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT name, REPLACE(name, '"', ' дюйм') AS name_ru, price FROM products WHERE name LIKE '%"%' ORDER BY name; -->

**statement:**

В таблице `products` размер экрана отмечен двойной кавычкой в конце
названия: «Монитор 27"». Подготовьте человекочитаемый вариант названия
`name_ru`, заменив каждую двойную кавычку на слово « дюйм» (с пробелом
перед ним). Выведите колонки `name`, `name_ru`, `price` только для
товаров, у которых в названии есть двойная кавычка. Строки отсортируйте
по исходному названию.

**expected_result_text:**

Финальный SELECT возвращает четыре строки: мышь офисная без кавычки в
названии отсеяна шаблону LIKE '%"%'. «Монитор 27"» превращается в
«Монитор 27 дюйм», «Диск SSD 2.5"» — в «Диск SSD 2.5 дюйм»; REPLACE
заменяет все найденные вхождения.

**seed_sql:**

```sql
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10,2) NOT NULL
);

INSERT INTO products (name, price) VALUES
    ('Монитор 27"', 18490.00),
    ('Монитор 24"', 9990.00),
    ('Телевизор 43"', 24990.00),
    ('Диск SSD 2.5"', 4290.00),
    ('Мышь офисная', 640.00);
```

**expected_rows:**

| name           | name_ru           | price    |
| -------------- | ----------------- | -------- |
| Диск SSD 2.5"  | Диск SSD 2.5 дюйм | 4290.00  |
| Монитор 24"    | Монитор 24 дюйм   | 9990.00  |
| Монитор 27"    | Монитор 27 дюйм   | 18490.00 |
| Телевизор 43"  | Телевизор 43 дюйм | 24990.00 |

**runtime:** mysql
