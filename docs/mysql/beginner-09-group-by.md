### Из одного числа — по числу на группу

Урок 8 научил сворачивать таблицу в одну строку: «сколько всего
товаров», «какая средняя цена», «когда последний заказ». Но живые
вопросы отчётов звучат чуть иначе: «сколько товаров **в каждой
категории**», «сколько заказов **пришлось на каждый месяц**», «сколько
покупателей **в каждом городе**». Не одно число на всю таблицу, а по
числу на каждую группу строк — и результатом не строка, а маленькая
таблица: группа за группой.

Урок 8 оставил и открытый долг. Запрос `SELECT name, COUNT(*) FROM
products` кончился ошибкой 1140: свёртка и построчный столбец без
группировки не смешиваются — у шести товаров нет «общего имени».
Инструмент для «счёт по каждому имени» — GROUP BY: сначала разбить
строки на группы, потом свернуть каждую группу отдельно. Урок 6
назвал его «способом образовать группы для агрегатов» — сегодня этот
этаж конвейера включается.

Принцип «считать должен сервер» (урок 3 «Начинающего») остаётся в
силе. Вместо того чтобы выгружать все строки и считать города в
приложении, сервер сам разложит строки по группам и отдаст готовую
таблицу — четыре строки вместо пяти тысяч.

### Первая группировка

Три таблицы урока 8 с нами — покупатели, каталог, заказы. Сколько
покупателей в каждом городе:

```sql
SELECT city, COUNT(*) AS buyers
FROM customers
GROUP BY city;
```

```text
+-------------------------------+--------+
| city                          | buyers |
+-------------------------------+--------+
| Казань                        |      1 |
| Москва                        |      2 |
| Новосибирск                   |      1 |
| Санкт-Петербург               |      1 |
+-------------------------------+--------+
```

Читается запрос так: «для каждого города — сколько покупателей».
Механика: сервер проходит строки и раскладывает их по корзинам — по
одной на каждое уникальное значение `city`. Затем каждая корзина
сворачивается в одну строку результата: значение ключа группы
(`city`) и агрегаты по корзине (`COUNT(*)`). Строк было пять, групп
получилось четыре — Москва собрала двоих.

В списке SELECT рядом с агрегатом стоит `city` — и это законно:
`city` входит в GROUP BY, его значение одинаково для всей группы,
представлять группу ему можно. Строгое правило сформулируем ниже.

Порядок строк. В нашем прогоне группы вышли по алфавиту — но это
устройство конкретного выполнения, а не обещание сервера: правило
урока 9 «Основ» действует и здесь. Нужен порядок — фиксируйте его
явно: `GROUP BY city ORDER BY city` даст ту же таблицу, но уже с
гарантией. В примерах дальше ORDER BY пишем всегда.

Место на конвейере (урок 6): GROUP BY — третий этаж, после WHERE и до
SELECT. Поэтому в группы собираются только строки, прошедшие фильтр,
и поэтому же агрегат в WHERE невозможен — ошибка 1111 из урока 8, а
условие по агрегату живёт этажом выше, в HAVING (урок 10).

### Закрытый список: что может стоять рядом с агрегатом

Правило: **каждая колонка в SELECT — либо внутри агрегатной функции,
либо в GROUP BY.** Нарушение выглядит невинно:

```sql
SELECT name, city, COUNT(*) AS buyers
FROM customers
GROUP BY city;
```

MySQL 8 с настройками по умолчанию (проверка `ONLY_FULL_GROUP_BY`
включена) отвечает отказом:

```text
ERROR 1055 (42000): Expression #1 of SELECT list is not in GROUP BY
clause and contains nonaggregated column 'shop.customers.name' which
is not functionally dependent on GROUP BY columns; this is
incompatible with sql_mode=only_full_group_by
```

За канцеляритом — тот же вопрос урока 8: `city` — ключ группы, ему
есть что представлять; а какое **одно** имя соответствует двум
москвичам? Сервер отказывается выбирать наугад. Ошибка 1055 — родная
сестра ошибки 1140: там смешение было с всей таблицей, здесь — с
группой; суть одна, но теперь сервер видит группы и может проверить
каждую колонку.

Одна тонкость спрятана прямо в тексте ошибки: «functionally
dependent» — функциональная зависимость. MySQL 8 иногда сам видит,
что колонка однозначно определяется ключами группы: сгруппируйте по
первичному ключу `id` (урок 6 «Основ») — любой столбец таблицы внутри
группы уже определён, и `SELECT name ... GROUP BY id` пройдёт без
ошибки. Это исключение стоит знать в лицо, но не применять: рабочее
правило проще и безопаснее — всё, что выводим построчно, явно
включаем в GROUP BY.

Мягкие настройки — как в нашей лаборатории — не отказывают, а молча
берут произвольную строку группы:

```text
+-----------------------------+-------------------------------+--------+
| name                        | city                          | buyers |
+-----------------------------+-------------------------------+--------+
| Иван Сидоров                | Казань                        |      1 |
| Анна Петрова                | Москва                        |      2 |
| Ольга Смирнова              | Новосибирск                   |      1 |
| Дмитрий Козлов              | Санкт-Петербург               |      1 |
+-----------------------------+-------------------------------+--------+
```

Счёт верный. Имя для Москвы — Анна Петрова: произвольная строка
группы — могла быть и Мария. Результат выглядит осмысленным и является
бессмысленным — вывод урока 8 дословно.

Что разрешено помимо ключей и агрегатов: **выражения над ключами
группы**. `UPPER(city)` в SELECT при `GROUP BY city` — законно: внутри
одной группы города значение выражения одинаково. Что запрещено:
построчные колонки мимо GROUP BY — у них внутри группы много разных
значений, «одно от группы» не выбрать.

### WHERE — до группировки

Знакомый отчёт «средняя цена по категориям» и его уточнение «только
среди товаров в наличии»:

```sql
SELECT category_id, ROUND(AVG(price), 2) AS avg_price
FROM products
GROUP BY category_id
ORDER BY category_id;
```

```text
+-------------+-----------+
| category_id | avg_price |
+-------------+-----------+
|           1 |    570.00 |
|           2 |   2910.17 |
|           3 |  15990.00 |
+-------------+-----------+
```

```sql
SELECT category_id, ROUND(AVG(price), 2) AS avg_price
FROM products
WHERE stock > 0
GROUP BY category_id
ORDER BY category_id;
```

```text
+-------------+-----------+
| category_id | avg_price |
+-------------+-----------+
|           1 |    570.00 |
|           2 |   1870.25 |
|           3 |  15990.00 |
+-------------+-----------+
```

Разница — во второй категории: 2910.17 против 1870.25. Клавиатура за
4990.00 с нулевым остатком вышла из игры **до** группировки: WHERE —
второй этаж, GROUP BY — третий, группы собираются уже из выживших
строк. Любой фильтр, который вы умеете писать, — сравнения урока 8
«Основ», LIKE, IN, BETWEEN уроков 1–2 «Начинающего» — работает до
группировки.

В обратную сторону — условие **по агрегату** («категории, где товаров
больше трёх») — в WHERE невозможно: ошибка 1111, урок 8. Для условий
по группам и агрегатам существует HAVING — урок 10.

### Группировка по нескольким ключам

GROUP BY принимает список ключей через запятую. Группа — уникальная
комбинация значений **всех** ключей. Разложим заказы по месяцам и
статусу оплаты сразу:

```sql
SELECT DATE_FORMAT(created_at, '%Y-%m') AS month_key,
       CASE WHEN paid_at IS NULL THEN 'нет' ELSE 'да' END AS is_paid,
       COUNT(*) AS orders
FROM orders
GROUP BY DATE_FORMAT(created_at, '%Y-%m'),
         CASE WHEN paid_at IS NULL THEN 'нет' ELSE 'да' END
ORDER BY month_key, is_paid;
```

```text
+-----------+---------+--------+
| month_key | is_paid | orders |
+-----------+---------+--------+
| 2026-06   | да      |      2 |
| 2026-07   | да      |      1 |
| 2026-07   | нет     |      1 |
| 2026-08   | да      |      1 |
+-----------+---------+--------+
```

Пять строк — четыре группы: июль расщепился на «оплаченный» и
«неоплаченный». Заметьте: второй ключ — не столбец, а CASE урока 7;
ключом группы может быть любое выражение, значение которого одинаково
для строк, которым положено быть вместе.

Каждый добавленный ключ мельчит группы: город → город и месяц → город,
месяц и категория. Набор столбцов GROUP BY называют **зерном отчёта**
— тем, что представляет одна строка результата. Здесь зерно — «месяц
× статус оплаты». Прежде чем писать отчёт, решите, каково зерно;
остальное — какие агрегаты считать, какие строки отсеять в WHERE —
приложится.

Одна тонкость синтаксиса. В примере GROUP BY повторяет выражения
целиком — так написан стандарт SQL. MySQL разрешает сократить —
псевдонимы из SELECT в GROUP BY работают: `GROUP BY month_key,
is_paid`. Это расширение MySQL (в WHERE алиасы по-прежнему невозможны
— очередь этажей урока 6 не переписывается); в других СУБД так не
написать, поэтому привычка «повторить выражение» переносимее, а
алиас — законная экономия в MySQL-коде.

### Отчёты по месяцам: ключом может быть выражение

Долг урока 5 закрыт: месячный ключ `DATE_FORMAT(created_at, '%Y-%m')`
был заготовкой отчёта — теперь строки с одинаковым ключом становятся
группой, и «сколько заказов пришлось на каждый месяц» считается одним
запросом:

```sql
SELECT DATE_FORMAT(created_at, '%Y-%m') AS month_key,
       COUNT(*) AS orders,
       SUM(total) AS revenue
FROM orders
GROUP BY month_key
ORDER BY month_key;
```

```text
+-----------+--------+----------+
| month_key | orders | revenue  |
+-----------+--------+----------+
| 2026-06   |      2 |  6280.50 |
| 2026-07   |      2 | 16440.00 |
| 2026-08   |      1 |   3200.00 |
+-----------+--------+----------+
```

`ORDER BY month_key` сортирует «по-людски» — не потому что GROUP BY
добрый, а потому что ключ так спроектирован: сначала год, потом месяц
(урок 5), и `2026-06 < 2026-07 < 2026-08` по правилам сравнения
строк. Ряды по периодам — самый частый вид аналитических отчётов.

Честная оговорка: месяцев **без** заказов в отчёте не будет — группы
возникают только из существующих строк. Если август без заказов
обязан показывать ноль, а не исчезать, — это задача календарной
таблицы, средний уровень; пока держите ограничение в голове.

### NULL в группировке

В сравнениях NULL «проваливает» любое условие (урок 11 «Основ») — но
группировка не сравнение. Сгруппируем покупателей по необязательному
телефону:

```sql
SELECT phone, COUNT(*) AS buyers
FROM customers
GROUP BY phone;
```

```text
+---------------+--------+
| phone         | buyers |
+---------------+--------+
| NULL          |      3 |
|               |      1 |
| 912-345-67-89 |      1 |
+---------------+--------+
```

Три группы. Все три NULL собрались в **одну общую** группу — строки
без телефона принадлежат вместе. Не потому, что NULL = NULL стало
истинно (урок 11 «Основ» такого сравнения не разрешает), а потому,
что группировка раскладывает строки по корзинам — и корзина
«телефона нет» одна на всех. Пустая строка Дмитрия — отдельная группа: '' — значение, а не
NULL (урок 11). И заметьте: `COUNT(*)` внутри NULL-группы равен трём,
хотя `COUNT(phone)` в ней же был бы нулём — строки есть, значений нет
(урок 8).

Вывести «не указано» вместо NULL можно выражением над ключом — это
законно, ведь `phone` входит в GROUP BY:

```sql
SELECT COALESCE(phone, 'не указан') AS phone, COUNT(*) AS buyers
FROM customers
GROUP BY phone;
```

```text
+-------------------+--------+
| phone             | buyers |
+-------------------+--------+
| не указан         |      3 |
|                   |      1 |
| 912-345-67-89     |      1 |
+-------------------+--------+
```

Группировка осталась по `phone`, изменилось только отображение —
COALESCE урока 11 на службе отчётов.

### Условные агрегаты: COUNT(CASE ...)

«Сколько заказов в каждом месяце» — есть. Следующий вопрос: «в каждом
месяце — сколько из них оплачено». Раскладывать по статусу оплаты,
как в разделе про несколько ключей, не хочется: строки множатся, а
хочется два счётчика в одной строке. Паттерн «условный агрегат»:

```sql
SELECT DATE_FORMAT(created_at, '%Y-%m') AS month_key,
       COUNT(*) AS orders,
       COUNT(CASE WHEN paid_at IS NULL THEN 1 END) AS unpaid
FROM orders
GROUP BY month_key
ORDER BY month_key;
```

```text
+-----------+--------+--------+
| month_key | orders | unpaid |
+-----------+--------+--------+
| 2026-06   |      2 |      0 |
| 2026-07   |      2 |      1 |
| 2026-08   |      1 |      0 |
+-----------+--------+--------+
```

Механика — два урока, защёлкнутые вместе. CASE вычисляется построчно
(урок 7): неоплаченным он даёт 1, остальным — NULL, потому что ELSE
не написано, а NULL — значение CASE по умолчанию. COUNT(выражение)
пропускает NULL (урок 8) — и считает только те строки, куда CASE
послал единицу. Отсутствие ELSE здесь не оплошность, а половина
паттерна.

Ловушка — дорисовать ELSE 0 «для порядка»:

```sql
SELECT COUNT(CASE WHEN paid_at IS NULL THEN 1 END) AS bez_else,
       COUNT(CASE WHEN paid_at IS NULL THEN 1 ELSE 0 END) AS s_else
FROM orders;
```

```text
+----------+--------+
| bez_else | s_else |
+----------+--------+
|        1 |      5 |
+----------+--------+
```

1 против 5: ноль — **значение**, и COUNT его честно считает; не
пропускается только NULL. Если хочется явного ELSE, считайте через
SUM: `SUM(CASE WHEN paid_at IS NULL THEN 1 ELSE 0 END)` — нули
суммируются безвредно, выйдет та же единица.

Условным бывает и SUM — с ELSE 0, который здесь как раз уместен.
«Валовая и оплаченная выручка по месяцам» одним запросом:

```sql
SELECT DATE_FORMAT(created_at, '%Y-%m') AS month_key,
       SUM(total) AS revenue,
       SUM(CASE WHEN paid_at IS NOT NULL THEN total ELSE 0 END) AS paid_revenue
FROM orders
GROUP BY month_key
ORDER BY month_key;
```

```text
+-----------+----------+--------------+
| month_key | revenue  | paid_revenue |
+-----------+----------+--------------+
| 2026-06   |  6280.50 |      6280.50 |
| 2026-07   | 16440.00 |     15990.00 |
| 2026-08   |   3200.00 |      3200.00 |
+-----------+----------+--------------+
```

В июле неоплаченные 450.00 остались в валовой выручке, но выпали из
оплаченной. Условные агрегаты — рабочий конёк отчётов: одна группа —
несколько счётчиков по разным условиям, без разрастания строк.

### Агрегаты в ORDER BY

ORDER BY — шестой этаж, после SELECT (урок 6): алиасы и агрегаты в
нём доступны. «Какая категория держит самую дорогую витрину»:

```sql
SELECT category_id, SUM(price * stock) AS stock_value
FROM products
GROUP BY category_id
ORDER BY stock_value DESC;
```

```text
+-------------+-------------+
| category_id | stock_value |
+-------------+-------------+
|           3 |    47970.00 |
|           1 |    46410.00 |
|           2 |    44886.00 |
+-------------+-------------+
```

Гонка плотная: мониторы (47970.00) впереди аксессуаров (46410.00) и
периферии (44886.00). Добавьте `LIMIT 1` — и ответ на вопрос «какая
категория первая» одной строкой (урок 9 «Основ»: сортировка плюс
ограничение — топ-N). Сортировка по агрегату упорядочивает группы —
строк в результате всё равно сколько групп.

### GROUP BY без агрегатов

GROUP BY работает и без единого агрегата — тогда он просто схлопывает
повторы, как DISTINCT урока 3:

```sql
SELECT city FROM customers GROUP BY city;
```

```text
+-------------------------------+
| city                          |
+-------------------------------+
| Казань                        |
| Москва                        |
| Новосибирск                   |
| Санкт-Петербург               |
+-------------------------------+
```

«Сколько уникальных городов» — `COUNT(DISTINCT city)` из урока 8;
«перечислить уникальные города» — DISTINCT или GROUP BY без
агрегатов. Эффект один, инструмент выбирают по смыслу: убрать повторы
из вывода — DISTINCT, считать по группам — GROUP BY.

### Чего в этом уроке нет

- HAVING — фильтрация готовых групп («месяцы, где заказов больше
  трёх») — урок 10;
- группировка вместе с JOIN — например, название категории рядом с
  `category_id` из таблицы-справочника — уроки 13–15;
- «месяцы без заказов» — календарная добивка нулями через рекурсивные
  CTE — средний уровень.

### Резюме

- GROUP BY раскладывает строки на группы по значению ключей и сворачивает
  каждую в одну строку: ключ + агрегаты. Вся таблица — одна строка
  (урок 8); группы — по строке на группу (этот урок).
- Рабочее правило закрытого списка: каждая колонка SELECT — внутри
  агрегата или в GROUP BY (исключение MySQL — функциональная
  зависимость от ключей, как при GROUP BY по первичному ключу). Иначе
  MySQL 8 — ошибка 1055; мягкие настройки молча подставят
  произвольную строку группы.
- WHERE — до группировки; агрегат в WHERE — ошибка 1111; фильтр по
  группам и агрегатам — HAVING, урок 10.
- GROUP BY a, b — группа это уникальная комбинация значений всех
  ключей; набор ключей — зерно отчёта.
- Ключом может быть выражение: месячный ключ DATE_FORMAT(..., '%Y-%m')
  (долг урока 5 закрыт). Алиас в GROUP BY — расширение MySQL; в WHERE
  алиасы невозможны.
- Все NULL одного ключа — одна общая группа; '' — отдельное значение.
  Выражение над ключом (COALESCE) — «не указано» на выводе.
- COUNT(CASE WHEN условие THEN 1 END) — счётчик строк по условию: без
  ELSE, чтобы остальные давали NULL. ELSE 0 в COUNT — ловушка (ноль —
  значение); безопасная альтернатива — SUM(... THEN 1 ELSE 0 END).
- ORDER BY понимает агрегаты и алиасы: топ-группы — ORDER BY ...
  DESC LIMIT N.

## Теоретические задания

### Вопрос 1: Что ответит MySQL 8 с настройками по умолчанию на запрос `SELECT name, city, COUNT(*) FROM customers GROUP BY city;`?

- ✅ ошибку 1055: name не входит в GROUP BY и не свёрнут агрегатом
<!-- правило закрытого списка: колонка в SELECT — либо в агрегате, либо среди ключей группы -->
- ❌ четыре строки — по одной на город, в name произвольное имя покупателя этого города — error_text: так отвечает сервер с выключенной проверкой ONLY_FULL_GROUP_BY: имя молча берётся из произвольной строки группы — та же бессмыслица, что у ошибки 1140 в уроке 8; MySQL 8 по умолчанию отказывает — ошибка 1055.
- ❌ строки «город + имя» с количеством покупателей такой пары — error_text: зерно «город + имя» потребовало бы GROUP BY city, name — тогда каждая пара стала бы отдельной группой; здесь группа — город, и одного имени на двух москвичей сервер взять не может.
- ❌ то же, что и без name: город и счёт, лишняя колонка тихо выкидывается — error_text: SELECT — список колонок результата: заявленная колонка либо осмыслена (в GROUP BY или внутри агрегата), либо запрос не выполняется; выбрасывать колонки за спиной пользователя сервер не умеет.

### Вопрос 2: В orders 5 строк, у одной paid_at = NULL. Что вернёт `SELECT COUNT(CASE WHEN paid_at IS NULL THEN 1 ELSE 0 END) FROM orders;`?

- ✅ 5
<!-- ELSE 0 возвращает ноль — значение, и COUNT считает все строки; NULL пропускается, ноль — нет -->
- ❌ 1 — error_text: единица была бы без ELSE: неоплаченные дают 1, остальные — NULL, который COUNT пропускает; ELSE 0 возвращает ноль — обычное значение, и COUNT честно считает все пять строк.
- ❌ 0 — error_text: ноль — значение, а не NULL: COUNT его не пропускает. Пропускается только NULL — поэтому паттерн COUNT(CASE ...) и обходится без ELSE.
- ❌ ошибку — error_text: CASE — обычное выражение (урок 7), агрегат поверх выражения — законная композиция (урок 8). Ошибки нет — есть ловушка подсчёта.

### Вопрос 3: Отчёт: по каждой категории — количество товаров дороже 1000. Куда писать условие `price > 1000`?

- ✅ в WHERE — отобрать строки до группировки
<!-- WHERE — второй этаж, GROUP BY — третий: группы собираются из выживших строк -->
- ❌ в HAVING — error_text: HAVING фильтрует готовые группы — по ключам и агрегатам (урок 10); условие по строке должно сработать до свёртки: WHERE — второй этаж конвейера, GROUP BY — третий.
- ❌ внутрь CASE в списке SELECT — error_text: CASE в SELECT решает, что писать в значениях уже отобранных строк, а не какие строки проходят (урок 7: разделение труда); отбирать строки — работа WHERE.
- ❌ в GROUP BY рядом с category_id — error_text: GROUP BY не отбрасывает строки, а задаёт зерно отчёта: с ключом price > 1000 категории дробились бы на «дорогие» и «дешёвые» — и дешёвые группы остались бы в результате.

### Вопрос 4: Запрос: `SELECT ... FROM orders GROUP BY customer, DATE_FORMAT(created_at, '%Y-%m')`. Что представляет одна строка результата?

- ✅ все заказы одного покупателя в одном месяце
<!-- группа = уникальная комбинация значений всех ключей GROUP BY -->
- ❌ все заказы одного покупателя — error_text: покупатель один — при GROUP BY customer; второй ключ раскладывает каждого покупателя по месяцам: июльские и августовские заказы одного человека — разные строки.
- ❌ все заказы одного месяца — error_text: месяц один — при группировке только по месячному ключу; customer в списке GROUP BY добавляет разрез по покупателям, и строка — комбинация обоих ключей.
- ❌ один заказ — error_text: строка результата — всегда группа; она может состоять из одной строки, но ключ здесь «покупатель + месяц»: несколько заказов одного покупателя за месяц схлопнутся в одну строку с общими агрегатами.

### Вопрос 5: В phone значения NULL, NULL, NULL, '' и '912-345-67-89'. Сколько строк вернёт `SELECT phone, COUNT(*) FROM customers GROUP BY phone;`?

- ✅ 3
<!-- все NULL — одна общая группа; '' — отдельное значение; номер — третья -->
- ❌ 5 — error_text: в сравнениях NULL не равен даже NULL (урок 11 «Основ»), но группировка — не сравнение: сервер собирает строки по одинаковым значениям, и все NULL образуют одну общую группу.
- ❌ 2 — error_text: это слияет NULL и пустую строку в одну «пустоту»; '' — значение и живёт в собственной группе, отдельно от NULL-группы (урок 11).
- ❌ ошибку — error_text: NULL в ключе группы — штатная ситуация: строки с NULL группируются так же, как любые другие, ошибки нет.
