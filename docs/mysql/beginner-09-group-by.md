## Материал

В прошлом уроке агрегатные функции считали статистику по **всей** таблице (или по всей таблице после `WHERE`) — одно число на весь набор строк. Но куда чаще на практике нужна статистика **по подмножествам**: не «средняя цена всех товаров», а «средняя цена **в каждой категории**»; не «сколько всего заказов», а «сколько заказов **у каждого клиента**». Именно эту задачу решает `GROUP BY` — он разбивает строки на группы по значению одного или нескольких столбцов, и агрегатные функции из прошлого урока начинают считаться **отдельно для каждой такой группы**, а не для всей таблицы целиком.

### GROUP BY по одному столбцу

Разберём базовый пример: посчитать количество товаров в каждой категории:

```sql
SELECT category, COUNT(*) AS products_count
FROM products
GROUP BY category;
```

Происходит следующее: СУБД сначала находит все уникальные значения столбца `category` во всей таблице `products` — это и станут будущие группы (например, «Периферия», «Мониторы», «Ноутбуки»). Затем каждая строка исходной таблицы «раскладывается» в свою группу по значению `category`. И, наконец, для каждой группы отдельно вычисляется `COUNT(*)` — то есть считается количество строк именно в этой группе, а не во всей таблице. Результат — одна строка **на каждую уникальную категорию**, а не на каждый товар: если в таблице сто товаров, но всего пять категорий, результат будет из пяти строк.

Это принципиально отличается от `DISTINCT category` из третьего урока: `DISTINCT` тоже даёт одну строку на уникальное значение, но не позволяет посчитать вместе с этим статистику по каждой группе — `GROUP BY` делает то же самое «схлопывание» до уникальных значений, но при этом даёт доступ к агрегатам внутри каждой группы.

### Ключевое правило: что можно писать в SELECT при GROUP BY

Как только в запросе появляется `GROUP BY`, действует важное структурное правило: в списке `SELECT` разрешены только **два вида** выражений — столбцы, **по которым идёт группировка** (они одинаковы для всех строк внутри одной группы, поэтому однозначны), и **агрегатные функции** (они по определению сворачивают всю группу в одно число). Столбец, который **не входит** ни в `GROUP BY`, ни в агрегатную функцию, использовать в `SELECT` нельзя — потому что внутри одной группы такой столбец может принимать **разные** значения у разных строк, и SQL не может решить, какое из них показать в единственной итоговой строке группы:

```sql
-- ОШИБКА: name не входит ни в GROUP BY, ни в агрегатную функцию
SELECT category, name, COUNT(*)
FROM products
GROUP BY category;
```

Этот запрос завершится ошибкой (в строгом режиме MySQL, который используется по умолчанию в актуальных версиях), потому что внутри группы «Периферия» может быть несколько товаров с разными `name`, и непонятно, чьё именно название показывать в единственной строке результата для этой группы. Правильные варианты — либо убрать `name` из `SELECT`, либо агрегировать его (например, через `MIN(name)` — «первое по алфавиту название в группе», если такая метрика имеет смысл для задачи), либо добавить `name` в сам `GROUP BY`, если по нему тоже нужна отдельная группировка.

### GROUP BY по нескольким столбцам

`GROUP BY` принимает список из нескольких столбцов через запятую — в этом случае группа определяется **уникальным сочетанием** значений всех указанных столбцов, а не каждым по отдельности (тот же принцип, что мы уже видели у `DISTINCT` с несколькими столбцами в третьем уроке). Посчитаем количество товаров и суммарный остаток на складе для каждой пары «категория + наличие на складе» (используем `CASE` из прошлого урока, чтобы свести `stock` к двум состояниям):

```sql
SELECT category,
    CASE WHEN stock > 0 THEN 'в наличии' ELSE 'нет' END AS availability,
    COUNT(*) AS products_count
FROM products
GROUP BY category, CASE WHEN stock > 0 THEN 'в наличии' ELSE 'нет' END;
```

Обратите внимание, что мы группируем по тому же выражению `CASE WHEN ...`, которое присутствует и в `SELECT` — важно писать выражение целиком в обеих частях запроса (в отличие от псевдонима из `SELECT`, псевдоним группировки в `GROUP BY` в MySQL допустим, но для сложных выражений явное повторение делает запрос понятнее и однозначнее для чтения). Более практичный пример группировки по нескольким столбцам без вычислений — статистика по категории и году регистрации клиента:

```sql
SELECT city, YEAR(registered_at) AS reg_year, COUNT(*) AS customers_count
FROM customers
GROUP BY city, reg_year;
```

Каждая уникальная пара «город + год регистрации» становится отдельной группой (в MySQL псевдоним `reg_year`, заданный в `SELECT`, можно повторно использовать в `GROUP BY` — это особенность конкретно этой СУБД, а не универсальное правило SQL).

### Условные агрегаты: COUNT(CASE WHEN ...)

Иногда нужна не просто общая статистика по группе, а статистика **по подмножеству строк внутри группы**, отобранному по условию — например, «сколько товаров в каждой категории стоят дороже 5000, и сколько — дешевле». Прямого способа написать «условный `COUNT`» не существует, но эта задача элегантно решается комбинацией `COUNT` с уже знакомым нам `CASE`:

```sql
SELECT category,
    COUNT(*) AS total_products,
    COUNT(CASE WHEN price >= 5000 THEN 1 END) AS expensive_count,
    COUNT(CASE WHEN price < 5000 THEN 1 END) AS cheap_count
FROM products
GROUP BY category;
```

Механика этого приёма опирается на два факта, которые мы уже разбирали по отдельности: `CASE` без `ELSE` возвращает `NULL` для строк, не подошедших ни под одно условие (седьмой урок), а `COUNT(столбец)` игнорирует строки с `NULL` (прошлый урок). Соединив эти два факта, мы получаем «условный счётчик»: `CASE WHEN price >= 5000 THEN 1 END` возвращает `1` для дорогих товаров и `NULL` для всех остальных, а внешний `COUNT` считает только те строки, где получился не-`NULL` результат — то есть только дорогие товары внутри текущей группы.

Тот же приём работает и с `SUM` — например, посчитать суммарный остаток отдельно для товаров в наличии и отдельно (гипотетически, для проверки данных) — сколько было бы недостающих единиц, если бы `stock` мог быть отрицательным:

```sql
SELECT category,
    SUM(CASE WHEN stock > 0 THEN stock ELSE 0 END) AS in_stock_total
FROM products
GROUP BY category;
```

Такой паттерн — «`COUNT`/`SUM` внутри `CASE`» — один из самых часто встречающихся приёмов в реальной SQL-аналитике, потому что он позволяет получить сразу несколько «срезов» статистики по одной и той же группе в одном запросе, без необходимости писать несколько отдельных запросов с разными `WHERE`.

### GROUP BY и ORDER BY

`GROUP BY` полностью совместим с `ORDER BY` — и, что логично из порядка выполнения шестого урока (`GROUP BY` — шаг 3, `ORDER BY` — шаг 6, значительно позже), в `ORDER BY` уже можно использовать и агрегатные результаты, и псевдонимы из `SELECT`:

```sql
SELECT category, COUNT(*) AS products_count
FROM products
GROUP BY category
ORDER BY products_count DESC;
```

Этот запрос покажет категории, отсортированные от самой «многочисленной» к самой малочисленной — типичный паттерн для отчёта «топ категорий по количеству товаров».

### GROUP BY и WHERE: фильтрация ещё до группировки

Как мы уже знаем из шестого урока, `WHERE` выполняется раньше `GROUP BY`, поэтому им можно отфильтровать строки, которые вообще не должны попасть ни в одну группу, — например, посчитать среднюю цену по категориям, но только среди товаров, которые есть на складе:

```sql
SELECT category, ROUND(AVG(price), 2) AS avg_price_in_stock
FROM products
WHERE stock > 0
GROUP BY category;
```

Товары с `stock = 0` будут полностью исключены `WHERE` ещё до того, как СУБД начнёт формировать группы, — они не повлияют ни на одну из итоговых групп, даже косвенно.

### Резюме

- `GROUP BY столбец` разбивает строки на группы по уникальным значениям столбца; агрегатные функции внутри такого запроса считаются отдельно **для каждой группы**, а не для всей таблицы.
- В `SELECT` запроса с `GROUP BY` допустимы только столбцы группировки и агрегатные функции — обычный столбец «сам по себе» использовать нельзя, потому что внутри группы он может иметь разные значения.
- `GROUP BY` по нескольким столбцам через запятую группирует по уникальному **сочетанию** их значений, аналогично `DISTINCT` с несколькими столбцами.
- `COUNT(CASE WHEN условие THEN 1 END)` (и аналогично `SUM(CASE WHEN ... THEN значение ELSE 0 END)`) — стандартный приём «условного агрегата», считающего статистику только по подмножеству строк внутри группы, основанный на том, что `CASE` без `ELSE` даёт `NULL`, а агрегаты `NULL` игнорируют.
- `WHERE` выполняется раньше `GROUP BY` и убирает строки из рассмотрения ещё до формирования групп; `ORDER BY` выполняется позже и может использовать псевдонимы агрегатов из `SELECT`.

## Теоретические задания

### Вопрос 1: Что ответит MySQL 8 с настройками по умолчанию на `SELECT category, name, COUNT(*) FROM products GROUP BY category;`?

- ✅ ошибку: name не входит в GROUP BY и не свёрнут агрегатной функцией
<!-- правило закрытого списка: в SELECT — только столбцы группировки и агрегаты -->
- ❌ таблицу «категория + имя + счёт», где имя взято из произвольной строки группы — error_text: так отвечают серверы с ослабленным режимом: имя молча берётся из случайной строки группы, и результат выглядит осмысленным, оставаясь бессмысленным. Строгий режим, включённый в MySQL 8 по умолчанию, отказывает выполнять такой запрос.
- ❌ по строке на каждую пару «категория + имя» — error_text: такое зерно дал бы `GROUP BY category, name`: каждая пара стала бы отдельной группой. Здесь группа — категория целиком, и одного имени на все её товары сервер выбрать не может.
- ❌ ошибку из-за COUNT(*) рядом с обычным столбцом — error_text: агрегат в SELECT — законная часть запроса с GROUP BY; проблема не в COUNT(*), а в столбце name, который не входит в GROUP BY и не обёрнут агрегатом.

### Вопрос 2: В таблице 6 товаров: 4 в категории «Периферия» и 2 в «Мониторы». Сколько строк вернёт `SELECT category, COUNT(*) FROM products GROUP BY category;`?

- ✅ 2 — по строке на каждую уникальную категорию
<!-- строка результата — группа, а не исходная строка таблицы -->
- ❌ 6 — error_text: 6 строк вернул бы SELECT без GROUP BY — по строке на каждый товар. GROUP BY схлопывает строки каждой категории в одну строку результата: категорий две — строк две.
- ❌ 1 — error_text: одна строка была бы вовсе без GROUP BY: тогда COUNT(*) посчитал бы все 6 товаров одним числом. GROUP BY как раз и нужен, чтобы получить счёт на каждую категорию отдельно.
- ❌ 2, но COUNT(*) в каждой строке покажет 6 — error_text: COUNT(*) вычисляется внутри своей группы: у «Периферии» он равен 4, у «Мониторов» — 2. Общее число 6 появилось бы только в запросе без группировки.

### Вопрос 3: Нужен отчёт «средняя цена по категориям, только среди товаров в наличии». Куда писать условие stock > 0?

- ✅ в WHERE — отфильтровать строки до группировки
<!-- WHERE выполняется раньше GROUP BY; группы собираются из выживших строк -->
- ❌ в HAVING — error_text: HAVING фильтрует готовые группы и стоит в конвейере урока 6 после GROUP BY. Условие же проверяется по одной строке (товару), поэтому должно сработать до группировки — в WHERE. Подробно HAVING — следующий урок.
- ❌ в CASE внутри SELECT — error_text: CASE в SELECT решает, что выводить в значениях уже отобранных строк, а не какие строки участвуют в группировке (урок 7 «Начинающего»: CASE — выражение отображения). Отбирать строки — работа WHERE.
- ❌ в GROUP BY рядом с category — error_text: GROUP BY не отбрасывает строки, а задаёт зерно отчёта. Ключ `stock > 0` дробил бы категории на группы «в наличии» и «нет» — и обе остались бы в результате.

### Вопрос 4: Почему `COUNT(CASE WHEN price >= 5000 THEN 1 END)` в запросе с GROUP BY считает только дорогие товары каждой группы?

- ✅ CASE без ELSE возвращает NULL для неподходящих строк, а COUNT(выражение) пропускает NULL
<!-- два факта — NULL у CASE без ELSE и пропуск NULL у COUNT(столбца) — защёлкнуты вместе -->
- ❌ COUNT умеет читать условие внутри CASE и учитывает только истинное — error_text: COUNT не «понимает» условия: он просто получает по одному значению на строку и считает не-NULL из них. Вся условность — в CASE, который отдаёт 1 или NULL.
- ❌ неподходящие строки получают 0, который COUNT не считает — error_text: наоборот: без ELSE неподходящие строки получают NULL, а не 0. Ноль — обычное значение, и COUNT его посчитал бы — поэтому ELSE 0 внутри COUNT ловушка: считались бы все строки группы.
- ❌ CASE вычисляется после COUNT и подставляет готовые числа — error_text: порядок обратный: CASE вычисляется построчно для каждой строки (урок 7 «Начинающего»), и только потом агрегат сворачивает полученные значения (урок 8 «Начинающего»).

### Вопрос 5: Запрос группирует покупателей `GROUP BY city, YEAR(registered_at)`. Что представляет одна строка результата?

- ✅ всех покупателей одного города, зарегистрировавшихся в одном году
<!-- группа — уникальное сочетание значений всех ключей GROUP BY -->
- ❌ всех покупателей одного города — error_text: одним городом ограничился бы запрос с `GROUP BY city`. Второй ключ расщепляет каждый город по годам: москвичи 2025 и 2026 годов регистрации — разные строки результата.
- ❌ всех покупателей, зарегистрировавшихся в одном году — error_text: только год был бы ключом в запросе без city в GROUP BY. Здесь строка — сочетание обоих ключей: год считается внутри каждого города отдельно.
- ❌ ошибку — выражение в GROUP BY недопустимо — error_text: ключом группы может быть и выражение: `YEAR(registered_at)` — пример прямо из материала урока. Запрос корректен.
