# Мини-проект: каталог товаров

## Материал

### Одиннадцать кирпичей — один дом

Уровень шёл по кирпичикам: `SELECT` и таблицы, сервер и базы, синтаксис,
`INSERT`, типы данных, `CREATE TABLE` с ограничениями, `ALTER` и удаление,
`WHERE`, сортировка и страницы, `UPDATE`/`DELETE`, NULL. В этом уроке — ни
одной новой команды. Вместо неё — проект: собрать всё перечисленное в
работающий каталог магазина, от пустой базы до витрины и эксплуатации.
Так проверяется настоящее понимание: не «помню команды по отдельности»,
а «могу довести задачу до конца».

План проекта повторяет жизненный цикл любой маленькой системы: спроектировать
и создать схему → наполнить данными → научиться показывать → начать
эксплуатировать. Четыре шага, одиннадцать уроков за спиной.

### Шаг 1. Схема: две таблицы

Каталог — это категории и товары. У категории только имя; у товара —
категория, имя, цена и остаток на складе. Переводим на SQL, каждое решение
— из пройденного:

```sql
CREATE TABLE IF NOT EXISTS categories (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    category_id INT NOT NULL,
    name VARCHAR(100) NOT NULL UNIQUE,
    price DECIMAL(8,2) NOT NULL CHECK (price >= 0),
    stock INT NOT NULL DEFAULT 0
);
```

Разберём решения, как в настоящем код-ревью. `id` в обеих таблицах —
первичный ключ с автонумерацией: «имя строки» из урока 6. `category_id` —
просто число, номер категории товара: связывает таблицы по договорённости
«в этом столбце живёт `id` категории»; серверной проверки связи — внешних
ключей — в курсе ещё нет, следующий уровень обещал. Имена — `VARCHAR` с
запасом (урок 5) и `UNIQUE`: повторять «Периферия» или два одинаковых
товара каталогу незачем — бизнес-уникальность урока 6. Цена — `DECIMAL`:
деньги любят точность. `CHECK (price >= 0)` — бесплатный товар возможен,
отрицательный — нет: бизнес-правило переехало в схему, и теперь его
проверяет сервер при любой записи, из любого приложения. `stock` —
обязательный, по умолчанию ноль: новый товар до прихода на склад честно
считается отсутствующим. `IF NOT EXISTS` — страховка повторных запусков
скрипта (урок 6).

Почему вообще две таблицы, а не одна с колонкой «категория»? Потому что
имя категории — отдельная сущность: в одной таблице «Периферия»
повторялась бы в каждой строке — с опечатками и вариациями написания, — а
переименование категории превратилось бы в правку десятков строк. В двух
таблицах имя живёт один раз, а товар хранит лишь её номер. У принципа
есть имя — нормализация, — его выучите в среднем уровне; здесь достаточно
здравого смысла: повторяющееся — выносим, ссылку — храним.

Проверяем результат инструментом урока 5:

```text
+-------------+--------------+------+-----+---------+----------------+
| Field       | Type         | Null | Key | Default | Extra          |
+-------------+--------------+------+-----+---------+----------------+
| id          | int          | NO   | PRI | NULL    | auto_increment |
| category_id | int          | NO   |     | NULL    |                |
| name        | varchar(100) | NO   | UNI | NULL    |                |
| price       | decimal(8,2) | NO   |     | NULL    |                |
| stock       | int          | NO   |     | 0       |                |
+-------------+--------------+------+-----+---------+----------------+
```

Все решения видны в шести строках: `PRI`, `UNI`, умолчание, автонумерация —
колонки DESCRIBE, которые «ожили» в уроке 6, здесь читаются как готовый
проект.

### Шаг 2. Наполнение

Категории — одной многострочной инструкцией урока 4, имена без id — их
раздаст счётчик:

```sql
INSERT INTO categories (name) VALUES
    ('Аксессуары'),
    ('Периферия'),
    ('Мониторы');
```

Товары — пятью строками с явными остатками, а шестую, веб-камеру, положим
без `stock` — пусть сработает умолчание:

```sql
INSERT INTO products (category_id, name, price, stock) VALUES
    (1, 'Коврик для мыши', 690.00, 34),
    (2, 'Мышь беспроводная', 1290.50, 12),
    (2, 'Клавиатура механическая', 4990.00, 8),
    (3, 'Монитор 27"', 15990.00, 3),
    (1, 'Кабель HDMI 2 м', 450.00, 51);

INSERT INTO products (category_id, name, price) VALUES
    (2, 'Веб-камера', 2450.00);
```

Контроль — уроков 4 и 9:

```sql
SELECT id, category_id, name, price, stock FROM products ORDER BY id;
```

```text
+----+-------------+-----------------------------+----------+-------+
| id | category_id | name                        | price    | stock |
+----+-------------+-----------------------------+----------+-------+
|  1 |           1 | Коврик для мыши            |   690.00 |    34 |
|  2 |           2 | Мышь беспроводная          |  1290.50 |    12 |
|  3 |           2 | Клавиатура механическая    |  4990.00 |     8 |
|  4 |           3 | Монитор 27"                 | 15990.00 |     3 |
|  5 |           1 | Кабель HDMI 2 м            |   450.00 |    51 |
|  6 |           2 | Веб-камера                  |  2450.00 |     0 |
+----+-------------+-----------------------------+----------+-------+
```

Шесть товаров, id проставлены сервером, у веб-камеры `stock = 0` из
умолчания — схема работает.

И одна дисциплина договорённостей: `category_id` сервер не проверяет —
пока это просто число. Вставить товар с `category_id = 7`, когда категорий
три, можно — но каталог соврёт: товар повиснет «ни в какой» категории.
Пока внешних ключей нет, корректность ссылок — на вашей совести: номер
категории берётся из `categories`, а не из головы.

### Шаг 3. Витрина: пройденное в одну строку

Каталог живёт запросами — и все они собраны из уроков 8–9. Вся периферия
по алфавиту:

```sql
SELECT name, price
FROM products
WHERE category_id = 2
ORDER BY name;
```

```text
+-----------------------------+---------+
| name                        | price   |
+-----------------------------+---------+
| Веб-камера                  | 2450.00 |
| Клавиатура механическая     | 4990.00 |
| Мышь беспроводная           | 1290.50 |
+-----------------------------+---------+
```

Хиты витрины — три самых дорогих **из доступных**: сначала фильтр по
остатку, потом сортировка вниз, потом лимит (порядок `WHERE` → `ORDER BY` →
`LIMIT` — урок 9):

```sql
SELECT name, price
FROM products
WHERE stock > 0
ORDER BY price DESC
LIMIT 3;
```

```text
+-----------------------------+----------+
| name                        | price    |
+-----------------------------+----------+
| Монитор 27"                 | 15990.00 |
| Клавиатура механическая     |  4990.00 |
| Мышь беспроводная           |  1290.50 |
+-----------------------------+----------+
```

Веб-камера за 2450 в тройку не попала — и правильно: остаток ноль, фильтр
отсеял её до лимита. Именно поэтому порядок частей не произволен: сначала
убираем ненужное, потом упорядочиваем, потом режем.

Страница каталога — вторая двойка по возрастанию цены (урок 9):

```sql
SELECT name, price
FROM products
ORDER BY price
LIMIT 2 OFFSET 2;
```

```text
+-----------------------------+---------+
| name                        | price   |
+-----------------------------+---------+
| Мышь беспроводная           | 1290.50 |
| Веб-камера                  | 2450.00 |
+-----------------------------+---------+
```

И служебные запросы: кладовщика — «что распродано?» — делает
`WHERE stock = 0` (вернёт веб-камеру); а точная карточка товара — это
`WHERE name = 'Монитор 27"'`: уникальность имени из схемы гарантирует не
более одного ответа (уроки 6 и 8). Заметьте: ни один запрос не длиннее
четырёх строк, и в каждом — только пройденное.

### Шаг 4. Эксплуатация: данные живут

Распродажа периферии. Дисциплина урока 10: сперва смотрим на жертв —
`SELECT name, price FROM products WHERE category_id = 2;` (мышь, клавиатура,
веб-камера), затем правим:

```sql
UPDATE products
SET price = 999.00
WHERE category_id = 2;
```

`Query OK, 3 rows affected` — три строки, как и показывал контрольный
SELECT. Снимаем с продажи то, чего нет:

```sql
DELETE FROM products WHERE stock = 0;
```

`Query OK, 1 row affected` — веб-камера ушла. Итог эксплуатации:

```sql
SELECT id, category_id, name, price, stock FROM products ORDER BY id;
```

```text
+----+-------------+-----------------------------+----------+-------+
| id | category_id | name                        | price    | stock |
+----+-------------+-----------------------------+----------+-------+
|  1 |           1 | Коврик для мыши            |   690.00 |    34 |
|  2 |           2 | Мышь беспроводная          |   999.00 |    12 |
|  3 |           2 | Клавиатура механическая    |   999.00 |     8 |
|  4 |           3 | Монитор 27"                 | 15990.00 |     3 |
|  5 |           1 | Кабель HDMI 2 м            |   450.00 |    51 |
+----+-------------+-----------------------------+----------+-------+
```

Периферия по 999, распроданное удалено, нумерация продолжилась как ни в
чём не бывало — счётчик помнит использованные номера (уроки 6–7): если
веб-камеру вернут в ассортимент, она встанет новой строкой с id 7, номера
не переиспользуются. Проект живой: схема приняла данные, данные выдержали
запросы, изменения прошли по правилам.

### Что вы теперь умеете

Одиннадцать уроков одним списком — фундамент уровня «Основы»:

| Урок | Умеете |
| ---- | ------ |
| 1 | понимать таблицы, строки, столбцы; первый `SELECT` |
| 2 | работать с сервером, базами, `USE` |
| 3 | писать и форматировать SQL, читать ошибки, `LIMIT` |
| 4 | добавлять данные `INSERT`-ом |
| 5 | выбирать типы и читать `DESCRIBE`; строгий режим |
| 6 | создавать таблицы с ограничениями |
| 7 | менять и удалять таблицы; `DELETE`/`TRUNCATE`/`DROP` |
| 8 | фильтровать строки `WHERE`-ом |
| 9 | сортировать и листать страницы |
| 10 | безопасно изменять и удалять строки |
| 11 | обращаться с NULL: `IS NULL`, `COALESCE`, `NULLIF` |

Список работает и как обратное оглавление: что-то забудется — уроки
называются по темам и ждут перечитывания. Перед следующим уровнем
пробегитесь по нему ещё раз: каждый пункт должен отозваться «умею» без
заглядывания.

Этого достаточно, чтобы вести настоящий маленький каталог в одиночку.
Дальше — следующие уровни: условия поинтереснее, связи между таблицами
на уровне сервера, агрегаты и JOIN. Но все они строятся на том, что уже
пройдено: таблица, тип, ограничение, условие, порядок.

### Резюме

- Путь проекта: схема (`CREATE` с ограничениями) → наполнение (`INSERT` с
  умолчаниями и автонумерацией) → витрина (`WHERE` + `ORDER BY` + `LIMIT`/
  `OFFSET`) → эксплуатация (`UPDATE`/`DELETE` с контрольным `SELECT`).
- Решения схемы — из уроков 5–6: `DECIMAL` для денег, `UNIQUE` для
  бизнес-имён, `CHECK` для бизнес-правил, `DEFAULT` для честного нуля,
  `category_id` — связь по договорённости до внешних ключей.
- Порядок частей запроса не произволен: `WHERE` → `ORDER BY` → `LIMIT` —
  фильтр раньше сортировки раньше обрезки.
- Изменения — только с техникой безопасности урока 10: посмотрел жертв,
  изменил, сверил отчёт.
- Уровень «Основы» закрыт: дальше — новые уровни над этим фундаментом.

## Теоретические задания

### Вопрос 1: Зачем в таблице `products` стоит `CHECK (price >= 0)`, если проверять цену может и приложение?

- ✅ правило живёт в схеме и защищает данные при записи из любого источника
- ❌ так INSERT выполняется быстрее — error_text: CHECK не про скорость: это правило таблицы из урока 6 — сервер проверяет его сам, из какого бы приложения ни пришла запись; приложение может ошибиться или отсутствовать.
- ❌ без CHECK таблица не создастся — error_text: CHECK необязателен: таблица прекрасно создаётся и без него; выбор — перенести бизнес-правило «цена не отрицательна» в схему, чтобы его гарантировал сервер.

### Вопрос 2: Нужно вывести три самых дорогих товара из имеющихся в наличии. Какой запрос верен?

- ✅ `SELECT name, price FROM products WHERE stock > 0 ORDER BY price DESC LIMIT 3;`
- ❌ `SELECT name, price FROM products WHERE stock > 0 ORDER BY price LIMIT 3;` — error_text: без DESC сортировка по возрастанию — вернутся три самых дешёвых из доступных; направление обязательно указывать явно (урок 9).
- ❌ `SELECT name, price FROM products ORDER BY price DESC LIMIT 3;` — error_text: нет фильтра по остатку: в топ попадут и распроданные товары с нулевым stock — фильтр WHERE обязан отсеять их до лимита.

### Вопрос 3: Каталог отсортирован по возрастанию цены, страницы по 2 товара. Какой запрос вернёт страницу №2?

- ✅ `SELECT name, price FROM products ORDER BY price LIMIT 2 OFFSET 2;`
- ❌ `SELECT name, price FROM products ORDER BY price LIMIT 2 OFFSET 1;` — error_text: первая страница заняла 2 строки — вторая начинается после смещения 2; смещение равно числу пропускаемых строк, а не номеру страницы.
- ❌ `SELECT name, price FROM products ORDER BY price DESC LIMIT 2 OFFSET 2;` — error_text: DESC развернёт сортировку: страница «по возрастанию» и страница «по убыванию» — разные наборы строк; направление — часть условия задачи.

### Вопрос 4: Перед `UPDATE products SET price = 999.00 WHERE category_id = 2;` что сделать обязательно?

- ✅ выполнить `SELECT` с тем же `WHERE` и посмотреть, какие строки затронет
- ❌ ничего: UPDATE безопасен — error_text: безопасен только прицел по id из урока 10; массовое изменение по неуникальному условию перед выполнением проверяют контрольным SELECT — условие то же, строки те же.
- ❌ удалить таблицу и создать заново — error_text: это уничтожит и данные, и схему; UPDATE меняет значения на месте, сохранив строки и их id — «грубый способ» разбирался в уроке 10.

### Вопрос 5: Нужно очистить `products` полностью и начать нумерацию id с 1 заново. Какая команда верна?

- ✅ `TRUNCATE TABLE products;`
- ❌ `DELETE FROM products;` — error_text: строки уйдут, но счётчик AUTO_INCREMENT продолжит нумерацию — следующая строка получит id 7, не 1 (уроки 7 и 10).
- ❌ `DROP TABLE products;` — error_text: DROP удалит и схему — таблицу придётся создавать заново; задача была очистить данные, сохранив таблицу — это TRUNCATE.

### Задание 2: Витрина

Топ-3 из доступных: фильтр, сортировка, лимит.

<!-- Эталонное решение (для автора/бота-верификатора): SELECT name, price FROM products WHERE stock > 0 ORDER BY price DESC LIMIT 3; -->

**statement:**

Каталог из задания 1 уже создан и заполнен (скрипт ниже). Выведите три
самых дорогих товара **из имеющихся в наличии** — name и price. Товары
с нулевым остатком на витрину не попадают.

**expected_result_text:**

Финальный SELECT возвращает монитор, клавиатуру и мышь — от самой дорогой
к третьей. Веб-камера (2450.00, остаток 0) отфильтрована до лимита:
сначала WHERE, потом ORDER BY, потом LIMIT.

**seed_sql:**

```sql
CREATE TABLE categories (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    category_id INT NOT NULL,
    name VARCHAR(100) NOT NULL UNIQUE,
    price DECIMAL(8,2) NOT NULL CHECK (price >= 0),
    stock INT NOT NULL DEFAULT 0
);

INSERT INTO categories (name) VALUES
    ('Аксессуары'),
```
