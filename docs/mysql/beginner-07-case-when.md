### Если внутри запроса

Условия в SQL до сих пор жили в одном месте — в WHERE, и решали один
вопрос: «какие строки проходят». А жизнь спрашивает другое: «как **метить**
значения по условиям». Витрине нужны ценовые сегменты — «бюджетный,
средний, премиум». Выгрузке — человеческие слова вместо номеров
категорий. Сортировке — «сначала товары в наличии, закончившиеся — в
конце». Функции уроков 4–5 преобразуют значения, но не умеют «думать»:
UPPER не спросит, дорогой ли товар. Для «если… то» в SQL есть выражение
CASE — переключатель, который проверяет условия и возвращает первое
подошедшее значение. Сегодня: две его формы, ELSE, коварный NULL,
условная сортировка — и место CASE на конвейере урока 6.

### Поисковый CASE: условия как в WHERE

Задача: пометить каждый товар ценовым сегментом — до тысячи «бюджетный»,
до пяти «средний», дальше «премиум». **Поисковый CASE** — это цепочка
«если — то», закрытая словом END:

```sql
SELECT name, price,
       CASE
           WHEN price < 1000 THEN 'бюджетный'
           WHEN price <= 5000 THEN 'средний'
           ELSE 'премиум'
       END AS segment
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+----------+--------------------+
| name                                          | price    | segment            |
+-----------------------------------------------+----------+--------------------+
| Коврик для мыши                               |   690.00 | бюджетный          |
| Мышь беспроводная                             |  1290.50 | средний            |
| Клавиатура механическая                       |  4990.00 | средний            |
| Монитор 27"                                   | 15990.00 | премиум            |
| Кабель HDMI 2 м                               |   450.00 | бюджетный          |
| Веб-камера                                    |  2450.00 | средний            |
+-----------------------------------------------+----------+--------------------+
```

Читается сверху вниз как обычное «если»: «если цена меньше тысячи —
верни „бюджетный", иначе если не больше пяти тысяч — „средний", иначе —
„премиум"». Если вы писали на языках программирования: поисковый CASE —
это if / else if / else, а простой, который ниже, — switch по значению;
SQL обходится одним словом для обеих форм. Условия в WHEN — те же, что
пишут в WHERE: сравнения,
BETWEEN, IN, LIKE, IS NULL, AND/OR (уроки 8 «Основ» и 1–2 «Начинающего»).
THEN возвращает значение любого типа — строку, число, дату. И заметьте
`AS segment`: CASE — выражение, и псевдоним ему положен как любому
вычисляемому столбцу урока 3. И следите за парой слов: у каждого CASE —
свой END; забытый END — синтаксическая ошибка 1064, самая частая шишка
новичка.

Условия в WHEN — не только «больше-меньше»: в распоряжении весь
инструментарий урока 2. Тот же сегмент, записанный через BETWEEN:

```sql
SELECT name, price,
       CASE WHEN price BETWEEN 1000 AND 5000 THEN 'средний'
            WHEN price < 1000 THEN 'бюджетный'
            ELSE 'премиум'
       END AS segment
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+--------------------+
| name                                          | segment            |
+-----------------------------------------------+--------------------+
| Коврик для мыши                               | бюджетный          |
| Мышь беспроводная                             | средний            |
| Клавиатура механическая                       | средний            |
| Монитор 27"                                   | премиум            |
| Кабель HDMI 2 м                               | бюджетный          |
| Веб-камера                                    | средний            |
+-----------------------------------------------+--------------------+
```

Результат тот же: BETWEEN включает обе границы (урок 2), так что «от
1000 до 5000» покрывает и хаб за ровно тысячу. Выбор стиля — вкус
задачи: пара сравнений читается «от и до», BETWEEN — «диапазон». Ветви
здесь не перекрываются, поэтому порядок не важен — но в разделе о
порядке WHEN увидим, когда он становится решающим.

### Простой CASE: сравнение на равенство

Когда условие одно и то же — «равно ли столбец вот этому значению», —
есть короткая форма. **Простой CASE** берёт выражение один раз и сравнивает
его со значениями WHEN:

```sql
SELECT name, city,
       CASE city
           WHEN 'Москва' THEN 'столица'
           ELSE 'другой город'
       END AS marka
FROM customers
ORDER BY id;
```

```text
+-----------------------------+-----------------+-------------------------+
| name                        | city            | marka                   |
+-----------------------------+-----------------+-------------------------+
| Анна Петрова                | Москва          | столица                 |
| Иван Сидоров                | Казань          | другой город            |
| Мария Волкова               | Москва          | столица                 |
| Дмитрий Козлов              | Санкт-Петербург | другой город            |
| Ольга Смирнова              | Новосибирск     | другой город            |
+-----------------------------+-----------------+-------------------------+
```

`CASE city WHEN 'Москва'` — это «если city равен 'Москва'»; каждая ветка
WHEN — ещё одно значение для сравнения. Значение, не условие: условие в
простой форме писать некуда — для условий есть поисковая. Поисковый CASE умеет всё то же и
больше (любые условия), простой — короче для перечислений: «номер
категории → название». Честная оговорка: настоящие названия категорий
живут в таблице, и «по-взрослому» их подставляют соединением таблиц —
JOIN, урок 13; CASE хорош, когда справочника нет, а метка нужна на лету.

### Первый совпавший WHEN выигрывает

Ветви проверяются **сверху вниз, до первого совпадения** — остальное не
смотрится. Кажется мелочью, пока условия не перекрываются. Два порядка
одних и тех же ветвей:

```sql
SELECT name, price,
       CASE WHEN price > 2000 THEN 'дороже 2000'
            WHEN price > 500  THEN 'дороже 500'
            ELSE 'до 500' END AS sverhu_vniz,
       CASE WHEN price > 500  THEN 'дороже 500'
            WHEN price > 2000 THEN 'дороже 2000'
            ELSE 'до 500' END AS snizu_vverh
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+----------+-------------------+------------------+
| name                                          | price    | sverhu_vniz       | snizu_vverh      |
+-----------------------------------------------+----------+-------------------+------------------+
| Коврик для мыши                               |   690.00 | дороже 500        | дороже 500       |
| Мышь беспроводная                             |  1290.50 | дороже 500        | дороже 500       |
| Клавиатура механическая                       |  4990.00 | дороже 2000       | дороже 500       |
| Монитор 27"                                   | 15990.00 | дороже 2000       | дороже 500       |
| Кабель HDMI 2 м                               |   450.00 | до 500            | до 500           |
| Веб-камера                                    |  2450.00 | дороже 2000       | дороже 500       |
+-----------------------------------------------+----------+-------------------+------------------+
```

Клавиатура за 4990 в первой колонке — «дороже 2000»: первое условие
истинно, второй WHEN даже не проверялся. Во второй колонке широкое
условие `> 500` встало первым — и «поглотило» все дорогие товары: ветвь
`> 2000` стала недостижимой. Правило: **частные случаи — выше, общие —
ниже**; и следите, чтобы нижние ветви вообще были достижимы.

### ELSE и NULL: молчание по умолчанию

ELSE — значение «для всех остальных». Без него CASE не отказывается
работать — он молчит NULL:

```sql
SELECT name,
       CASE city WHEN 'Москва' THEN 'столица' END AS marka
FROM customers
ORDER BY id;
```

```text
+-----------------------------+----------------+
| name                        | marka          |
+-----------------------------+----------------+
| Анна Петрова                | столица        |
| Иван Сидоров                | NULL           |
| Мария Волкова               | столица        |
| Дмитрий Козлов              | NULL           |
| Ольга Смирнова              | NULL           |
+-----------------------------+----------------+
```

Не совпало ни одно WHEN и нет ELSE — NULL: «значение не определено»,
знакомое правило урока 11. Хотите явное «прочее» — пишите ELSE.

И главная NULL-ловушка CASE — в **простой** форме. Соблазн написать
«CASE phone WHEN NULL THEN…» оборачивается пустотой:

```sql
SELECT name,
       CASE phone WHEN NULL THEN 'нет' ELSE 'есть' END AS cherez_ravenstvo,
       CASE WHEN phone IS NULL THEN 'нет' ELSE 'есть' END AS cherez_is_null
FROM customers
ORDER BY id;
```

```text
+-----------------------------+------------------+----------------+
| name                        | cherez_ravenstvo | cherez_is_null |
+-----------------------------+------------------+----------------+
| Анна Петрова                | есть             | нет            |
| Иван Сидоров                | есть             | есть           |
| Мария Волкова               | есть             | нет            |
| Дмитрий Козлов              | есть             | есть           |
| Ольга Смирнова              | есть             | нет            |
+-----------------------------+------------------+----------------+
```

Первая колонка соврала всем: простой CASE сравнивает на равенство, а
`phone = NULL` — «неизвестно» даже там, где телефона нет (урок 11:
сравнение с NULL не даёт «да»). У Анны, Марии и Ольги — «есть», хотя
телефона нет. Правильный инструмент — поисковая форма с `WHEN phone IS
NULL` — вторая колонка. Отсутствие ловится только IS NULL, в любой
одежде CASE.

Кстати, старый знакомый COALESCE — родственник CASE: `COALESCE(a, b)` —
«первое не-NULL» — это по сути `CASE WHEN a IS NOT NULL THEN a WHEN b IS
NOT NULL THEN b END`. Урок 11 дал короткую запись для одной частой
задачи; CASE — общая форма для любых «если».

### CASE в ORDER BY: условная сортировка

Задача: «в наличии — первыми, закончившиеся — в конце; внутри групп — по
убыванию цены». В конвейере урока 6 ORDER BY — шестой этаж, и он
принимает любое выражение, включая CASE. Приём — CASE возвращает «номер
группы сортировки»:

```sql
SELECT name, price, stock
FROM products
ORDER BY CASE WHEN stock > 0 THEN 0 ELSE 1 END, price DESC;
```

```text
+-----------------------------------------------+----------+-------+
| name                                          | price    | stock |
+-----------------------------------------------+----------+-------+
| Монитор 27"                                   | 15990.00 |     3 |
| Веб-камера                                    |  2450.00 |    12 |
| Мышь беспроводная                             |  1290.50 |    12 |
| Коврик для мыши                               |   690.00 |    34 |
| Кабель HDMI 2 м                               |   450.00 |    51 |
| Клавиатура механическая                       |  4990.00 |     0 |
+-----------------------------------------------+----------+-------+
```

Как это работает: для каждой строки CASE вычислил 0 (есть на складе)
или 1 (закончился); ORDER BY отсортировал по этому номерку, а при
равенстве — по цене вниз. Отсюда приём «сколько угодно групп в любом
порядке»: номерки 0, 1, 2… — и вторая колонка сортировки внутри группы.
Простая сортировка `ORDER BY stock` так не умеет: она разложит по
количеству, а закончившийся ноль встанет первым.

Приём масштабируется без предела: «сначала Москва, потом остальные» —
`ORDER BY CASE WHEN city = 'Москва' THEN 0 ELSE 1 END, name`;
«дорогие и закончившиеся — в топ списка проблем» — номерок по паре
условий с AND из урока 1. Любой порядок групп, который не выражается
простой сортировкой столбца, выражается номерком от CASE.

### CASE — выражение: место на конвейере

По конвейеру урока 6 CASE — обычное выражение пятого этажа: вычисляется
построчно, получает псевдоним через AS, сортируется в ORDER BY. Условия
в WHEN умеют и даты урока 5: пометить «долгие» заказы — `CASE WHEN
DATEDIFF(paid_at, created_at) > 2 THEN 'долгий' ELSE 'быстрый' END` —
условие из DATEDIFF, результат — метка. Как любое
выражение, CASE вкладывается в другие — например, в CONCAT урока 3:

```sql
SELECT CONCAT(name, ' [', CASE WHEN price > 2000 THEN 'дорого' ELSE 'доступно' END, ']') AS label
FROM products
ORDER BY id
LIMIT 3;
```

```text
+--------------------------------------------------------------+
| label                                                        |
+--------------------------------------------------------------+
| Коврик для мыши [доступно]                                   |
| Мышь беспроводная [доступно]                                 |
| Клавиатура механическая [дорого]                             |
+--------------------------------------------------------------+
```

Вкладывается CASE и в сам себя — как функции урока 4. «Периферия со
своим подсегментом по цене»:

```sql
SELECT name,
       CASE WHEN category_id = 2 THEN
            CASE WHEN price > 3000 THEN 'периферия дорогая'
                 ELSE 'периферия доступная' END
            ELSE 'вне периферии'
       END AS marka
FROM products
ORDER BY id;
```

```text
+-----------------------------------------------+---------------------------------------+
| name                                          | marka                                 |
+-----------------------------------------------+---------------------------------------+
| Коврик для мыши                               | вне периферии                         |
| Мышь беспроводная                             | периферия доступная                   |
| Клавиатура механическая                       | периферия дорогая                     |
| Монитор 27"                                   | вне периферии                         |
| Кабель HDMI 2 м                               | вне периферии                         |
| Веб-камера                                    | периферия доступная                   |
+-----------------------------------------------+---------------------------------------+
```

Внутренний CASE целиком служит значением THEN для внешнего; читается
так же — изнутри наружу. Глубже двух уровней лучше не зарываться, по
той же причине, что и в композиции функций: читаемость дороже
вычурности.

А вот в WHERE CASE обычно не нужен: WHERE сам состоит из условий, и
«если» внутри фильтра — тавтология. Разделение труда: WHERE решает,
какие строки проходят; CASE решает, что писать в значениях.

### Чего в этом уроке нет

- агрегатные функции — урок 8 (а условные агрегаты вида COUNT(CASE …) —
  урок 9);
- подстановка названий из таблиц-справочников через JOIN — урок 13;
- CASE внутри UPDATE для условного изменения строк — оставляем за
  скобками: приём рабочий, но меняет данные, и его время ещё придёт.

### Резюме

- CASE — выражение-переключатель: цепочка «если — то», живёт где угодно
  среди выражений — SELECT, ORDER BY, внутри функций.
- Поисковая форма: `CASE WHEN условие THEN значение … ELSE … END` — любые
  условия, как в WHERE. Простая: `CASE столбец WHEN значение THEN …` —
  сравнение на равенство, короче для перечислений.
- Ветви проверяются сверху вниз до первого совпадения: частные случаи —
  выше, общие — ниже, иначе нижние станут недостижимыми.
- Без ELSE и без совпадений — NULL; отсутствие ловится только `WHEN … IS
  NULL`: `WHEN NULL` в простой форме не срабатывает никогда.
- CASE в ORDER BY — условная сортировка: CASE выдаёт «номер группы»
  (0, 1, 2…), дальше — обычные ключи сортировки внутри групп.
- WHERE для условий строк, CASE для условий в значениях — не путать
  инструменты.
- COALESCE — родственник: «первое не-NULL» — частный случай поискового
  CASE (урок 11 дал короткую запись).
- У каждого CASE — свой END; забытый END — ошибка 1064. Вложения CASE —
  как вложенные функции: изнутри наружу, без гонки за глубиной.

## Теоретические задания

### Вопрос 1: `CASE WHEN price > 5000 THEN 'A' WHEN price > 1000 THEN 'B' ELSE 'C' END` — что вернёт выражение для товара с price = 4990?

- ✅ B
<!-- первое совпавшее: 4990 не больше 5000 — первая ветвь мимо; 4990 > 1000 — вторая сработала -->
- ❌ A — error_text: 4990 не больше 5000 — первая ветвь не сработала; CASE проверяет условия по-настоящему, а не выбирает «ближайшую» ветвь по величине.
- ❌ C — error_text: ELSE — запасной выход, когда ни одно WHEN не совпало; здесь второе условие 4990 > 1000 истинно.
- ❌ и B, и A — обе ветви истинны — error_text: проверка идёт до первого совпадения: даже если бы несколько условий были истинны, сработала бы только самая верхняя.

### Вопрос 2: Что вернёт CASE без ELSE, если ни одно условие WHEN не совпало?

- ✅ NULL
<!-- нет совпадения и нет запасного значения — «не определено», правило урока 11 -->
- ❌ пустую строку — error_text: пустая строка — значение; CASE без ELSE молчит именно NULL — отсутствием ответа.
- ❌ ошибку — error_text: ошибки нет: конструкция законна, «нет совпавших ветвей» — штатная ситуация с результатом NULL.
- ❌ значение из последнего THEN — error_text: последний THEN не становится «по умолчанию»; запасной выход — только ELSE.

### Вопрос 3: `CASE phone WHEN NULL THEN 'нет' ELSE 'есть' END` — что вернёт строка, у которой phone = NULL?

- ✅ есть
<!-- простой CASE сравнивает на равенство, а phone = NULL — «неизвестно»: ветвь не срабатывает -->
- ❌ нет — error_text: чтобы ветвь сработала, сравнение должно дать «да»; NULL = NULL — «неизвестно» (урок 11), сравнение с NULL не срабатывает никогда — нужен WHEN phone IS NULL.
- ❌ NULL — error_text: NULL вернулся бы без ELSE; здесь ELSE есть и честно отдаёт «есть» — вся ирония ловушки в этом.
- ❌ ошибку — error_text: синтаксис корректен: NULL в WHEN допустим; конструкция просто никогда не срабатывает — молча.

### Вопрос 4: Что делает простой CASE — `CASE столбец WHEN значение THEN …`?

- ✅ сравнивает столбец на равенство с каждым значением WHEN
<!-- короткая форма для перечислений: номер категории → название -->
- ❌ проверяет произвольные условия в WHEN — error_text: произвольные условия — поисковая форма CASE WHEN …; в простой форме после WHEN стоит значение, а не условие.
- ❌ сравнивает только числа — error_text: значения WHEN могут быть любого сравнимого типа — строки, числа, даты; ограничений на числа нет.
- ❌ заменяет WHERE — error_text: CASE метит значения, WHERE фильтрует строки — разные инструменты; простой CASE лишь сравнивает столбец со списком значений.

### Вопрос 5: Как вывести товары так, чтобы закончившиеся (stock = 0) стояли в конце, а внутри групп была своя сортировка?

- ✅ ORDER BY CASE WHEN stock > 0 THEN 0 ELSE 1 END, …
<!-- CASE выдаёт номер группы сортировки; вторым ключом — сортировка внутри группы -->
- ❌ ORDER BY stock — error_text: числовая сортировка по остатку поставит закончившиеся (stock = 0) первыми, а не последними; порядок групп нужен произвольный — через номерок от CASE.
- ❌ WHERE stock > 0 — error_text: WHERE выбросит закончившиеся товары из результата совсем, а задача — показать их в конце; фильтр ≠ порядок.
- ❌ CASE нельзя использовать в ORDER BY — error_text: можно: ORDER BY принимает любое выражение, и CASE внутри ORDER BY — стандартный приём условной сортировки.
