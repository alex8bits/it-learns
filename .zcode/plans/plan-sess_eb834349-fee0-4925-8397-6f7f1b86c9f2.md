# План починки двух критичных пунктов

## Контекст (из аудита)

1. **500 на `/seizures/email-doctor`**: контроллер читает query-параметры `from`/`to` без валидации (`app/Http/Controllers/SeizureController.php:222-225`); мусорное значение приводит к необработанному `CarbonImmutable::parse()` (`app/Services/SeizureQuery.php:68,76`) → 500 вместо 422. Прочие period-эндпоинты (`download`, `print`, `emailSelf`) уже валидированы через `IndexJournalRequest` — чиним только `emailDoctor`.
2. **Нет throttle на email-роутах**: `seizures/email-self` и `seizures/email-doctor` (`routes/web.php:28-32`) позволяют авторизованному пользователю слать неограниченный поток писем.

**Ключевой подводный камень**: в `EmailDoctorRequest` body-поле `to` — это email получателя, а query-параметр `to` — дата. В объединённом validation-мешке POST-запроса ключи коллидируют (body перекрывает query), поэтому «просто добавить date-правила для `to` в `rules()`» сломает валидацию получателя. Решение — валидировать query-мешок **отдельно**, в именованном error-bag.

---

## Часть A: валидация `from`/`to` на emailDoctor

### A1. Новый concern `app/Concerns/JournalValidationRules.php` (~35 строк)
По образцу существующих `SeizureValidationRules`/`ProfileValidationRules` — извлекаем переиспользуемые правила периода:

```php
public function periodRules(): array
{
    return [
        'from' => ['nullable', 'date_format:Y-m-d'],
        'to' => ['nullable', 'date_format:Y-m-d', 'after_or_equal:from'],
    ];
}
```

### A2. `app/Http/Requests/Seizures/IndexJournalRequest.php`
`rules()` возвращает `$this->periodRules()` вместо инлайн-правил. Поведение не меняется (правила идентичны текущим).

### A3. `app/Http/Requests/Seizures/EmailDoctorRequest.php`
- `use JournalValidationRules;`
- Новый метод-акцессор (в стиле `toInput()`/`bodyInput()` этого же класса):

```php
/**
 * Validate `from` / `to` period bounds from the query bag. Validated
 * separately from the body rules: query `to` is a date bound and must
 * not collide with the body `to` (recipient email) in the merged bag.
 *
 * @return array{from: ?string, to: ?string}
 */
public function validatedPeriod(): array
{
    $validated = Validator::make($this->query->all(), $this->periodRules())
        ->validateWithBag('period');

    return [
        'from' => $this->normalized($validated, 'from'),
        'to' => $this->normalized($validated, 'to'),
    ];
}
```
(`normalized()` — приватный хелпер: отсутствующее/пустое → null; именованный bag `period` не смешивает ошибки дат с ошибками полей диалога.)

- Переписать устаревший докблок класса (сейчас неверно утверждает, что контроллер мержит `from`/`to` в input bag).

### A4. `app/Http/Controllers/SeizureController.php` — `emailDoctor()`
- Удалить блок ручного чтения `$request->query('from'/'to')` (строки 222-231), заменить на:

```php
$period = $request->validatedPeriod();

$report = new SeizurePeriodReport(
    owner: $user,
    from: $period['from'],
    to: $period['to'],
    query: $this->query,
);
```

- Исправить докблок метода: убрать неверное утверждение «a malformed pair would only widen the report range» — оно опровергнуто throw-цепочкой через `SeizureQuery::forPeriod`.

### Поведение после фикса
`POST /seizures/email-doctor?from=garbage` (валидное тело) → `ValidationException` в bag `period` → редирект назад / 422 для Inertia-XHR вместо 500. SPA на легитимных данных поведение не меняет (URL строится из уже валидированных фильтров, ошибки bag `period` через UI недостижимы).

## Часть B: throttle на email-роутах

### B1. `routes/web.php` (строки 28-32)
Добавить `->middleware('throttle:5,1')` обоим роутам — по прецеденту `routes/api.php:22-26` (эндпоинты `password/forgot` / `password/reset`, тоже рассылающие почту, используют ровно `throttle:5,1`).

Ключ лимита для авторизованного пользователя = `user id | ip`, оба роута делят один бюджет 5 писем/мин — это осознанно: ограничиваем суммарный исходящий mail per user. Зафиксировать кратким комментарием в routes.

Фронтенд не трогаем: Wayfinder-типы от middleware не зависят.
